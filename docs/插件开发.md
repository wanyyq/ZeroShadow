# 插件开发

> 对应版本：**v2.0.0-beta**。插件体系目前处于 **P1 阶段**：`theme`（主题）插件已完整可用；
> `fileType`（文件类型：预览）插件已可用（沙箱 iframe + postMessage）；`server`（服务端）插件**可以安装、启停**，
> 但运行时在后续版本接入，安装后界面会明确提示"暂不生效"。
> 接口以本文为准；`apiVersion` 变更会写进 [CHANGELOG](../CHANGELOG.md)。

---

## 1. 它是什么

插件是**一个 zip 包**，里面必须有一个 `manifest.json` 描述它自己：

```
my-theme.zip
├── manifest.json        # 必需，唯一的入口
└── （主题插件）不需要其它文件；后续 kind 可以带 html/js/css/字体
```

管理员在「设置 → 插件」里上传 zip → 服务端校验 → 装进 `data/plugins/<id>/` →
**默认禁用**（要手动勾选启用）→ 主题插件还要再点「应用主题」才会生效。

> 插件的总开关 `pluginsEnabled` **默认关闭**，关着的时候安装接口直接 403。
> 这是刻意的：插件是第三方内容，必须由管理员显式打开这扇门。

## 2. manifest.json 字段

```json
{
  "id": "org.example.solarized",
  "name": "Solarized 主题",
  "version": "1.0.0",
  "apiVersion": 1,
  "kind": "theme",
  "description": "低饱和的暖色主题",
  "author": "example",
  "homepage": "https://example.org/solarized",
  "theme": {
    "light": { "--background": "oklch(0.98 0.01 90)", "--foreground": "oklch(0.3 0.02 220)" },
    "dark": { "--background": "oklch(0.22 0.02 220)", "--foreground": "oklch(0.93 0.01 90)" },
    "fontSans": "'Google Sans Flex', system-ui, sans-serif",
    "noise": false
  },
  "settings": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "accent": { "type": "string", "title": "主色", "enum": ["auto", "blue", "green"], "default": "auto" },
      "compact": { "type": "boolean", "title": "紧凑模式", "default": false },
      "size": { "type": "integer", "title": "字号", "minimum": 12, "maximum": 20, "default": 16 }
    }
  }
}
```

| 字段 | 必填 | 约束 |
|:--|:--|:--|
| `id` | ✅ | `^[a-z0-9][a-z0-9-]*(\.[a-z0-9-]+){1,5}$`，例如 `org.example.solarized`；全局唯一，卸载前不能重装同名 |
| `name` | ✅ | ≤ 40 字符 |
| `version` | ✅ | `x.y.z`（可带 `-prerelease`） |
| `apiVersion` | ✅ | 目前**只接受 `1`**；宿主不认的值直接拒绝安装 |
| `kind` | ✅ | `theme` / `fileType` / `server` |
| `description` | | ≤ 300 字符 |
| `author` | | ≤ 60 字符 |
| `homepage` | | ≤ 200 字符 |
| `permissions` | | 白名单：`fs.read` `fs.write` `ui.toast` `settings.rw`；**`theme` 必须为空数组** |
| `theme` | `kind=theme` 时必填 | 见下 |
| `settings` | | JSON Schema 子集（见 §5） |
| `entry` / `extensions` / `modes` | `kind≠theme` 时 `entry` 必填 | 包内相对路径，不能包含 `..` |

> **未知顶层字段会直接导致安装失败**。这是有意的：宁可装不上，也不要"某个字段被静默忽略、
> 作者以为生效了"。

## 3. 主题插件（声明式，零执行风险）

`theme` 只接受**声明式的 CSS 变量**，不接受任何 JS —— 因此它零执行风险。

| 字段 | 说明 |
|:--|:--|
| `theme.light` | 亮色模式下的变量表，键必须是 `--` 开头的 CSS 自定义属性（≤ 80 个） |
| `theme.dark` | 暗色模式下的变量表，规则同上 |
| `theme.fontSans` | 可选，字体栈；会作用到 `body` |
| `theme.noise` | 可选，布尔（保留字段，当前不改变行为） |

**值的安全约束**：长度 ≤ 200，且禁止 `;` `{` `}` `@` `<` `>` `\`、换行，以及 `url(` /
`expression(` / `javascript:`。原因很直接：这些值会被拼进一条 CSS 规则，能"逃出规则"就能改掉
整页样式，`url()` 甚至能引出一个远程请求（泄露访问者 IP）。

常用变量（写主题时抄这些就够；完整清单见 `web/src/index.css` 的 `@theme`）：

```
--background --foreground --card --card-foreground --popover --popover-foreground
--primary --primary-foreground --secondary --secondary-foreground --muted --muted-foreground
--accent --accent-foreground --destructive --border --input --ring
--radius-sm --radius-md --radius-lg --radius-xl
```

应用方式：管理员点「应用主题」后，服务端把令牌拼成一段**作用域受限**的 CSS
（`html[data-theme-plugin="<id>"]`），前端注入 `<style>`；点「恢复默认主题」即撤销。

## 4. 权限白名单（为什么插件拿不到文件）

宿主目前只定义了四个能力名，且**任何 kind 都不会自动获得**：

| 权限 | 含义 | 当前状态 |
|:--|:--|:--|
| `fs.read` | 读取当前用户可见的文件内容 | 通过 `readText` / `readBinary` 已可用（fileType 运行时） |
| `fs.write` | 保存文件（仍受 `fileWrite` + `editFiles` 约束） | 通过 `saveText` 已可用（fileType 运行时） |
| `ui.toast` | 由宿主弹提示（插件不能自己造 UI） | 通过 `notify` 已可用 |
| `settings.rw` | 读写插件自己的设置 | 已可用（`settings` schema） |

设计底线：**插件永远不直接访问 `/api`**。`fileType` 插件跑在 `sandbox="allow-scripts"` 的
iframe 里（见 §6），所有读写都通过 `postMessage` 请求宿主代执行，宿主再照常走 `req.perms` 校验。
换句话说：**插件的能力上限 = 当前登录用户的权限**，它拿不到 Cookie、也发不出同源请求。

## 5. 设置项：JSON Schema 子集

插件不需要写 React。声明 `settings`，后台「设置 → 插件 → 设置」会自动长出一张表单：

- 只支持 `type: "object"` + **扁平** `properties`（≤ 20 项），`additionalProperties` 只能是 `false`；
- 每个属性 `type` ∈ `string` / `number` / `integer` / `boolean`；
- `string` 可带 `enum`（下拉）、`maxLength`、`default`、`placeholder`；
- `number` / `integer` 可带 `minimum` / `maximum` / `default`；
- 可选的展示字段：`title`、`description`。

服务端保存时会**按 schema 再校验一遍**：越界、非枚举、类型不符都会 400，
并且**只保留 schema 里声明的键**（插件塞不进任意垃圾数据）。

## 6. 文件类型插件：沙箱 iframe + postMessage（P2）

`kind: "fileType"` 的插件负责**内置渲染器不认识的格式**（例如 `.dwg`、`.psd`）。
它被加载进预览页里的一个 iframe：

```html
<iframe sandbox="allow-scripts" src="/api/plugins/entry/<id>"></iframe>
```

四道约束（缺一条这条链路就不安全）：

| 约束 | 作用 |
|:--|:--|
| **`sandbox="allow-scripts"`，没有 `allow-same-origin`** | 文档变成**不透明源**：读不到父页面 DOM、拿不到本站 Cookie |
| **入口响应 CSP：`default-src 'none'` + `connect-src 'none'`** | 插件连子资源都发不出去，只能内联脚本/样式 + `data:`/`blob:` 图片 |
| **`entry` 必须是包内的单个 `.html`** | 天生自包含，不需要为加载 JS/CSS 再开口子 |
| **宿主只认 `event.source === iframe.contentWindow`** | 不透明源下 `event.origin` 恒为 `"null"`，用它校验等于没校验 |

### 消息协议（`apiVersion: 1`）

```
plugin → host   { type: "zs:ready" }
host   → plugin { type: "zs:init", apiVersion: 1, file: { path, name, size, mtime },
                  settings: {...}, canWrite: boolean, dark: boolean }
plugin → host   { type: "zs:request", id: <number>, method, params }
host   → plugin { type: "zs:response", id, ok, result?, error? }
plugin → host   { type: "zs:dirty", dirty: boolean }
```

| method | params | 返回 | 说明 |
|:--|:--|:--|:--|
| `readText` | `path?`, `encoding?` | `{ content, encoding, eol, baseVersion, … }` | 走 `/api/fs/file`（服务端自动识别编码） |
| `readBinary` | `path?` | `{ buffer: ArrayBuffer, mime }` | 上限 16 MB，超出拒绝 |
| `saveText` | `path?`, `content`, `encoding?`, `eol?`, `baseVersion?` | `{ ok, bytes, encoding, eol }` | 需要 `editFiles`；不传编码/换行时沿用最近一次 `readText` 的结果 |
| `notify` | `message` | `null` | 由宿主弹一条提示 |

**保存的并发语义**：`saveText` 会带上最近一次读到的 `baseVersion`。文件若已被别人改过，
服务端返回 409，宿主把错误原样回给插件（`ok: false`），**不会悄悄覆盖**。
保存成功后宿主会丢弃旧的 `baseVersion`，插件下次写入前应重新 `readText`。

### 最小插件示例

```html
<!doctype html>
<meta charset="utf-8">
<style>body{font:14px system-ui;padding:16px;color:#333}</style>
<p id="info">loading…</p>
<script>
  const info = document.getElementById("info")
  addEventListener("message", (e) => {
    const msg = e.data
    if (msg.type === "zs:init") {
      info.textContent = `${msg.file.name} · ${msg.file.size} bytes`
      parent.postMessage({ type: "zs:request", id: 1, method: "readText", params: {} }, "*")
    }
    if (msg.type === "zs:response" && msg.id === 1) {
      info.textContent = msg.ok ? msg.result.content.slice(0, 200) : "读取失败：" + msg.error
    }
  })
  parent.postMessage({ type: "zs:ready" }, "*")
</script>
```

把 `manifest.json` 与这个 `app.html` 一起压进 zip，`entry` 填 `app.html`，
`extensions` 填它负责的后缀（**必须声明**，否则安装会被拒）。

## 7. 安装、启用、卸载

| 动作 | 入口 | 说明 |
|:--|:--|:--|
| 安装 | 设置 → 插件 → 安装插件… | 上传 zip；服务端校验清单、apiVersion、权限、包体积（≤ 2 MB）与解压总量（≤ 10 MB） |
| 启用 | 列表里的开关 | **装完默认禁用**；启用时会重新读一次清单（被手改坏就拒绝） |
| 应用主题 | 主题插件行上的按钮 | 同一个时间只能有一个主题生效 |
| 卸载 | 列表里的垃圾桶 | 删除 `data/plugins/<id>/` 与它的设置；当前主题若正在用它，自动恢复默认 |

API（仅超管，`X-Requested-With: XMLHttpRequest` 必须带）：

```
GET    /api/admin/plugins                    列出 + 总开关状态
POST   /api/admin/plugins?filename=x.zip     安装（body 是 zip 原始字节，Content-Type: application/zip）
PATCH  /api/admin/plugins/:id                { enabled?: boolean, settings?: {...} }
POST   /api/admin/plugins/:id/theme          { active: true } 应用 / 取消
DELETE /api/admin/plugins/:id                卸载
GET    /api/plugins/theme                    公开：当前主题 CSS（访客也要能看到）
```

## 8. 打包与自测

```powershell
# 1) 写 manifest.json 到任意目录
# 2) 打 zip（内容必须在根，或放在单一顶层目录里也可以）
Compress-Archive -Path .\my-plugin\* -DestinationPath .\my-plugin.zip -Force
# 3) 在「设置 → 插件」上传，或在开发态直接调接口
```

自测清单（对应 `smoke-test.ps1` 第 17 / 18 组的断言）：

- [ ] 总开关关闭时安装返回 403；
- [ ] 装完列表里 `enabled: false`；
- [ ] 未启用就点「应用主题」返回 400；
- [ ] 应用后 `GET /api/plugins/theme` 返回的 CSS 里有 `data-theme-plugin` 与自己的变量；
- [ ] 设置越界值返回 400；
- [ ] 卸载后主题自动恢复默认；ileType 插件：未启用时不出现在 /api/plugins/list、入口返回 404；\n- [ ] 启用后入口响应带 sandbox allow-scripts 与 connect-src 'none'；\n- [ ] entry 写 .js 或缺少 extensions 时安装被拒（400）。

## 9. 版本与兼容

- `apiVersion` 目前只认 `1`。宿主将来若支持多版本，会在本文与 CHANGELOG 里写明兼容区间；
- 插件自身的 `version` 由作者维护，宿主只用来展示（不做"自动更新"）；
- **不会**自动更新插件：更新意味着权限可能变化，必须由管理员重新确认。

---

## 10. 已知边界（现在做不到的事）

- `server`（服务端子进程）插件的**运行时**尚未接入：可以装、可以启停，但不生效；
- 一个时间只能有一个主题生效；
- 插件不能添加自己的路由、不能读写任意路径、不能直连网络；
- `pkg` 打出的单文件 exe 与源码运行**行为一致**（插件不依赖原生模块），
  但 `data/plugins/` 需要可写。
