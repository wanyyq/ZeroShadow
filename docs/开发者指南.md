## 1. 技术底座

| 部分 | 技术 | 关键约定 |
|:---------- |:---------------------------------------------------- |:--------------------------------------- |
| 后端 | Node.js（**ESM**，`server/package.json` 里 `"type": "module"`）+ Express 4 | 全部使用 `import` / `export`，无构建步骤即可运行 |
| 前端 | React 19 + TypeScript + Vite 8 + Tailwind CSS v4 | 路径别名 `@` → `web/src`；组件用 shadcn CLI 生成 |
| 图标 | 本地 `lucide.min.js` + `<i data-lucide>` 占位，由 `createIcons()` 渲染 | 不用 CDN，内网离线可用 |
| 动画 | 本地 `gsap.min.js` + CSS 过渡 | 列表入场与页面入场动画（「减少动画」偏好会关掉它们） |
| 文本编码 | `iconv-lite` 0.7.3（MIT） | 在线编辑器的编码识别与写回；**服务端唯一为编解码引入的依赖**，其余模块都是手写的 |
| 打包 | Vite（前端）/ esbuild + pkg（后端） | esbuild 先把 ESM 打成 CJS，再由 pkg 生成 exe |

根 `package.json` **没有依赖**，只是一个脚本入口；依赖分别装在 `server/` 与 `web/` 两个子项目里，
各自有独立锁文件（`lockfileVersion: '9.0'`）。

> `server/package.json` 的 `dependencies` 就是后端全部第三方运行时依赖：
> `archiver`、`bcryptjs`、`busboy`、`cookie-parser`、`express`、`iconv-lite`、`jsonwebtoken`、`unzipper`。
> 完整清单（含版本与许可证）在「软件开源信息」页（`/about`）与 [使用手册 §19](使用手册.md#19-软件开源信息页)。

## 3. 后端

### 3.1 请求处理链（`server/index.js` 的中间件顺序）

```
关闭 x-powered-by
  → （可选）app.set("trust proxy", env.trustProxy)
  → GET /ping                     健康检查，纯文本 pong
  → 请求日志中间件                打印 [REQ] 方法 路径 host ip ua（静默模式下跳过）
  → 安全响应头中间件              nosniff / SAMEORIGIN / no-referrer / Permissions-Policy
  → cookieParser
  → socket.setNoDelay(true)       缓解隧道代理场景的缓冲问题
  → metricsMiddleware             请求指标（QPS / 状态码 / 慢请求）
  → createWebdavRouter()          WebDAV（挂在挂载点、未启用时自回 404）
  → attachAuth                    解析 Cookie 得到 req.auth = { role, username, userId }
  → attachContext                 解析 X-ZS-Group 小组上下文，算出 req.perms
  → /api 上的 csrfGuard           非 GET/HEAD/OPTIONS 校验自定义头与来源
  → express.json({ limit: SAVE_FILE_MAX_BYTES })   仅 /api/fs/save-file（16 MB）
  → express.json({ limit: "1mb" })                 其余 JSON 接口
  → GET /api/meta
  → /api/auth  /api/fs  /api/admin  /api/avatars  /api/todos  /api/groups
  → /api 兜底 404 JSON
  → express.static(WEB_DIST) + 非 /api 的 SPA fallback（带应用外壳 CSP）
  → 统一错误处理（5xx 记日志，只回"服务器内部错误"）
```

> **两条顺序不能动**（都是踩过坑之后才排成现在这样的）：
> 1. **body parser 必须在 `attachAuth` / `csrfGuard` 之后**。否则任何**未登录**者都能强迫服务把
>    16 MB 请求体解析成 JSON（`/api/fs/save-file` 是单独放宽的端点），几个并发请求就能把单核打满。
> 2. **`createWebdavRouter()` 必须在 body parser 之前**。WebDAV 的 `PUT` 是原始请求体，一旦被
>    `express.json()` 读完，`req.pipe(ws)` 只会写出 0 字节并以 204 成功返回——用户看到"保存成功"，
>    文件却被清空（静默数据丢失）。它也必须排在静态托管与 SPA fallback 之前，否则 `/dav/` 会被
>    fallback 吞掉、返回前端首页。挂载点可在后台改，所以这里**无条件挂载**，是否启用由中间件自己判断。

启动时会：自检并隔离损坏的数据文件（`integrity.js`，同时清空 `data/tmp/` 残留）→
重载配置 / 成员 / 小组 / 待办 → 重建头像索引（顺手删掉尺寸或格式不合规的文件）→ 做一次每日快照；
服务监听后启动指标采样（每分钟一次）与过期日志清理，并每 6 小时再清理一次日志 + 做每日快照；
若隧道已启用则拉起隧道。
退出信号（`SIGINT` / `SIGTERM`）会先停隧道与指标再关服务，兜底 3 秒强制退出。

进程级兜底（`server/index.js` 末尾）：`unhandledRejection` 与 `uncaughtException` 都**只记日志、不退出**。
理由是本项目没有 Docker / pm2 之类的进程管理器——一次失败的上传清理（例如磁盘写满后 `rm` 也失败）
如果让进程退出，局域网里所有人的网盘会同时断线。对应日志事件名是
`unhandled_rejection` / `uncaught_exception`（可在「设置 → 日志与指标」里筛）。

### 3.2 权限是怎么判的

两级中间件（`server/src/auth.js`）：

```js
requireRole("superadmin")            // 按角色
requirePerm("compressZip")           // 按 req.perms（effectivePerms(role, group) 的结果）里的权限点
```

`effectivePerms(role, group)`（`server/src/config.js`）是**唯一的权限真相来源**：
把 `config.json` 里的 `memberPerms` / `guestPerms` 与角色叠加，算出最终布尔表
（例如成员的写类权限都要 `fileWrite` 为真）。前端拿到的 `perms` 就是它的输出。

小组（`server/src/groups.js`）在此基础上再做一层**收窄**：`attachContext` 先解析请求头
`X-ZS-Group`（或 `?group=` 兜底）并校验成员归属，然后把该组的 `perms` 与全局结果**逐键取与**，
写进 `req.perms`。所有 `requirePerm` 读的都是 `req.perms`，所以「切换小组 → 立即生效」不需要额外机制；
可见范围同理，由 `isVisibleForContext` 统一判定（黑名单优先、白名单为空即不限制）。
小组的可见性在**递归操作里也必须逐层应用**：打包 / 压缩走 `zipVisibility()`，
否则会出现"列表里看不到、zip 里却能拿到"。

**新增权限点的完整步骤**：

1. `server/src/config.js`：在 `DEFAULTS.memberPerms`（或 `guestPerms`）里加默认值；
2. 同文件 `effectivePerms()`：给对应角色返回这个键；
3. 目标路由：加上 `requirePerm("你的键")`；
4. `web/src/lib/types.ts`：在 `Perms` 接口里加字段；
5. `web/src/state/auth.tsx`：在 `GUEST` 兜底常量里补一个默认值（未登录时前端要用）；
6. `web/src/pages/settings/index.tsx`：用 `permItem(...)` 在「权限」页加一个开关；
7. 想让小组也能收窄这个权限点：`web/src/pages/settings/groups-section.tsx` 的 `PERM_GROUPS`
   会自动跟随 `MEMBER_PERM_KEYS`，但分组与中文名要手工补上（写类的键还要加进 `WRITE_PERM_KEYS`）。

### 3.3 数据存放

| 数据 | 位置 | 生命周期 |
|:-------------- |:------------------------- |:--------------------------------------- |
| 服务配置 | `data/config.json` | 启动时读入内存，后台修改后原子写回 |
| 成员账号 | `data/users.json` | 同上；密码为 bcrypt 哈希 |
| 小组 | `data/groups.json` | 启动时读入内存；成员 / 组长 / 权限收窄 / 可见范围 / 组长能力 |

避免并发覆盖和半个文件；**覆盖写之前会自动把旧内容快照进 `data/backups/`**（`backup.js`），
所以后台改错配置也能回滚。

### 3.4 长任务模型

`compress` / `extract` / `download-url` 三个接口都是**先返回 `jobId` 再后台执行**：

```
POST /api/fs/compress        → { jobId }
   ↓ 前端每 400ms 轮询
GET /api/fs/compress/status?job=<id>  → { state, percent, processed, total, processedBytes, error }
```

- 任务对象里有 `createdBy`，默认只有创建者与超管能查询（`jobStatusOwnerOnly`）；
- 状态机：`running` → `done` / `error`；任务被清理后查询返回 `state: "gone"`；
- 失败时（含解压中途超限）会清理临时产物——解压会**整个删掉半成品目录**，
  压缩会**删掉已经写出的半个 `.zip`**，并如实把状态置为 `error`（而不是 `done`）。

### 3.5 在线编辑的编码处理（`server/src/encoding.js`）

在线编辑器的编解码**全部收在服务端**这一个模块里，前端只拿最终文本：

| 导出 | 作用 |
|:---------------------- |:----------------------------------------------------------- |
| `EDITOR_ENCODINGS` / `encodingList()` | 支持的编码表（id / label / bom），前端下拉框直接用 |
| `detectEncoding(buf)` | 识别编码，返回 `{ encoding, bom, confident }`；`confident: false` 表示是靠打分猜的，前端会提示用户手动切换 |
| `decodeBuffer(buf, encoding)` | 解码并剥掉 BOM |
| `detectEol(text)` / `applyEol(text, eol)` | 换行风格探测与还原（读取时统一成 `\n`，保存时按选择写回 `crlf` / `lf` / `cr`） |
| `encodeText(text, encoding)` | 编码并**回读比对**，返回 `{ buffer, unmappable }`；目标编码表示不了的字符由调用方报 400 |
| `looksBinary(buf)` | 二进制判定（NUL 字节，或控制字符比例 > 10%） |
| `EDITOR_MAX_BYTES` | 单次读取上限 8 MB |

识别的判定顺序（每一步都有理由，改之前请先读懂）：

1. **BOM**：`utf8bom` / `utf16le` / `utf16be`，最确定，直接采信；
2. **无 BOM 的 UTF-16**：按 16 位单元落在「可打印 ASCII / CJK / 常用标点」里的比例打分，
   两种字节序差距 > 0.1 才认（只看 NUL 字节是不够的——纯中文的 UTF-16 一个 NUL 都没有）；
3. **严格 UTF-8**：`TextDecoder("utf-8", { fatal: true })` 不抛异常就认定 UTF-8（含 NUL 时跳过这一步）；
4. **逐个候选编码打分**：`gb18030` / `big5` / `shift_jis` / `euc-kr` / `windows-1252` / `iso-8859-1`，
   用「命中常用字的数量 ×3 − 替换字符 ×100 − 控制字符 ×20」排序取最高分。
   只数替换字符是不够的：GB18030 几乎能解码任意字节序列，拿它去解 Big5 文件往往一个替换字符都没有，但内容是错的；
5. **候选都不像正常文本时**才回头采信第 2 步的 UTF-16 结果（顺序很关键：
   Shift_JIS 的假名字节按 UTF-16BE 读会落在汉字区，让候选编码先表态才不会把日文误判成 UTF-16）。

写回时的两条硬约束：**BOM 要按编码补上**（UTF-16 没有 BOM 就无法区分字节序），
**表示不了的字符宁可拒绝也不静默写成 `?`**（`encodeText` 回读比对，最多列出 12 个字符交给前端提示）。

### 3.6 想加一个接口

```js
// server/src/routes/fs.js
router.post("/my-op", requirePerm("editFiles"), rateLimit, async (req, res, next) => {
  try {
    const { abs, rel } = resolveSafe(req.body?.path)   // 一定走 safety.js
    blockSoft(rel)                                     // 只读映射目录要拦住
    // ...业务
    info("my_op", { msg: rel, ...actor(req) })         // 记日志
    res.json({ ok: true })
  } catch (err) { next(err) }
})
```

要点：**路径一律用 `resolveSafe` / `resolveAny` 解析**（自带穿越防护），
写操作要先 `blockSoft`，需要限流就挂 `rateLimit`，错误统一交给 `next(err)`（`httpError(status, msg)` 造错误）。
涉及路径的端点还应当调用 `assertContextVisible(req, rel)`，让小组 / 默认可见范围对读写都生效
（`attachContext` 已经全局挂好，`req.perms` / `req.group` 随取随用）。
新路由文件要在 `server/index.js` 里 `app.use("/api/xxx", xxxRoutes)` 挂上。
前端在 `web/src/lib/api.ts` 里加一个薄封装即可。

### 3.7 内容版本与并发编辑（`server/src/version.js`）

版本串是 `<mtimeMs>-<size>-<内容哈希>`，同时用在三处：

| 用处 | 位置 |
|:------------------ |:--------------------------------------- |
| 在线编辑器的乐观并发控制 | `GET /api/fs/file` 返回 `baseVersion`；`POST /api/fs/save-file` 校验它 |
| HTTP `ETag` | `GET /api/fs/download` 与 WebDAV 的 `GET`，让客户端能用 `If-Match` / `If-None-Match` |
| WebDAV `PUT` 的 `If-Match` 前置条件 | 不匹配返回 412 |

**为什么不能只用 `mtime`**：Windows 的 mtime 粒度可达秒级（FAT 更粗），
同一秒内的两次保存用 `mtime` 区分不开，会把真实冲突漏判。所以必须带上内容哈希。
哈希用 sha1 是因为这里只做"内容变没变"的指纹，不是密码学用途，短且快。

改动这一块时注意：`versionOf()` 必须保持一致 —— 编辑器认的版本和 WebDAV 客户端认的
`ETag` 如果算法不同，就会出现"浏览器里保存提示冲突、但用 DAV 客户端却能写进去"这种怪事。

### 3.8 回收站（`server/src/trash.js`）

- 布局：`data/trash/<时间戳>-<随机>/meta.json` + `content`；
- **必须放在 `data/` 下**：放进 `FILES_DIR` 会让它出现在网盘根目录，被列目录、被搜索、
  被打包，甚至能按路径被访客下载；
- 移入用 `rename`（同盘原子）；跨设备 `EXDEV` 时退化为"先复制成功、再删原件"；
- 元数据用 `store.js` 的原子写；
- **目录建不出来不能抛异常**：`trash.js` 顶部的 `ensureDir()` 会捕获失败并置标志，
  写操作退回"直接删除"。早期版本在模块加载时直接 `mkdirSync`，`data/` 只读会让
  **整个服务起不来**（连登录界面都打不开）；
- 清理时机：服务启动时 + 每 6 小时的维护定时器（`sweepTrash`），天数取
  `config.trashRetentionDays`。

### 3.9 文件详细信息（`server/src/fileinfo.js`）

「详细信息」对话框里除基础字段以外的内容全部来自 `GET /api/fs/details`，实现集中在这一个模块：

| 能力 | 做法 |
|:--|:--|
| 签名识别 | 头 64KB 内按固定偏移比对的签名表，加几个需要上下文的特例：`ftyp` 品牌（MP4 / MOV / HEIC / AVIF / CR3）、RIFF 子类型（WAV / AVI / WebP）、用 ZIP 内部条目名区分 docx / xlsx / pptx / apk / jar / epub、偏移 257 的 `ustar`、MPEG-TS 的同步字节 |
| 图片尺寸 | PNG 的 `IHDR`、JPEG 逐段扫 `SOF`、GIF / BMP / WebP（`VP8 ` / `VP8L` / `VP8X`）、PSD、ICO |
| EXIF | 自带的 TIFF / IFD 解析器：IFD0、ExifIFD（`0x8769`）、GPS IFD（`0x8825`），按类型读取后格式化成中文（`1/125 秒`、`f/2.8`、GPS 十进制度） |
| 文档属性 | PDF 的 Info 字典（**头尾各 64KB 都搜**，兼容 Info 在文件尾的写法）、OOXML 的 `docProps/core.xml` 与 `app.xml`（就地定位并解压一个 ZIP 条目，用内置 `zlib.inflateRawSync`） |
| 媒体信息 | MP4 / MOV / M4A 沿顶层 box 走到 `moov` 再读 `mvhd`（**不能只搜开头**：未做 faststart 的文件 `moov` 在末尾且可能大于 64KB）、WAV 的 chunk、FLAC 的 `STREAMINFO`、ID3v2 帧 |
| 文本信息 | 复用 `encoding.js` 的探测；**只有签名判定为文本时**才统计编码与行数，否则 MP3 的 ID3 区会被误认成 UTF-16 文本 |
| 哈希 | `fs.createReadStream` + 三个 `crypto` Hash 流式计算；其中 sha1 的 base64url 与 `version.js` 的内容哈希同源，所以 `contentVersion` 和 `baseVersion` 是同一个串 |

三条纪律：

- **不整文件读进内存**：解析只读头尾各 64KB，哈希流式计算且限 64MB，文本统计限 8MB；
- **分段容错**：每一段都包在自己的 `try/catch` 里，解析失败只让那一段为 `null`，
  绝不能因为一个坏 EXIF 就返回 5xx；
- **不新增配置项**：上限都是模块内常量（`HEAD_BYTES` / `HASH_MAX_BYTES` / `TEXT_SCAN_BYTES`），
  不为一次详情点击引入需要文档化的新开关。

### 3.10 文件转换（`server/src/convert/`）

v2.1.0 引入。路由只负责鉴权、路径校验、读写与进度，具体能转什么全由这里的注册表决定：

| 文件 | 职责 |
|:-- |:----------------------------------------------------------- |
| `index.js` | 内置转换器的**注册点**（`registerConverter(...)`），也是对外出口 |
| `registry.js` | 转换器注册表：校验定义、按扩展名查表、生成下发给前端的清单 |
| `queue.js` | 并发闸门：同时最多 4 个转换在执行、最多 32 个排队，队列满回 503（`api.fs.convert_busy`） |
| `markdown.js` | 手写 Markdown 解析器（块级 + 行内）与纯文本渲染 |
| `converters/md-to-txt.js` | Markdown → 纯文本 |
| `converters/md-to-pdf.js` | Markdown → PDF（A4） |
| `converters/image.js` | PNG → JPG、JPG → PNG（走 `sharp`，可降级） |
| `pdf/font.js` | 找一个能排中文的系统字体，提供度量视图 |
| `pdf/truetype.js` | 只读 TrueType 解析 + 子集化（保留原始字形号，供 Identity-H 内嵌） |
| `pdf/layout.js` | 块列表 → 页面操作（折行、分页、表格、页脚、链接矩形） |
| `pdf/document.js` | 最小 PDF 1.7 写出器（对象 / xref / trailer / 内容流 / 字体对象） |

三个设计取舍：

- **零新增依赖**：PDF 写出与 TrueType 子集化都是自己写的。后端依赖清单刻意精简（见 [§1](#1-技术底座) 那张表），
  为一个导出功能引入 PDF / 字体库不划算；
- **注册表驱动**：加一种格式不需要改路由、也不需要改前端——右键菜单的「转换为」子项按
  `GET /api/fs/convert/targets` 返回的清单动态渲染。图片转换复用项目已有的 `sharp`；
  单文件 exe 里没有 `sharp` 时返回 **501**（`api.fs.convert_no_sharp`），与缩略图是同一套降级思路。
- **为什么需要 `queue.js`**：图片转换走原生解码、PDF 排版是纯 CPU 循环，两者都会把单个核心吃满。
  网盘是"一个人的机器给全组人用"，没有配额也没有进程管理器，所以转换必须自己限并发
  （与缩略图队列同一思路，参数按"用户主动发起"放宽到 4 / 32）。新加的转换器**自动**被这个闸门保护，
  不需要自己处理排队。

接口与错误码见 [API 参考](API参考.md#post-apifsconvert)。三个接口都挂在 `convertFiles` 权限点下，
`POST /api/fs/convert` 另外要求对源文件有读权限（`preview` 或 `downloadFile`）。
它和压缩 / 解压共用同一套作业模型（`createJob` / `patchJob` / `finishJob` / `failJob`），
只是任务状态里多两个字段：`notes`（补充提示，例如字体缺字已用 `?` 代替）与 `output`（产物相对路径）。

### 3.11 如何新增一种转换

四步，全在服务端：

1. **写模块**：在 `server/src/convert/converters/` 下新建一个 `.js`，导出一个（或几个）转换器对象；
2. **注册**：在 `server/src/convert/index.js` 里 `import` 进来并 `registerConverter(你的转换器)` 一次
   ——数组顺序即右键菜单里的显示顺序，定义写错会**在启动时就抛错**，而不是等用户点了菜单才 500；
3. **补译文**：给它的 `labelKey` 在 `web/src/locales/<语言>/convert.json` 里补上译文
   （不补也能用，会显示 `label` 里的中文兜底）；
4. **补断言**：在 `scripts/convert-test.mjs` 里加一条（`node scripts/convert-test.mjs` **不需要起服务**）。

转换器对象的字段（`registry.js` 的 `registerConverter` 会逐个校验）：

| 字段 | 必填 | 说明 |
|:-- |:-- |:----------------------------------------------------------- |
| `id` | 是 | 唯一标识，会出现在接口里（`POST /api/fs/convert` 的 `target` 传它） |
| `from` | 是 | 源扩展名数组，小写、不带点 |
| `to` | 是 | 目标扩展名，小写、不带点——决定产物文件名 |
| `label` | 否 | 中文兜底文案；缺省时由 `from` / `to` 拼出来 |
| `labelKey` | 否 | i18n 键，如 `ui.convert.md_pdf` |
| `input` | 否 | `"text"` = 先按识别出的编码解码，再把 `text` 交给 `run`；`"buffer"`（默认）= 传原始字节 |
| `maxBytes` | 是 | 源文件上限（字节），超过直接 413、不进转换 |
| `run` | 是 | `async (ctx) => ({ data: Buffer, notes?: string[] })` |

`run` 拿到的 `ctx` 是 `{ text?, buffer?, name, ext, encoding?, eol?, onProgress(percent), job }`，
返回的 `notes` 会原样进任务状态的 `notes` 数组。

示例（内置的 `converters/md-to-txt.js` 节选，`run` 的换行处理从略）：

```js
export const mdToTxt = {
  id: "md-to-txt",
  from: ["md", "markdown", "mdown", "mkd"],
  to: "txt",
  label: "Markdown → 纯文本",
  labelKey: "ui.convert.md_txt",
  input: "text",
  maxBytes: TEXT_MAX_BYTES,   // 4 MB
  run({ text, eol }) { /* 解析 → 去标记 → 按源文件的换行风格输出 */ },
}
```

新转换器会自动纳入并发闸门（`convert/queue.js`）：同时最多 4 个执行、32 个排队，排队与 503
都由闸门处理，转换器自己**不需要**处理排队；要调这两个数就改 `queue.js` 顶部的常量。

### 4.4 图标与动画

- `lib/lucide.ts` 提供 `initLucide()`：在 `DOMContentLoaded`、`load` 与
  **MutationObserver 监听到新节点**时调用 `window.lucide.createIcons()`，
  这样动态渲染出来的图标也能正确显示；
- `animateListIn()` / `animatePageIn()` 用 GSAP 做入场动画；GSAP 不存在时**静默跳过**，不影响功能。
  两者都会先看「设置 → 外观 → 减少动画」（`html[data-reduce-motion="1"]`）**以及系统的
  `prefers-reduced-motion`**，命中任一就不再播放。

> **动画必须守住的规矩**（违反过，代价是整页掉帧）：
>
> 1. **只动 `transform` 与 `opacity`**，不要动 `width/height/top/left`（会逐帧触发布局）；
> 2. **绝对不要给 `<html>` 或整页容器做动画**。曾经对 `document.documentElement` 淡入、
>    又给整页容器做 `y` 位移，等于每帧重绘/合成整屏，好机器都卡，机房机器更不用说。
>    整页级别的入场动画已全部移除，只保留小元素（如登录卡片）的入场；
> 3. **同一批元素只保留一个 tween**：`animateListIn` 会先 `kill()` 上一个再新建，
>    否则列表刷新频繁时会叠成好几个同时跑，既闪又费；
> 4. **限制数量**：只对前 36 个元素做错落（`MAX_STAGGER_ITEMS`），长列表直接不播；
> 5. **不要每次刷新都重放**：文件页只在「换目录 / 换搜索」时播一次，
>    团队页只在筛选条件变化时播一次——上传、删除、勾选完成之后的 `refresh()` 不再重放。
>
> 详见 `lib/lucide.ts` 顶部的注释（规则来自 GSAP 官方的 gsap-core / gsap-performance 指引）。

### 4.5 兼容模式（`robustness`）

给"跑不动 React / Tailwind 的老机器"用的一份**独立静态页面**，
源码在 `web/public/robustness/`，构建后由 `express.static(WEB_DIST)` 直接托管，
访问路径 **`/robustness/index.html`**：

```
web/public/robustness/
├── index.html       页面骨架（<head> 里同步加载 theme-boot.js）
├── index.css        样式（沿用正常页面的 oklch 配色，写法退回 IE11 能吃的那套）
├── index.js         全部逻辑（ES5 + XMLHttpRequest + 回调）
└── theme-boot.js    首帧应用深色，避免白闪
```

**它不是前端工程的一部分**：不经过 Vite 打包、不引用任何 npm 依赖，
`public/` 会被原样复制到 `web/dist/robustness/`。

改这个目录下的文件时必须遵守这几条，否则老浏览器会整页白屏：

| 约束 | 原因 |
|:------------------ |:--------------------------------------- |
| 只用 **ES5**：不用 `let`/`const`/箭头函数/模板字符串/解构/`class`/`for...of` | 目标浏览器含 IE11 |
| 不用 **Promise / fetch** | IE11 都没有；统一 XHR + `function (err, data)` 回调 |
| 不用现代 DOM API：`classList` / `dataset` / `closest` / `Object.assign` / `includes` / `startsWith` | IE11 缺失 |
| **不写内联 `<script>`** | 后端给 `web/dist` 下的 `.html` 挂了 `script-src 'self'` 的 CSP（见 `server/index.js` 的 `SHELL_CSP`），内联脚本会被拦掉 |
| 不写内联事件属性（`onclick="..."`） | 同上，CSP 不允许；统一用 `node.onclick = fn` 赋值 |
| 所有拼进 `innerHTML` 的字符串先过 `esc()` | 文件名与路径都是用户可控输入 |
| 每个请求都带 `X-Requested-With: XMLHttpRequest` | 这是 `csrfGuard` 的第一道校验 |
| 修改后跑 `node --check web/public/robustness/index.js` | 快速排掉语法错误 |

**为什么不需要放松任何安全设置**：同源 XHR 设置自定义头不触发 CORS 预检，
而 IE11 的**同源**请求不带 `Origin` 头，所以 `csrfGuard` 的第二道校验（比对
`Origin` 与 `Host`）自然放行。因此这个页面零安全例外——不要为了它去改
`csrfOriginCheck` 或加什么白名单。

**与服务端的两处约定**（改接口时要注意，否则兼容页会静默出错）：

1. `MAX_FILES_PER_REQUEST = 100`：服务端丢弃超出的文件且只回 `truncated: true`，
   兼容页自己按 100 分批（`web/src/state/uploads.tsx` 里的同名常量也是这个值，
   三处必须一致）。
2. 文件夹上传靠 **filename 里带相对路径**还原目录结构。浏览器只把相对路径给到
   `webkitRelativePath`，而服务端 busboy 读的是 `filename`，所以兼容页会先
   `new File([file], relativePath, ...)` 把名字改写成相对路径再上传。

**预览策略**：不自己解析任何文件格式，能交给浏览器原生组件的就交给它
（`<img>` / `<video>` / `<audio>` / `<iframe>` 加载 PDF），并在元素上挂 `onerror`
兜底成「浏览器不支持此格式」；文本类走 `GET /api/fs/file`（服务端识别编码）后
以文本节点只读显示。**不要**在这里引入任何 JS 解析库。

**入口**：正常页面底部状态条右侧的「无法渲染？使用兼容模式」链接
（`web/src/pages/browser-page.tsx` 末尾），用原生 `<a target="_blank">` 打开，
不走 react-router。

---

- `lib/lucide.ts` 提供 `initLucide()`：在 `DOMContentLoaded`、`load` 与
  **MutationObserver 监听到新节点**时调用 `window.lucide.createIcons()`，
  这样动态渲染出来的图标也能正确显示；
- `animateListIn()` / `animatePageIn()` 用 GSAP 做入场动画；GSAP 不存在时**静默跳过**，不影响功能。
  两者都会先看「设置 → 外观 → 减少动画」（`html[data-reduce-motion="1"]`）**以及系统的
  `prefers-reduced-motion`**，命中任一就不再播放。

> **动画必须守住的规矩**（违反过，代价是整页掉帧）：
>
> 1. **只动 `transform` 与 `opacity`**，不要动 `width/height/top/left`（会逐帧触发布局）；
> 2. **绝对不要给 `<html>` 或整页容器做动画**。曾经对 `document.documentElement` 淡入、
>    又给整页容器做 `y` 位移，等于每帧重绘/合成整屏，好机器都卡，机房机器更不用说。
>    整页级别的入场动画已全部移除，只保留小元素（如登录卡片）的入场；
> 3. **同一批元素只保留一个 tween**：`animateListIn` 会先 `kill()` 上一个再新建，
>    否则列表刷新频繁时会叠成好几个同时跑，既闪又费；
> 4. **限制数量**：只对前 36 个元素做错落（`MAX_STAGGER_ITEMS`），长列表直接不播；
> 5. **不要每次刷新都重放**：文件页只在「换目录 / 换搜索」时播一次，
>    团队页只在筛选条件变化时播一次——上传、删除、勾选完成之后的 `refresh()` 不再重放。
>
> 详见 `lib/lucide.ts` 顶部的注释（规则来自 GSAP 官方的 gsap-core / gsap-performance 指引）。

### 4.6 WebDAV（正式功能，`server/src/webdav.js`）

**v2.0 起为正式功能**：开关与挂载点都在后台（`data/config.json` 的 `webdavEnabled` /
`webdavPath`），默认关闭，改完**实时生效**。`.env` 的 `WEBDAV` / `WEBDAV_PATH` 只作为
这两个字段的**默认值**（见 `server/src/config.js` 的 `DEFAULTS`）。

入口在 `server/index.js`，**无条件挂载一次**：

```js
app.use(createWebdavRouter())   // 永远返回中间件；是否命中/是否启用由中间件自己判断
```

挂载时机的三个要点，改动时别踩：

1. **必须在 body parser 之前挂**。DAV 的 `PUT` 是原始请求体，一旦被 `express.json()`
   读完，`req.pipe(ws)` 只会写出 0 字节却回 204（静默数据丢失）；
2. **必须在 `express.static` 与 SPA fallback 之前挂**。否则 `/dav/` 会被 fallback 吞掉、
   返回前端首页 —— 用户把地址填进客户端后拿到的是网页，非常难排查；
3. **未启用时由中间件自己 404**（不再需要 `index.js` 里那段静态兜底）。
   只靠"不挂载"是不够的：`app.get("*")` 会接住一切 GET，于是 `/dav` 仍然返回首页。
   这也是为什么早期症状是"`GET /dav` 返回网页、`PROPFIND /dav` 却 404"这种自相矛盾的现象。

**为什么挂载点可以随时改**：中间件每个请求都算一次 `davPath()` 并判断"是否命中前缀"，
所以后台改 `webdavPath` 立即生效（`normalizeDavPath()` 会拒绝 `/api`、`/assets`、
前端路由等保留前缀，避免把接口或静态资源整片遮住）。

三条**不能改**的安全约束（改了就是漏洞）：

| 约束 | 原因 |
|:------------------ |:--------------------------------------- |
| 只认 Basic 认证，**不认 Cookie 会话** | 认 Cookie 就等于给了任意网页一个绕过 CSRF 的后门：它可以用用户浏览器里已有的登录态发 `PROPFIND` / `PUT`，而 DAV 请求不会带 `X-Requested-With`、也走不到 `csrfGuard` |
| **不接受超管账号** | Basic 凭据每个请求都会重复发送，超管密码不该被这样反复暴露。只走 `verifyLogin()`（成员账号、bcrypt），超管显式 403 |
| 权限与路径复用 Web 端那套 | `effectivePerms(role, group)` + `normRel`/`resolveAny`；隐藏路径返回 **404**（不是 403，避免探测"这里有什么"） |

方法与权限的对应：`OPTIONS`（免认证，公告能力）、`PROPFIND`→browse、`GET/HEAD`→downloadFile、
`PUT`→fileWrite+upload、`MKCOL`→mkdir、`DELETE`→delete（走回收站）、
`COPY/MOVE`→copy/move（`Destination` 头要按同样规则剥离前缀并重新做穿越校验，
且**主机必须与本站一致**否则 502）、
`LOCK/UNLOCK`→内存锁表（**只是让客户端认为锁生效**，真正的并发保护靠 `version.js`）。

性能与抗洪水的三处实现，改之前先读注释：

- **凭据缓存**（`credCache`）：`sha256(username + 口令) → { userId, tokenVersion }`，
  TTL 60 秒、上限 500 条；命中后仍校验 `tokenVersion`，所以改密码 / 禁用立即失效。
  没有它，Basic 认证就是"每请求一次 bcrypt"（成本 10 ≈ 100ms）的 CPU 放大器。
- **按 IP 限流**（`davRateLimited`）：1200 次/分钟，计数表 5000 条上限、按最早淘汰。
- **元数据请求体上限** 64 KB（`PROPFIND`/`PROPPATCH`/`LOCK` 我们根本不读 body）。

改完请跑一遍 `smoke-test.ps1` 第 14 组（25 项 DAV 断言，含"仅带 Cookie 必须 401"、
"超管必须 403"、`Depth: infinity` 403、`Destination` 跨主机 502、挂载路径实时切换）。

### 4.7 缩略图与虚拟滚动（`server/src/thumbs.js` + `web/src/lib/virtual.ts`）

**缩略图**（v2.0）解决的是"网格视图直接拉原图"：一张 4K 照片好几 MB，弱网/穿透下滚动直接卡死。

- 服务端在 `GET /api/fs/thumb?path=&w=` 里用 `sharp` 生成 webp（宽度收敛到
  `96/128/192/256/384/512` 白名单），权限跟 `preview` 走，路径照过 `resolveAny` + 上下文可见性；
- **内容寻址缓存**：键 = `sha1(rel | size | mtimeMs | 宽度)`，落在 `data/thumbs/<key>.webp`。
  文件一变键就变，所以既不会拿到旧图，也可以放心让浏览器长期缓存（响应带 `max-age`）；
- **原子写 + 并发闸门**：先写临时文件再 rename；最多 2 个解码任务，排队上限 64（满了回 503）；
- **可降级**：`sharp` 是原生模块，**pkg 打出来的单文件 exe 里没有它**。加载失败时
  `thumbAvailable()` 为假、路由回 501，前端 `EntryThumb` 收到 `onError` 就退回图标；
- 输入限制：只认 `jpg/jpeg/png/webp/gif/avif/tiff/tif/bmp`（**不含 svg**：光栅化复杂 SVG 会吃 CPU）、
  单文件 ≤ 64 MB、解码像素 ≤ 8000 万；
- `data/thumbs` 已加入 `safety.js` 的敏感条目（不能被网盘接口列举/下载），
  启动时与每 6 小时由 `sweepThumbs()` 清理（30 天过期 + 512 MB 预算，按最旧淘汰）；
- 打包注意：`server/package.json` 的 `bundle` 脚本必须带 `--external:sharp`，否则 esbuild 会尝试把原生模块打进去。

**虚拟滚动**（`web/src/lib/virtual.ts`）：

- `useVirtualRows(count, rowHeight, resetKey)` —— 定高行窗口化。文件列表的行高由
  `--row-py` 与 `text-sm` 决定，所以**行高是量出来的**（`[data-file-row]` 的 `offsetHeight`），
  不要写死；`resetKey` 变化（换目录/搜索词/视图）时会把 `scrollTop` 归零，否则会停在上一个
  目录的偏移量上只显示中间几行。
- `useProgressiveReveal(count, step, resetKey)` —— 网格用"滚到底再追加一批"，
  因为卡片高度会随文件名换行变化，硬套定高会裁内容。
- 两者都要求渲染函数接收**绝对索引**（`virt.start + i`），否则 Shift 连选的区间会错。

### 4.8 Markdown 预览渲染（`lib/markdown.ts` + `lib/markdown-html.ts`）

`.md` 预览的渲染器是**自己写的**，没有引入第三方 Markdown 库（`marked` / `markdown-it`
会让前端产物多出 30~110KB）。它的安全前提只有一条：

> **先整体转义，再解析。** `inline()` 一进来就把 `&` `<` `>` `"` 转成实体，此后所有正则
> 只处理已经转义过的文本，而生成出来的标签全是我们自己拼的。因此输出串里不可能出现
> 来自文件的标签，可以安全地交给 `dangerouslySetInnerHTML` —— 不存在 XSS 通道。

唯一的例外是一张**固定的无属性标签白名单**（`lib/markdown-html.ts` 的 `SAFE_HTML_TAGS`，
13 个：`br` / `hr` / `sub` / `sup` / `kbd` / `u` / `s` / `mark` / `small` / `span` / `div` /
`p` / `center`）。它把"已转义文本里的 `&lt;br&gt;`"还原成字面标签（如 `<br />`），**属性全部丢弃**，
所以"输出可信"这个前提没有被打破。

- **属性必须写成 `name=value`**（值可带引号或 `&quot;`）；`<span and more text>` 这种像标签的
  残句不会被当成标签，避免把正文吞掉 —— 这条规则由 `ATTRS_RE` 保证，改之前请先读注释；
- 还原动作排在**行内代码抠走之后**、图片 / 链接解析之前：代码里的 `<br>` 是示例，不该被渲染；
- 行内代码、链接地址、图片地址先用 `NUL + 序号 + NUL` 的占位符"抠出来"，最后再还原
  （占位符可能嵌套，所以还原要跑最多 4 轮）；
- 危险协议（`javascript:` / `vbscript:` / `data:`）命中即降级为纯文本；
- 样式集中在 `index.css` 的 `.md-body` 段：渲染器只产出语义标签、**不给任何 class**，
  这样既省字节，也避开"运行时生成的 HTML 里写的工具类 Tailwind 扫不到、根本不会进产物"
  这个坑；
- 预览页正文与源码视图都带 `select-text`：外层 `ContextMenuTrigger` 自带 `select-none`，
  不给这两处覆盖的话整页文字都选不中（"Markdown 不能复制"的根因）；
- **兼容模式的预览不在改动范围内**：那是独立静态页（见 4.5），
  它对 `.md` 仍然是等宽字体只读展示。

改这个模块后请跑 `node --experimental-strip-types scripts/markdown-html-test.mjs`（28 项）。
**加一个标签等于改安全边界**，必须同时补它的断言。

### 4.9 弱网 / 内网穿透优化（`lib/api.ts` + `web/public/sw.js`）

穿透链路（pinggy / serveo / Cloudflare Tunnel）的典型症状不是"连不上"，而是**偶发丢包、
RTT 抖动、首包慢**。这里分三层处理，改动时注意各自的边界：

**① 请求层（`lib/api.ts` 的 `request()`）**

| 机制 | 取值 | 注意 |
|:--|:--|:--|
| 超时 | 20 秒（`AbortController`） | 慢链路不该被无限等待拖住；也不该像某些实现那样 5 秒就误杀 |
| 自动重试 | 仅 `GET`/`HEAD`，最多 2 次，退避 `400ms` → `1200ms`（±20% 抖动） | **POST 绝不重试**：重试等于重复创建/重复上传 |
| 触发条件 | 网络错误、超时、`502/503/504` | 4xx 不重试（重试也没意义，还会放大日志） |
| 离线 | `navigator.onLine === false` 时直接失败 | 避免在断网时刷出一串超时 |
| 提示 | `setOnNetworkError()` → `state/auth.tsx` 里 **8 秒节流** 弹一次 toast | 一次断网会让并发请求同时失败，不节流会连弹五六个 |

**② 缓存层（`web/public/sw.js`）**

- `/assets/*`（内容哈希）→ **cache-first**；`/resources/*`（字体/图标/语言包）→ stale-while-revalidate；
- **不接管**：`/api/*`、`/dav`、Range 请求、以及**页面导航**（`index.html` 带 no-cache 且引用哈希资源，
  缓存它会引出"旧 HTML 配新 chunk"的经典故障）；
- 缓存名带版本：`zs-assets-<VERSION>`，`activate` 时清掉不匹配的缓存；
- `sw.js` 位于 `web/public/`，**构建时原样复制**，所以它的 `VERSION` 常量是手写的 ——
  `smoke-test.ps1` 第 16 组会断言它与 `package.json` 的 `version` 一致，忘了改会直接报错；
- **只在安全上下文注册**（`main.tsx`：`PROD` + `window.isSecureContext`），所以局域网
  `http://192.168.x.x:端口` 用不到它（浏览器限制），而隧道/HTTPS 正好覆盖；
- 注册失败一律静默：SW 只是"第二次打开更快"，没有它功能完全正常。

**③ 传输层（服务端）**

- `/api/fs/download` 走 `res.sendFile`，已自带 `Accept-Ranges: bytes`、`ETag`(weak) 与
  `If-None-Match → 304`；第 16 组用 `Range: bytes=0-3` 与 `If-None-Match` 做了回归断言；
- 缩略图与静态产物都是**内容寻址**，可以放心长缓存（见 4.7）；
- 死资源已清理：`resources/tailwindcss.min.js`（269.8 KB，全站无引用）已删除，
  第 16 组同时断言"磁盘上没有它、也不会再以 JS 返回"。

### 4.10 插件体系（`server/src/plugins/` + `web/src/pages/settings/plugins-section.tsx`）

插件是本项目**唯一会加载第三方内容**的功能，所以四道关都在服务端：

1. **准入**：`pluginsEnabled` 默认关，关时安装接口 403；只有超管能碰 `/api/admin/plugins`；
2. **清单**：`plugins/manifest.js` 的 `normalizeManifest()` —— 未知顶层字段直接拒绝、
   `apiVersion` 只认 `SUPPORTED_API_VERSIONS`、`kind` 与 `permissions` 走白名单、
   `theme` 插件的 `permissions` 必须为空；
3. **包**：`plugins/store.js` 自己逐条解 zip（不用 `unzipper.Extract`），拒绝 `..` /
   绝对路径 / 符号链接，并限制 2 MB 包 / 10 MB 解压 / 300 条目；
4. **值**：主题令牌的名与值都校验（禁止 `;{}@<>\\`、`url(` 等），再由 `themeCss()`
   拼成 `html[data-theme-plugin="<id>"]` 作用域的 CSS —— **前端不拼接、只注入**。

数据：`data/plugins/<id>/`（包内容）+ `data/plugins.json`（启停、哈希、私有设置、当前主题）。
两处都加入了 `safety.js` 敏感条目；`plugins.json` 同时进了 `MANAGED_FILES`（可备份/回滚）
与 `integrity.js`（损坏会被隔离而不是让服务起不来）。

前端：

| 文件 | 作用 |
|:--|:--|
| `pages/settings/plugins-section.tsx` | 总开关、上传 zip、启停、应用主题、设置表单、卸载 |
| `components/plugins/schema-form.tsx` | 按 JSON Schema 渲染表单（**只导出组件**，避免破坏 HMR） |
| `lib/plugin-schema.ts` | Schema 类型与 `defaultsFromSchema()`（非组件，供上面两者共用） |
| `lib/plugin-theme.ts` | 拉 `/api/plugins/theme` 并注入 `<style>`；`main.tsx` 启动即调用，避免闪默认配色 |
| `lib/api.ts` | `fetchPlugins` / `patchPlugin` / `deletePlugin` / `setPluginTheme` / `installPluginPackage` |

**注意**：`installPluginPackage` **不能**用 `api.post` —— 那里会把 body 当 JSON 字符串化，
而插件包是二进制 zip，必须直接发 `ArrayBuffer`。

新增一种插件类型时，按顺序改：`manifest.js` 的 `PLUGIN_KINDS` 与对应分支 →
`store.js` 的运行时钩子 → `routes/plugins.js` → 前端 `PluginInfo["kind"]` 与展示逻辑 →
`smoke-test.ps1` 第 17 组补断言 → 文档三处（插件开发、安全设计、开发者指南）。

| `web/src/locales/en/<区域>.json` | 英文 |
| `web/src/locales/index.ts` | 用 `import.meta.glob` 在**构建期**把各区域文件合并成 `BUILTIN`（运行期零请求） |
| `web/src/components/language-select.tsx` | 语言选择器 + 「导出翻译模板」（值就是中文原文，给翻译者用） |
| `server/src/i18n.js` | 扫描 / 校验 `data/lang/*.json`，按 mtime 失效缓存 |
| `server/src/routes/i18n.js` | `GET /api/i18n`（清单 + 站点默认）、`GET /api/i18n/:code`（译文） |
| `web/public/robustness/index.js` 顶部 | 兼容模式页自带的 ES5 版 `T()` 与字典加载（它不参与构建，自己去取 `/resources/locales/*.json`） |
| `vite.config.ts` 的 `localeAssets()` | 构建时额外把合并后的字典输出成 `dist/resources/locales/<语言>.json`，专供兼容模式页 |
| `i18n-check.mjs` | 键完整性校验 + 剩余硬编码中文统计 |

键的形状：`<命名空间>.<区域>.<名字>`，**至少三段**（第三段用于排除 `meta.json` 这类文件名误报），
命名空间取 `ui`（界面）/ `api`（服务端提示）/ `meta`（文件元数据字段名）/ `compat`（兼容模式）。

#### 写代码时的三条纪律

1. 组件里 `const t = useT()`（语言一变就重渲染）；非组件模块用 `translate()`；
2. **不要在模块顶层把 `translate()` 的结果存成常量** —— 那会把首次加载时的语言锁死
   （`lib/format.ts` 的 `EXT_KIND` 存的是**键**，在 `fileKind()` 里才翻译，就是这个原因）；
3. 插值统一用 `{name}` 占位符：`t("ui.browser.deleted_count", { n })`。

#### 中文是唯一的兜底

任何键在当前语言里缺失都会依次回落到 `zh`、最后回落到键名本身。所以"英文漏翻一条"
只会看到中文，不会出现空白或 `ui.xxx.yyy` —— 这也是为什么 `zh` 必须完整。

#### 服务端的文案怎么本地化

服务端**不持有字典**，只在错误里多带两个字段（见 `server/src/http.js` 的 `httpError`）：

```js
throw httpError(400, `文件过大（${size}），在线编辑上限 ${limit}`, {
  errorKey: "api.fs.file_too_large_for_editor",
  errorParams: { size, limit },
})
```

- `error` 仍是拼好的**中文原文**（第三方脚本与 `curl` 的既有行为一字不变）；
- 前端在 `lib/api.ts` 里优先用 `errorKey` + `errorParams` 渲染，缺键就回落到 `error`；
- 所以新增服务端错误时：**中文照写，另外给一个键**；
- **日志不要本地化**：`info()` / `warn()` 的 event 与 msg 是运维数据，保持中文。
- 文件元数据的字段名（EXIF、签名等）走同一套：`server/src/fileinfo.js` 里每条返回
  `{ key: "meta.exif.make", label: "相机厂商", value }`，前端 `t(key)` 查不到就用 `label`。

#### 校验

```bash
node i18n-check.mjs            # 退出码 = 错误数
node i18n-check.mjs --list-cn  # 列出还没接入 i18n 的中文
node i18n-check.mjs --strict   # 把"剩余硬编码中文"也算作失败
```

它检查：用到的键在 zh / en 里是否都存在（**缺 zh 是错误**，缺 en 是警告）、en 里有而 zh 里没有的键（错误）、
**en 值里是否还残留中文**（错误，漏翻的强信号）、两个语言都没用到的死键（警告）、
同一个键在两份区域文件里冲突（错误）、`data/lang/` 里的非法键（警告），以及还剩多少处硬编码中文。
扫描范围包括 `web/src`、`web/public/robustness` 与 `server/src` + `server/index.js` ——
服务端的 `errorKey` / `meta.*` 字面量同样算"用到的键"。

> **"剩余硬编码中文"这个数字怎么读**：服务端文件里的中文**大多是设计使然**，不是漏改 ——
> `error` 字段必须保留中文原文（保证 curl 与第三方脚本的既有行为）、元数据的
> `label` / `value` 是缺译文时的兜底、`info()` / `warn()` 日志与启动横幅不做本地化。
> 所以它的用途是**看趋势**：前端（`web/src`、`web/public/robustness`）应当为 0，
> 服务端则逐个确认"新加的中文有没有同时给 `errorKey`"。

#### 要内置一门新语言

在 `web/src/locales/` 下新建语言目录（如 `ja/`）放入各区域文件，并在 `locales/index.ts` 的
`BUILTIN_META` 里登记代码与自称；`BUILTIN` 会自动把它合并进来。
只想**临时加一门**（不改代码）：往服务端 `data/lang/<代码>.json` 丢文件即可，
格式与限制见 [配置参考 · 界面语言](配置参考.md#界面语言datalang)。

## 5. 本地开发

### 工作目录（重要）

`server/src/env.js` 用 **`process.cwd()`** 推导项目根目录（`ROOT_DIR`），`.env`、`data/`、
`web/dist` 全都挂在它下面。也就是说：**工作目录决定用哪一套配置和数据。**

```js
const ROOT_DIR = isPkg ? path.dirname(process.execPath) : process.cwd()
```

历史上有过两种跑法，各读各的 `.env` 与 `data/`，非常容易踩坑：

| 命令 | 旧行为的工作目录 | 读到的配置 |
|:------------------- |:------------ |:---------------------- |
| `pnpm start` | 仓库根 | 根 `.env` + 根 `data/` |
| `pnpm dev:server` | `server/`（旧脚本是 `pnpm -C server dev`） | `server/.env` + `server/data/` |

现在 `dev:server` 已改成 `node --watch server/index.js`，**与 `start` 一样以仓库根为工作目录**，
两套配置的歧义已消除。请遵守以下约定：

- 一律在**仓库根**执行 `pnpm start` / `pnpm dev:server`，不要在 `server/` 里直接 `node index.js`
  （那会把 `server/` 当成项目根，凭空生成 `server/.env` 与 `server/data/`，看起来像"数据丢了"）；
- `server/` 下**不应出现** `.env` 或 `data/`。若出现了，说明有命令用错了工作目录，删掉即可
  （`data/` 与 `.env` 都是可再生的）；
- 打包成 exe 后规则不同：`ROOT_DIR` 取 `ZeroShadow.exe` 所在目录，`.env` 与 `data/` 就在 exe 旁边。

### 常用命令

```bash
pnpm setup          # 安装 server 与 web 的依赖
pnpm dev:server     # 后端：node --watch server/index.js（保存自动重启），端口取根 .env 的 PORT
pnpm dev:web        # 前端：Vite 开发服务器，默认 5173

pnpm typecheck      # web: tsc -p tsconfig.app.json --noEmit && tsc -p tsconfig.node.json --noEmit
pnpm lint           # web: eslint .
pnpm -C web format  # web: prettier --write "**/*.{ts,tsx}"
```

> **`typecheck` 曾经是个空操作**：旧脚本跑的是 `tsc --noEmit`，而 `web/tsconfig.json` 是
> solution-style 的（只有 `references`、`files: []`），等于什么都没检查。
> 现在改成分别检查 `tsconfig.app.json`（前端源码）与 `tsconfig.node.json`（Vite 配置等），
> 真正会把类型错误暴露出来——**提交前请确保它通过**。

开发时浏览器打开 **http://localhost:5173**（Vite 会把 `/api` 代理到后端）。

代理目标端口是 `web/vite.config.ts` 里的 `backendPort()` **从根 `.env` 的 `PORT` 读出来的**，
所以不必再手工同步——改了 `.env` 的 `PORT`，代理会跟着变。

### 构建

```bash
pnpm build                  # web: tsc -b && vite build → web/dist
cd server && pnpm bundle    # 后端打包成 dist/server-bundle.cjs（esbuild，供 pkg 使用）
```

`server` 的 `bundle` 脚本把 ESM 打成 CJS，因为 pkg 对 ESM 支持不佳；
`--external:../web/*`、`--external:../data/*` 让这些运行时路径不被内联进去。

> 注意：`pnpm build` 与 `pnpm -C web build` 等价，都必须在仓库根执行；
> `web/dist` 不存在时后端会对 `/` 返回 503 并提示先构建。

### smoke-test.ps1（冒烟测试）

```powershell
# 先起服务，然后另开一个终端（端口与超管账号自动从 .env 读取）
powershell -NoProfile -ExecutionPolicy Bypass -File smoke-test.ps1

# 指定别的实例
powershell -NoProfile -ExecutionPolicy Bypass -File smoke-test.ps1 `

```

参数：`-BaseUrl`（默认 `http://127.0.0.1:<.env 的 PORT>`）、`-Root`（默认脚本所在目录）、
`-User` / `-Password`（默认读 `.env` 的 `SUPER_ADMIN_USER` / `SUPER_ADMIN_PASSWORD`）、
`-KeepScratch`（保留测试临时目录）。

- 输出形如 `PASS csrf-blocked` / `FAIL xxx` 的逐项结果，**退出码 = 失败项数量**；
  连不上服务退 `1`，超管登录失败退 `2`；
- **20 组共 137 项断言**（脚本里 `Section "0."` ～ `Section "19."` 共 20 段）：
  连通性、CSRF 拦截与认证、目录创建与路径穿越拦截、
  上传（手工拼 multipart）、访客隐藏文件夹与访客权限边界（404 / 401 / 下载 / me）、
  成员创建与登录（含 `uploadLimitMB` 与后台配置一致性、成员访问 admin 接口 403）、
  复制 / 重命名 / 移动 / 详情 / 删除、禁用成员后降级为访客、ZIP 打包 / 搜索 / 日志 / 状态 / 隧道、
  SPA 首页与静态资源、兼容模式页面（含首页的静态兜底入口）、回收站（删除 → 隐藏 → 列表 → 还原 → 彻底删除）、
  并发编辑保护（`baseVersion` 与 409）、审计日志导出（JSONL / CSV 与 BOM）、WebDAV（开关 / 挂载 / Depth / Range / 304 / 路径切换）、图片缩略图、弱网相关（`sw.js` 版本与 MIME、死资源、Range/304）、插件（安装 / 主题 / JSON Schema 设置 / fileType 沙箱入口 / server 子进程超时与恢复）。

设计要点（改这个脚本时请保留这些性质）：

| 性质 | 为什么 |
|:------------------- |:------------------------------------------------------------------------- |
| 端口与凭据从 `.env` 读，不写死 | 旧脚本写死 `http://localhost:5170` + `admin`，与根 `.env` 的 `Wangyq` 对不上，注定失败 |
| 用 `127.0.0.1` 而不是 `localhost` | 服务端监听 `0.0.0.0`（仅 IPv4），`localhost` 在部分系统上先解析到 `::1`，会连接被拒 |
| 全部工作在自己的随机临时目录里 | 旧脚本固定创建「公开资料」「内部资料」，与真实数据撞名，且重跑就乱 |
| 成员按用户名查找 id，**不取 `members[0]`** | 旧脚本取 `members[0]`，在有多个成员的真实环境里会禁用错人 |
| 错误凭据断言用不存在的用户名 | 登录失败计数按用户名累计，用超管的账号会让每跑一次就给他记一笔，可能把他锁在门外 |
| 跑完自动还原现场 | 删除临时目录与临时成员，并在 `config.json` 是本轮才生成且隐藏列表已清空时删掉它 |
| 断言与「后台配置」比对，而不是写死数值 | 例如 `uploadLimitMB` 与 `/api/admin/config` 的值比对，管理员调过上限也不会误报 |
| 前端未构建时跳过 SPA 断言 | `web/dist` 不存在时后端对 `/` 返回 503，dev 模式下这是正常的，不该算失败 |

> **维护提醒：这个文件必须带 UTF-8 BOM。** 它含中文字面量（目录名、文件名），而
> Windows PowerShell 5.1 在没有 BOM 时会用 ANSI 代码页解码 `.ps1`，中文会变成乱码，
> 甚至整个文件无法解析（`Unexpected token '}'`）。
> 用 `edit`/`write` 类工具改完之后，请确认前 3 字节仍是 `EF BB BF`；
> 另外 `package-release.ps1`、`build-release.ps1`、`security-test.ps1` 刻意保持**纯 ASCII**，
> 因此不需要 BOM，也不应加入非 ASCII 字符。


- **不需要起服务**，也不需要浏览器：脚本用 `server/node_modules/archiver` 现场生成最小的
  `.docx` / `.xlsx` / `.pptx`，再 `import` `web/src/lib/office/` 的解析函数断言结构；
- **40 项断言**，逐项打印 `✓`，全部通过时退出码 `0`；
- 覆盖：docx 的段落 / 粗体字号 / 对齐 / 列表 / 合并表 / 图片 / 分页符；xlsx 的多表顺序、
  共享字符串多 run、inlineStr、合并格、日期、百分比、公式缓存值、列宽；pptx 的页面顺序、
  `xfrm` 百分比定位、文本 run、填充色、图片、组合递归、无 `xfrm` 占位符兜底；
  以及失败路径（随机字节 / 空文件 / 加密 OLE / 格式不符）给出可识别的错误码；
- 解析器**不依赖 `DOMParser`**（自带极简 XML 解析器），所以浏览器与 Node 共用同一份代码；
  ZIP 解压走标准 `DecompressionStream("deflate-raw")`，Node 18+ 与主流浏览器都支持。

改 `web/src/lib/office/**` 或 `office-preview.tsx` 后请跑一遍；它不覆盖 React 渲染层，
所以界面改动仍需人工点一次预览页。

## 7. 发布打包

### 三层结构

```
Auto-building.bat          薄封装，只在 Windows 上双击用（转发参数给下一层）
.github/workflows/*.yml    CI：五个平台并行跑下一层
        ↓
build-release.ps1          构建编排：依赖 → 前端 → esbuild 打包 → 逐平台 pkg → 暂存
        ↓
package-release.ps1        单个平台的收尾：暂存文档 → 清理凭据 → 密钥门禁 → 出 zip
```

构建逻辑只在 `build-release.ps1` 里有一份，本地与 CI 都调它，**两边的产物不会跑偏**。

### 平台矩阵

| 平台标签 | pkg 目标 | 二进制 |
|:--------------- |:------------------------- |:------------------ |
| `windows-x64` | `node18-win-x64` | `ZeroShadow.exe` |
| `windows-arm64` | `node18-win-arm64` | `ZeroShadow.exe` |
| `linux-x64` | `node18-linux-x64` | `ZeroShadow` |
| `linux-arm64` | `node18-linux-arm64` | `ZeroShadow` |
| `linux-armv7` | `node18-linuxstatic-armv7` | `ZeroShadow` |

产物落在仓库根，命名为 `ZeroShadow-<版本>-<平台>.zip`，版本取自根 `package.json`。
逐平台的暂存目录是 `build/<平台>/`（已 gitignore）。

> **`windows-x32` 无法构建**，而且这不是配置问题：`pkg-fetch` **从未**发布过 win-x86 的
> 基础运行时，任何 Node 版本都没有。已从三个独立来源核对：`pkg-fetch` 3.4.2 的
> `lib-es5/expected.js`（`EXPECTED_HASHES`）里没有任何 `*-win-x86` 键；`pkg-fetch` v3.4
> release 的 178 个 asset 里没有；`@yao-pkg/pkg-fetch` v3.5 release 的 997 个 asset 里也没有。
> 向 pkg 请求该目标会得到
> `Error! 404: Not Found / Not found in remote cache: {"tag":"v3.4","name":"node-v18.5.0-win-x86"}`。
> 真要出 32 位 Windows 包就得换打包器（如 nexe），产出的二进制结构不同，需要单独一条路径。
> `build-release.ps1` 里有一张 `$UNSUPPORTED_TARGETS` 表，收到该目标时会打印原因并退出 1，
> 便于后人不必再踩一遍。
>
> **`linux-armv7` 实际用的是 `linuxstatic-armv7`**：pkg-fetch 只提供静态链接版 armv7，
> 没有普通的 `linux-armv7`。静态链接对分发更有利——产物不依赖目标机 glibc 版本。

> **"node18" 是打进包里的运行时，不是构建机上的 Node。** `pkg` 把 node18 内嵌进产物，
> 所以产物与构建机 Node 版本无关；但构建机需要较新的 Node，因为 Vite 8 声明
> `engines: ^20.19.0 || >=22.12.0`，**前端在 Node 18 上构建不了**。

```powershell
# 全部五个平台（windows-x64 / windows-arm64 / linux-x64 / linux-arm64 / linux-armv7）
pwsh -NoProfile -File build-release.ps1

# 只构建指定平台（避免每次重新下载 pkg 运行时）
pwsh -NoProfile -File build-release.ps1 -Targets windows-x64,linux-x64

# CI 用法：依赖已装好、锁文件固定
pwsh -NoProfile -File build-release.ps1 -FrozenLockfile

# 只构建 + 暂存，不出包
pwsh -NoProfile -File build-release.ps1 -NoZip
```

> 传 `windows-x32` 会**按设计直接退出 1**（打印原因，不会去下载运行时）——
> 它永远构建不出来，原因见上。
> `Auto-building.bat` 的用法文本里还留着一句历史遗留的 `all six platforms`，
> 但它下方列出的可用平台只有五个（`Platforms: windows-x64 windows-arm64 linux-x64 linux-arm64 linux-armv7`）。

退出码：`0` 全部成功；`1` 致命错误（工具链或某个构建步骤）；`2` 至少一个平台失败
（其余平台的结果仍然保留，`fail-fast` 是关的）。

### 文档暂存

`package-release.ps1` 默认会把 `LICENSE`、`README.md`、`docs/`（含 `docs/img` 截图）
复制进发布目录，所以每个平台包都自带许可证书与全部用户手册。这一步是集中在这里做的，
**本地构建与 CI 不需要各自再写一遍**，也就不会出现"CI 里有手册、本地包没有"的偏差。
用 `-IncludeDocs:$false` 可以关掉。

### 密钥门禁（`package-release.ps1`）

```powershell
# 默认行为（自动按 版本+平台 命名归档）
powershell -NoProfile -ExecutionPolicy Bypass -File package-release.ps1 -Platform windows-x64

# 只清理 + 扫描 + 暂存文档，不出包
... -File package-release.ps1 -NoZip

# 只报告会发生什么，不实际改动
... -File package-release.ps1 -DryRun

# 自定义目录 / 输出
... -File package-release.ps1 -ReleaseDir ZeroShadow-Release -ZipPath ZeroShadow-Release.zip
```

| 阶段 | 行为 |
|:-------- |:--------------------------------------------------------------------------------------------------- |
| 暂存文档 | 复制 `LICENSE` / `README.md` / `docs/` 进发布目录；源文件缺失时告警但不中断 |
| 清理 | 删除 `.env`、`data/.jwt-secret`、`data/users.json`、`data/config.json`、`data/logs/*.log`（都是可再生的） |
| 拦截 | 若存在 `data/files/*`、`data/tmp/*`、任何 `.zip`，**拒绝出包**（退出码 2），并列出具体文件 |
| 拒绝根目录 | 目标目录等于项目根目录时直接退出（否则会把 `.env` 与 `data/` 打进包） |
| 拒绝自嵌套 | 归档路径位于发布目录内部时退出（否则新包会被自己的 `*.zip` 规则拦下） |
| 打包 | 手工逐条写 zip 条目，路径统一用 `/`（`CreateFromDirectory` 在 Windows 上会写出反斜杠，导致 macOS/Linux 解压成一堆乱名文件）；1980 年之前的时间戳会被跳过（zip 格式无法表示） |
| 可执行位 | `ZeroShadow`（无扩展名，即 Linux/macOS 产物）在 zip 的 external attributes 里写入 `0100755`，解压后即可运行；其余文件写 `0100644` |
| 复核 | 打开生成的压缩包再扫一遍：不得含 `.env`、`jwt-secret`、`users.json`、`config.json`、`.log` 或反斜杠条目；有违规则**丢弃压缩包**，保留原有包不动 |
| 报告 | 列出归档里的二进制名、手册数量；二进制缺失或手册为 0 时告警 |
| 退出码 | `0` 成功；`1` 意外失败；`2` 门禁拦截 |

> 脚本注释里明确写了：**永远不要打包项目根目录** —— 那里有 `.env` 与 `data/`。
>
> 还要注意：**不要打包一个已经运行过的发布目录**。它内部已生成 `.env` 与
> `data/.jwt-secret`，门禁虽会把它们清掉，但只要漏一个就是全量凭据泄漏——
> 本仓库历史上就有一个 `ZeroShadow-Release.zip` 因此带着 `.env` 与 `.jwt-secret` 出了门。
> 让脚本从干净目录重新组装，别手工 zip。

## 8. 约定与注意事项

| 约定 | 说明 |
|:----------------------- |:--------------------------------------- |
| 后端全部用 `node:` 前缀导入内置模块 | 例如 `import fs from "node:fs"` |
| 前端只用 `@/` 别名导入 | 对应 `web/src` |
| UI 文案 | 全部中文，不引外部文案系统 |
| 图标与字体 | 一律走 `public/resources/`，**禁止 CDN**（内网离线可用性的前提） |
| 阴影 | 用 `edge-highlight` / `surface-inset` 这类内阴影 + 顶部高光工具类，避免生硬投影 |
| 颜色 | 通过 `index.css` 的 `@theme` 令牌引用，不硬编码色值 |
| 权限判定 | 只在服务端做；前端的隐藏/置灰只是体验优化 |
| 路径处理 | 客户端传来的路径必须过 `safety.js`，不要自己拼字符串 |
| 日志 | 业务动作记 `info("事件名", { msg, ...actor(req) })`，密码与令牌**绝不入库** |
| 错误 | 业务错误用 `httpError(status, msg)` 抛，交给统一错误处理 |

### 改版本号的完整清单

版本号是**写死在代码与文档里**的，不从 `package.json` 读（浏览器里拿不到），
所以每次发版要逐项同步。目前一共 10 处：

| # | 位置 | 说明 |
|:-- |:------------------ |:--------------------------------------- |
| 1 | 根 `package.json` 的 `version` | **发布版本的唯一来源**：`build-release.ps1` 的归档命名取自它 |
| 2 | `server/index.js` 的 `/api/meta` | 接口返回的版本号 |
| 3 | `web/src/version.ts` 的 `VERSION` | 前端唯一的版本号来源，关于页与侧边栏都从这里读 |
| 4 | `server/package.json` 的 `version` | 与根保持一致，避免三个包各说各话 |
| 5 | `web/package.json` 的 `version` | 同上 |
| 6 | `README.md` 的「发布包内容」示例 | 形如 `ZeroShadow-<版本>-windows-x64.zip` |
| 7 | `docs/使用手册.md` 的界面结构示意图 | 侧边栏品牌区显示 `v<版本号>` |
| 8 | `docs/API参考.md` 里 `/api/meta` 的响应示例 | 与第 2 项一致 |
| 9 | `docs/mdx/content/docs/api/reference.mdx` 里 `/api/meta` 的响应示例 | 文档站那一份，与第 8 项保持一致 |
| 10 | `README.md`「更新日志」一节的 `**v<版本>（当前版本）**` | 新版本写在最上面，旧版本去掉"（当前版本）" |

另外几处**不是版本号但常一起改**：

- `docs/README.md` 开头的「本文档对应仓库当前 `main` 分支（`package.json` 版本 `x.y.z`）」；
- `CHANGELOG.md`（以及内容应保持一致的 `docs/changelog.md`）把顶部的 `## [未发布]`
  改成 `## [<版本>] - <日期>`，并在文件末尾补上 `[<版本>]: …/releases/tag/v<版本>` 链接；
- `package-release.ps1` 用法注释里的示例归档名（纯注释，改了更清楚，不改也不影响功能）。

改完用这两条命令核对：第一条应当命中上面那 10 处，第二条应当**只剩历史标注**
（更新日志里的旧版本号、文档里的「（1.1.2 起）」、`SECURITY-AUDIT.md` 的审计对象版本）：

```bash
grep -rn "1\.2\.0" --include="*.json" --include="*.js" --include="*.ts" --include="*.md" . | grep -v node_modules
grep -rn "1\.1\.2" --include="*.json" --include="*.js" --include="*.ts" --include="*.md" . | grep -v node_modules
```

> **别动 `server/dist/server-bundle.cjs`**：它是 esbuild 的产物、由 `build-release.ps1`
> 重新生成，手工改没有意义。发布流程会先 `pnpm -C server bundle` 再拿产物去 pkg。

## 10. 提交前自查

1. `pnpm typecheck` 与 `pnpm lint` 通过；
2. `pnpm build` 能成功产出 `web/dist`；
3. 起一个独立实例跑 `security-test.ps1`，**退出码为 0**；
4. 动了 `server/src/encoding.js` 时，再跑一次 `node encoding-test.mjs`（**退出码为 0**）；
5. 动了 `web/src/lib/markdown*.ts`（尤其 `SAFE_HTML_TAGS`）时，跑这两个单测（**退出码为 0**）：
   `node --experimental-strip-types scripts/markdown-url-test.mjs`、
   `node --experimental-strip-types scripts/markdown-html-test.mjs`；
6. 需要的话跑 `smoke-test.ps1`（**退出码为 0**，且跑完后 `git status` 与 `data/` 应无残留）；
7. 改了打包相关脚本时，跑一遍 `build-release.ps1 -Targets windows-x64`，
   确认归档命名、内容与门禁都符合预期；
8. 涉及安全相关改动时，同步更新 [安全设计](安全设计.md) 与对应的测试断言
   （放宽 `SHELL_CSP` 属于安全改动：`security-test.ps1` 第 1 组已锁死"图片可放宽，脚本与请求不行"）；
9. **确认没有把 `.env`、`data/` 提交进仓库**（`.gitignore` 已经忽略，别用 `-f` 强行加）；
10. 若用编辑器/工具改过 `smoke-test.ps1`，确认它仍然带 UTF-8 BOM（见 [6](#smoke-testps1冒烟测试) 的维护提醒）。

> **关于已被跟踪但又被 gitignore 的文件**：`.gitignore` 只对**未被跟踪**的文件生效。
> 本仓库有四个历史遗留文件处于「已跟踪但符合忽略规则」的状态：
> `server/ZeroShadow.exe`（约 40 MB）、`server/dist/server-bundle.cjs`、`AIGC.md`、`main.md`。
> 想让忽略规则真正生效，需要 `git rm --cached <文件>` 先把它们移出索引（历史体积不会因此变小，
> 要真正瘦身得用 `git filter-repo` 重写历史）。用 `git ls-files -i -c --exclude-standard`
> 可以随时列出这类文件。
