## 1. 技术底座

| 部分 | 技术 | 关键约定 |
|:---------- |:---------------------------------------------------- |:--------------------------------------- |
| 后端 | Node.js（**ESM**，`server/package.json` 里 `"type": "module"`）+ Express 4 | 全部使用 `import` / `export`，无构建步骤即可运行 |
| 前端 | React 19 + TypeScript + Vite 8 + Tailwind CSS v4 | 路径别名 `@` → `web/src`；组件用 shadcn CLI 生成 |
| 图标 | 本地 `lucide.min.js` + `<i data-lucide>` 占位，由 `createIcons()` 渲染 | 不用 CDN，内网离线可用 |
| 动画 | 本地 `gsap.min.js` + CSS 过渡 | 列表入场与页面入场动画 |
| 打包 | Vite（前端）/ esbuild + pkg（后端） | esbuild 先把 ESM 打成 CJS，再由 pkg 生成 exe |

根 `package.json` **没有依赖**，只是一个脚本入口；依赖分别装在 `server/` 与 `web/` 两个子项目里，
各自有独立锁文件（`lockfileVersion: '9.0'`）。

## 3. 后端

### 3.1 请求处理链（`server/index.js` 的中间件顺序）

```
关闭 x-powered-by
  → （可选）app.set("trust proxy", env.trustProxy)
  → GET /ping                     健康检查，纯文本 pong
  → 请求日志中间件                打印 [REQ] 方法 路径 host ip ua（静默模式下跳过）
  → 安全响应头中间件              nosniff / SAMEORIGIN / no-referrer / Permissions-Policy
  → cookieParser
  → express.json({ limit: "1mb" })
  → socket.setNoDelay(true)       缓解隧道代理场景的缓冲问题
  → attachAuth                    解析 Cookie 得到 req.auth = { role, username, userId }
  → /api 上的 csrfGuard           非 GET/HEAD/OPTIONS 校验自定义头与来源
  → GET /api/meta
  → /api/auth  /api/fs  /api/admin
  → /api 兜底 404 JSON
  → express.static(WEB_DIST) + 非 /api 的 SPA fallback（带应用外壳 CSP）
  → 统一错误处理（5xx 记日志，只回"服务器内部错误"）
```

启动时会：清空 `data/tmp/` → 建目录 → 读配置 → 若隧道已启用则拉起隧道；
退出信号（`SIGINT` / `SIGTERM`）会先停隧道再关服务，兜底 3 秒强制退出。

### 3.2 权限是怎么判的

两级中间件（`server/src/auth.js`）：

```js
requireRole("superadmin")            // 按角色
requirePerm("compressZip")           // 按 effectivePerms(role) 里的权限点
```

`effectivePerms(role)`（`server/src/config.js`）是**唯一的权限真相来源**：
把 `config.json` 里的 `memberPerms` / `guestPerms` 与角色叠加，算出最终布尔表
（例如成员的写类权限都要 `fileWrite` 为真）。前端拿到的 `perms` 就是它的输出。

**新增权限点的完整步骤**：

1. `server/src/config.js`：在 `DEFAULTS.memberPerms`（或 `guestPerms`）里加默认值；
2. 同文件 `effectivePerms()`：给对应角色返回这个键；
3. 目标路由：加上 `requirePerm("你的键")`；
4. `web/src/lib/types.ts`：在 `Perms` 接口里加字段；
5. `web/src/state/auth.tsx`：在 `GUEST` 兜底常量里补一个默认值（未登录时前端要用）；
6. `web/src/pages/settings/index.tsx`：用 `permItem(...)` 在「权限」页加一个开关。

### 3.3 数据存放

| 数据 | 位置 | 生命周期 |
|:-------------- |:------------------------- |:--------------------------------------- |
| 服务配置 | `data/config.json` | 启动时读入内存，后台修改后原子写回 |
| 成员账号 | `data/users.json` | 同上；密码为 bcrypt 哈希 |
| 会话密钥 | `data/.jwt-secret` | 首次生成后复用；删除即让全部会话失效 |
| 长任务进度 | **内存** `Map` | 10 分钟 TTL，每分钟扫描清理 |
| 登录失败计数 | **内存** `Map` | 重启清零 |
| 限流计数 | **内存** `Map` | 重启清零 |
| 日志 | `data/logs/zs-*.log` | 按天一个 JSONL 文件 |

写入用 `store.js` 的 `withLock` + `writeJsonAtomic`（写临时文件再重命名），
避免并发覆盖和半个文件。

### 3.4 长任务模型

`compress` / `extract` / `download-url` 三个接口都是**先返回 `jobId` 再后台执行**：

```
POST /api/fs/compress        → { jobId }
   ↓ 前端每 400ms 轮询
GET /api/fs/compress/status?job=<id>  → { state, percent, processed, total, processedBytes, error }
```

- 任务对象里有 `createdBy`，默认只有创建者与超管能查询（`jobStatusOwnerOnly`）；
- 状态机：`running` → `done` / `error`；任务被清理后查询返回 `state: "gone"`；
- 失败时（含解压中途超限）会清理临时产物——解压还会**整个删掉半成品目录**。

### 3.5 想加一个接口

```js
// server/src/routes/fs.js
router.post("/my-op", requirePerm("editFiles"), rateLimit, async (req, res, next) => {
  try {
    const { abs, rel } = resolveSafe(req.body?.path)   // 一定走 safety.js
    blockSoft(rel)                                     // 只读映射目录要拦住
    // ...业务
    info("my_op", { msg: rel, ...actor(req) })         // 记日志
    res.json({ ok: true })
  } catch (err) { next(err) }
})
```

要点：**路径一律用 `resolveSafe` / `resolveAny` 解析**（自带穿越防护），
写操作要先 `blockSoft`，需要限流就挂 `rateLimit`，错误统一交给 `next(err)`（`httpError(status, msg)` 造错误）。
前端在 `web/src/lib/api.ts` 里加一个薄封装即可。

## 5. 本地开发

```bash
pnpm setup          # 安装 server 与 web 的依赖
pnpm dev:server     # 后端：node --watch index.js（保存自动重启），端口取 .env 的 PORT
pnpm dev:web        # 前端：Vite 开发服务器，默认 5173

pnpm typecheck      # web: tsc --noEmit
pnpm lint           # web: eslint .
pnpm -C web format  # web: prettier --write "**/*.{ts,tsx}"
```

开发时浏览器打开 **http://localhost:5173**（Vite 会把 `/api` 代理到 `http://localhost:12345`）。

修改后端端口时记得同步 `web/vite.config.ts` 的 `server.proxy.target`。

### 构建

```bash
pnpm build                  # web: tsc -b && vite build → web/dist
cd server && pnpm bundle    # 后端打包成 dist/server-bundle.cjs（esbuild，供 pkg 使用）
```

`server` 的 `bundle` 脚本把 ESM 打成 CJS，因为 pkg 对 ESM 支持不佳；
`--external:../web/*`、`--external:../data/*` 让这些运行时路径不被内联进去。

> 注意：这是**针对示例数据**写的脚本，例如它会创建「公开资料」「内部资料」两个目录并断言搜索结果包含

> 它会在你的网盘里**真实创建 / 删除文件**，建议对测试实例运行。

### security-test.ps1（安全回归测试）

```powershell
# 终端 1：起一个独立实例
$env:HOST='127.0.0.1'; $env:PORT='5179'; node server/index.js

# 终端 2
powershell -NoProfile -ExecutionPolicy Bypass -File security-test.ps1 -BaseUrl http://127.0.0.1:5179
```

参数：

| 参数 | 默认 | 说明 |
|:---------------------- |:----------------------------------- |:--------------------------------------- |
| `-BaseUrl` | `http://127.0.0.1:5179` | 被测服务地址 |
| `-Root` | 脚本所在目录 | 项目根目录，用于读 `.env`、定位文件目录、检查源码与发布包 |
| `-User` / `-Password` | 从 `.env` 读，回退 `admin` | 超管凭据 |
| `-PositiveProbeUrl` | 空 | 正向下载验证的目标地址；**需要服务端用 `DOWNLOAD_URL_ALLOW_HOSTS` 放开该主机**，留空则跳过 |
| `-LoopbackAllowlisted` | 关 | 当服务端白名单里放开了 `127.0.0.1` 时打开（`127.1` 与十进制 `2130706433` 会被 URL 解析器归一化成 `127.0.0.1`，属于合法放行） |
| `-TrustProxyMode` | 关 | 被测服务开了 `TRUST_PROXY` 时打开，此时断言 `X-Forwarded-For` **应当**生效 |
| `-TestLockout` | 关 | 登录锁定作用域测试，会消耗约 12 次单 IP 失败额度，**建议对全新实例运行** |
| `-SoftDirName` | 空 | 被测服务配置的只读映射目录名，用于验证其内容不能被复制进网盘 |
| `-TestJobOwnership` | 关 | 作业归属测试，会临时创建一个成员账号并在结束时删除 |
| `-KeepScratch` | 关 | 保留测试用的临时目录（默认跑完删掉） |

- **退出码 = 失败项数量**，0 表示全部通过；连不上服务时退出码 1，超管登录失败时退出码 2；
- 安全声明：只与本机服务通信，SSRF 探测都指向服务自身；产物集中在文件库里一个临时目录，
  结束后清理（`-KeepScratch` 可保留）。
- 它会**临时修改**少量设置——第 4 组会改访客权限开关、第 11 组会改解压总量上限——并在各自段落结束时
  **还原成你原来的值**；`-TestJobOwnership` 会临时创建一个成员账号并在结束时删除。除此之外不动用户与发布包。

16 组断言：

| 组 | 主题 |
|:--- |:----------------------------------------------------------- |
| 1 | 传输层加固（CSRF、响应头、CSP、Permissions-Policy、跨站来源拦截） |
| 2 | 认证与授权（错误密码、超管登录、匿名访问 admin 接口） |
| 3 | 路径穿越（4 种写法） |
| 4 | 访客授权必须跟随管理端开关（开 → 允许，关 → 全部拒绝，再恢复） |
| 5 | SSRF 过滤（12 种写法）+ 可选的 5b 正向下载 |
| 6 | HTML / SVG 预览不得在应用源下执行（响应头 + 前端源码里的 `sandbox` 实际取值） |
| 7 | 既有防护不退化（zip-slip、合法条目仍能解出） |
| 8 | 凭据与发布卫生（弱口令检查、发布包不得含 `.env`、路径分隔符必须可移植、门禁脚本能干净跑完） |
| 9 | 客户端 IP 解析（按 `TRUST_PROXY` 断言 `X-Forwarded-For` 是否生效） |
| 10 | 登录锁定作用域（可选） |
| 11 | 解压保护（声明超限直接拒绝；中途失败不留半成品） |
| 12 | 重型接口限流 |
| 13 | 只读映射目录（内容不可复制进网盘） |
| 14 | 作业状态归属 |
| 15 | 访客可见性随重命名同步 |
| 16 | 路径解析加固 |

## 7. 发布打包

### Windows 一键（`Auto-building.bat`）

顺序：检查 Node 版本 → 缺 `pkg` 就 `npm i -g pkg` → `pnpm install`（server、web）→
`pnpm build`（web）→ 删除 `data/config.json` → `pnpm bundle`（server）→
`pkg dist\server-bundle.cjs --target node18-win-x64 --output ZeroShadow.exe` →
组装 `ZeroShadow-Release/`（exe + `web/dist` + 空 `data/` + `.env.example`）→
调用 `package-release.ps1` 执行清理与门禁并产出 zip。

### 密钥门禁（`package-release.ps1`）

```powershell
# 默认行为
powershell -NoProfile -ExecutionPolicy Bypass -File package-release.ps1

# 只清理 + 扫描，不出包
... -File package-release.ps1 -NoZip

# 只报告会删什么，不实际改动
... -File package-release.ps1 -DryRun

# 自定义目录 / 输出
... -File package-release.ps1 -ReleaseDir ZeroShadow-Release -ZipPath ZeroShadow-Release.zip
```

| 阶段 | 行为 |
|:-------- |:--------------------------------------------------------------------------------------------------- |
| 清理 | 删除 `.env`、`data/.jwt-secret`、`data/users.json`、`data/config.json`、`data/logs/*.log`（都是可再生的） |
| 拦截 | 若存在 `data/files/*`、`data/tmp/*`、任何 `.zip`，**拒绝出包**（退出码 2），并列出具体文件 |
| 拒绝根目录 | 目标目录等于项目根目录时直接退出（否则会把 `.env` 与 `data/` 打进包） |
| 打包 | 手工逐条写 zip 条目，路径统一用 `/`（`CreateFromDirectory` 在 Windows 上会写出反斜杠，导致 macOS/Linux 解压成一堆乱名文件）；1980 年之前的时间戳会被跳过（zip 格式无法表示） |
| 复核 | 打开生成的压缩包再扫一遍：不得含 `.env`、`jwt-secret`、`users.json`、`config.json`、`.log` 或反斜杠条目；有违规则**丢弃压缩包**，保留原有包不动 |
| 退出码 | `0` 成功；`1` 意外失败；`2` 门禁拦截 |

> 脚本注释里明确写了：**永远不要打包项目根目录** —— 那里有 `.env` 与 `data/`。

## 8. 约定与注意事项

| 约定 | 说明 |
|:----------------------- |:--------------------------------------- |
| 后端全部用 `node:` 前缀导入内置模块 | 例如 `import fs from "node:fs"` |
| 前端只用 `@/` 别名导入 | 对应 `web/src` |
| UI 文案 | 全部中文，不引外部文案系统 |
| 图标与字体 | 一律走 `public/resources/`，**禁止 CDN**（内网离线可用性的前提） |
| 阴影 | 用 `edge-highlight` / `surface-inset` 这类内阴影 + 顶部高光工具类，避免生硬投影 |
| 颜色 | 通过 `index.css` 的 `@theme` 令牌引用，不硬编码色值 |
| 权限判定 | 只在服务端做；前端的隐藏/置灰只是体验优化 |
| 路径处理 | 客户端传来的路径必须过 `safety.js`，不要自己拼字符串 |
| 日志 | 业务动作记 `info("事件名", { msg, ...actor(req) })`，密码与令牌**绝不入库** |
| 错误 | 业务错误用 `httpError(status, msg)` 抛，交给统一错误处理 |

### 已知的小不一致

以下都不影响功能，改文档或改代码时注意别被绕进去：

- `package.json` 的版本是 `1.1.0`，而「关于」页显示的版本是 `1.0.0`，
  `GET /api/meta` 返回的 `version` 也是硬编码的 `1.0.0`（在 `server/index.js` 里）；
- `components/layout/app-shell.tsx` 里导出的 `useShellSearch` 与 `ShellContext`
  目前没有页面在用（文件浏览器的搜索框在自己的工具栏里）。

## 9. 常见改动指引

| 想做的事 | 改哪里 |
|:--------------------------- |:----------------------------------------------------------- |
| 加一个权限开关 | 见 [3.2](#32-权限是怎么判的) 的六步 |
