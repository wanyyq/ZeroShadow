面向**日常使用者**（超管、团队成员、访客都适用）。这一篇讲的是“界面上每个按钮干什么、点了会发生什么”。

权限点是否对你开放，取决于你的角色与超管的设置，详见 [权限与角色](/docs/zeroshadow/guide/permissions)。

## 界面结构

```text
┌──────────┬──────────────────────────────────────────────────────────┐
│ ZeroShadow│ 顶栏：手机端菜单 / 搜索框 · 小组切换 · 主题 · 登录状态    │
│ v1.1.0    ├──────────────────────────────────────────────────────────┤
│ 文件      │                                                          │
│ 团队      │   主内容区：文件浏览器 / 团队待办 / 设置 / 工具 / 开源信息│
│ 工具      │                                                          │
│ 设置      │                                                          │
│ 开源信息  │                                                          │
│ 折叠      │                                                          │
└──────────┴──────────────────────────────────────────────────────────┘
```

- **侧边栏**（窄屏时收进左上角的菜单按钮）有五个入口：文件、团队、工具、设置、开源信息；
  其中「团队」只在登录后出现，访客看不到团队待办。
  最上方是品牌区：第一行 `ZeroShadow`，第二行 `v<版本号>`（版本号取自 `web/src/version.ts`，
  与「软件开源信息」页显示的是同一个值）；折叠后品牌区只剩一个图标。
- 侧边栏底部的**「折叠」按钮**把桌面侧边栏收成只有图标的窄条（宽度 48 → 14），再点一次展开；
  图标是 `panel-left-close` / `panel-left-open`，也可以在**侧边栏空白处右键**选「收起侧边栏」。
  折叠状态存在浏览器本地（`zs-client-settings` 里的 `sidebarCollapsed`，旧的 `zs-sidebar-collapsed`
  键会在读取时自动迁移），刷新与切页都保持；窄屏的手机抽屉**不受影响**，始终显示完整文字。
- **顶栏**上有**小组切换器**（登录后出现）：选「默认」或某个小组后，文件可见范围、有效权限与团队待办一起切换。
- **设置**里的管理类标签页（状态 / 日志与指标 / 成员 / 小组 / 权限 / 数据与保留 / 安全 / 公网）**只对超级管理员显示**。
- **顶栏**右上角：主题切换按钮；未登录时显示「登录」按钮，已登录时显示头像 + 用户名，
  点开头像卡片可以换头像、改密码（成员）或退出登录。
- **顶栏搜索框只在窄屏（`<640px`）出现**；宽屏时搜索框在文件浏览器的工具栏里。两者行为一致。
- 文件浏览器**底部**有一行提示，写着当前身份，例如 `当前为"访客"模式`、`当前为"团队成员"模式，其他功能需要管理员模式`。

网页路由一览（可以直接在地址栏访问）：

| 路径 | 页面 |
|:---------------------- |:------------------------ |
| `/` | 文件浏览器 |
| `/team` | 团队待办（登录后才有入口） |
| `/login` | 登录 |
| `/settings` | 设置 |
| `/preview?path=…` | 文件预览（全屏） |
| `/editor?path=…` | 在线文本编辑器（全屏） |
| `/html-preview?path=…` | HTML 全屏预览（全屏） |
| `/tools` | 工具 |
| `/about` | 软件开源信息 |

访问不存在的路径会自动跳回 `/`。

- 顶部面包屑从「根目录」开始，点任意一段可以跳过去；

## 小组切换

登录后，顶栏会出现**小组切换器**（一个带层叠图标的下拉框）。它的作用是给当前会话选一个"上下文"：

| 选项 | 含义 |
|:--|:--|
| **默认** | 不使用小组上下文，按超管在「设置 → 数据与保留 → 默认上下文可见范围」里设定的白 / 黑名单显示文件 |
| **某个小组** | 只显示该小组可见范围内的目录，权限也按该小组的设置**收窄**（只减不增） |

切换后：

- 文件列表立刻按新范围刷新；不可见的目录表现为"不存在"，直接访问该路径返回 404；
- 权限按钮可能变灰或消失（例如小组关掉了「删除」，右键菜单里的删除就点不动）；
- 「团队」页的待办范围也跟着变；
- 选择记在浏览器本地（`zs-group-context`），下次打开还是同一个小组；
  若该小组被删除、或你被移出小组，会自动回退到「默认」。

成员只能切到自己所属的小组；超管可以切到任意小组；访客没有小组切换器。
小组怎么建、白名单 / 黑名单怎么填、组长有哪四项能力，见
[权限与角色](/docs/zeroshadow/guide/permissions) 与 [管理员指南](/docs/zeroshadow/admin/admin-guide)。

## 上传

<Steps>
<Step>
### 选一种上传方式

- 点工具栏「上传」，选择一个或多个文件；
- 点「上传文件夹」，选择整个文件夹（浏览器会带上相对路径）；
- **直接拖拽**文件或文件夹到列表区域，出现“松开以上传到当前文件夹”提示时松手（整目录拖拽会保留目录结构）。
</Step>
<Step>
### 看右下角的上传进度面板

上传过程中右下角会出现**上传进度面板**：

- 显示文件名（多文件时显示“某某 等 N 个文件”）、进度条、已传输 / 总大小；
- 上传中可点右侧 `×` 取消；
- 完成后点面板标题右侧 `×` 清除已完成记录；
- 结果提示：全部成功显示「已上传 N 个文件」，有失败项会列出具体原因。
</Step>
<Step>
### 遇到重名时按提示选择

重名默认自动改成 `名字 (1).ext`，也可以在上传时选择覆盖 / 跳过后再传；

上传文件夹时的重名以**顶层文件夹名**为单位询问，可对每个顶层文件夹分别选择合并 / 覆盖 / 重命名 / 跳过。
选「覆盖」或「合并」时，请求里会带上该文件夹内每个文件的**相对路径**（形如 `dir/sub/file.txt`），
服务端按"文件名或相对路径命中即覆盖"来判定，所以文件夹级的覆盖 / 合并是真的逐层生效的。

超出大小限制的文件会被拒绝，并逐条给出「超出大小限制 (NMB)」提示，**不会**产生半个残缺文件。
</Step>
</Steps>

### 一次上传超过 100 个文件

服务端单次请求最多接收 **100** 个文件（busboy 的 `files` 限制），但**界面会自动分批**，不需要你手动拆：

- 选中的文件按每批 100 个切片后依次上传，进度条显示的是所有批次的合计进度；
- 上传响应里会带回 `truncated` 与 `maxFilesPerRequest`（`100`）。如果服务端确实丢过文件
  （响应里的 `truncated` 为 `true`），界面会提示「单次最多上传 100 个文件，超出部分未处理」，
  照着提示把剩余文件再传一次即可；
- 任一文件失败时，界面只弹**一条**汇总提示：「已上传 N 个，M 个失败」，
  展开可以看到每个失败文件的文件名与具体原因，不会再出现"既报成功又报失败"的矛盾提示。

拖拽或选择整个文件夹上传时，浏览器会把每个文件的**相对路径**（形如 `子目录/文件.txt`）一起发过来，
服务端据此逐层创建目录，**目录结构会被完整保留**。

### 上限与规则

| 规则 | 值 | 来源 |
|:------------------ |:--------------- |:------------------------ |
| 单文件大小（成员） | 默认 512 MB，超管可改 | 「设置 → 权限 → 上传大小限制」(`memberUploadLimitMB`) |
| 单文件大小（超管） | 默认 2048 MB，超管可改 | 「设置 → 权限 → 上传大小限制」(`superUploadLimitMB`) |
| 单次请求文件数 | 100 | 服务端上传解析限制（响应里的 `maxFilesPerRequest`）；界面会按这个值**自动分批** |
| 上传时的覆盖判定 | 命中「文件名」或「相对路径」即覆盖 | 服务端按 `overwrite` 列表逐项比对，因此文件夹级的覆盖 / 合并有效 |
| 文件名 | 自动清洗掉 `\ / : * ? " < > \|` 与控制字符，去尾部空格与点 | 服务端 |
| 重名 | 默认自动改成 `名字 (1).ext`；也可以在上传时选择覆盖 / 跳过后再传 | — |
| 上传文件夹时的重名 | 以**顶层文件夹名**为单位询问，可对每个顶层文件夹分别选择合并 / 覆盖 / 重命名 / 跳过 | — |

<Accordions>
<Accordion title='为什么不会留下“下载到一半的文件”？'>
上传的文件先落到 `data/tmp/`，落盘成功后才移动到目标目录，因此不会出现“下载到一半的文件”。

所以中断的上传只会在临时目录留下残留，不会在目标目录里生成一个体积不对、名字正常的半成品。
</Accordion>
</Accordions>

## 下载

| 你选了什么 | 会发生什么 |
|:--------------------- |:--------------------------------------- |
| 单个文件 | 直接下载该文件，中文文件名会正确保留 |
| 单个文件夹 | 打包成 `<文件夹名>.zip` 下载 |
| 多选（文件 / 文件夹混选） | 打包成 `ZeroShadow-<日期>.zip` 下载 |

打包规则：

- 打包时**排除符号链接**；访客打包时会**自动跳过对其隐藏的文件夹及其内容**；
- 空文件夹会在压缩包里保留一个 `.keep` 占位文件；
- 多个不同目录下**同名**的条目会自动用路径（`/` 换成 `_`）区分，仍然重名则追加 `_2`、`_3`…

打包上限（「设置 → 权限 → ZIP 打包 / 解压限制」）：

| 限制 | 默认值 | 说明 |
|:-------------- |:-------- |:--------------------------------------- |
| 最大文件数 | 100 | 超出直接拒绝，提示实际数量 |
| 单文件最大 | 50 MB | 校验的是**被选中的那些文件**本身；所选文件夹内部的文件不单独校验，而是计入总量上限 |
| 总大小最大 | 128 MB | 递归统计的总量上限（文件夹内部的文件都算） |

<Callout type="warn" title="打包接口受限流保护">
打包需要遍历目录统计体积，因此这个接口**受接口限流保护**（默认单 IP 每分钟 120 次）。

若提示「操作过于频繁，请 N 秒后再试」，等一会儿或让超管放宽限流即可。
</Callout>

## 文件预览

| 类型 | 支持格式 | 交互 |
|:-------- |:----------------------------------------------------- |:--------------------------------------- |

| **视频** | mp4 / webm / mov / mkv / wmv / flv / 3gp / m4v | 自动播放，使用浏览器原生控制条（能不能播取决于浏览器是否支持该编码） |
| **音频** | mp3 / wav / ogg / flac / m4a / aac | 自动播放，显示文件名 |
| **PDF** | pdf | 内嵌浏览器 PDF 阅读器 |
| **文本** | txt / md / json / log / csv / js / ts / css / py / yml / yaml / xml / ini / conf / rst / adoc / tex / bat / ps1 / vbs / lua / rb / php / pl / sql / toml / properties / graphql / rtf / org / cmake / gradle / dockerfile / makefile / .gitignore / .env | 以等宽字体**原样**显示（不做 Markdown 渲染，也不做语法高亮） |

预览页面本身是只读的，不会修改服务器上的文件。

### HTML 全屏预览

`.html` / `.htm` 文件如果拥有「HTML 全屏预览」权限，**双击文件就会直接进入 HTML 全屏预览**（右键菜单里也有「HTML 预览」），
页面在**沙箱 iframe** 中渲染（`sandbox="allow-scripts"`，不含 `allow-same-origin`）。

这意味着页面里的脚本可以运行，但**拿不到网盘的 Cookie 与接口会话**——这是刻意的安全设计，详见 [安全设计](/docs/zeroshadow/security/design#5-html-与-svg-的沙箱处理)。

<Callout type="info" title="没有权限时会退化为文本预览">
没有这个权限时，双击 `.html` / `.htm` 会按普通**文本预览**打开，看到的是源码，而不是被下载下来。
</Callout>

### 文本预览与不支持的格式

- 文本类文件（及退化处理的 HTML）以等宽字体**原样**显示：内容是交给页面渲染的，**不会做二次转义**，
  所以引号、尖括号、`&` 在屏幕上都按文件里的原样出现，不会变成 `&quot;` / `&lt;` 之类的转义实体；
- 只有 `lib/format.ts` 里登记过的扩展名才会走预览。**不在名单里的格式不会拿去当文本抓取**，
  而是显示「**暂不支持预览此格式**」，避免把二进制内容渲染成一片乱码。

<Callout type="warn" title="文本预览不识别编码">
预览页是把文件按浏览器默认方式（UTF-8）直接显示的，所以 GBK / Big5 的文件在预览里可能是乱码。
要看正确内容请用**在线编辑**打开——它会自动识别编码（见下一节）。
</Callout>

## 在线编辑

右键可编辑文件 →「在线编辑」，进入全屏编辑器（路由 `/editor?path=…`）：

- 编辑器是纯文本编辑（等宽字体，不做语法高亮、不做自动补全）；
- `Ctrl`/`⌘ + S` 或点右上角「保存」写回服务器；
- 文件名后面出现「未保存」徽章表示有改动；有改动时关闭 / 按 `Esc` 会弹确认框（「继续编辑」/「放弃并离开」）；
- 保存是**原子替换**（先写同目录临时文件再 `rename` 覆盖），保存途中断电也不会把原文件截断成半个。

### 编码

**旧版只有 UTF-8**：打开 GBK 的 txt 是满屏乱码，保存还会把文件写坏。现在编解码交给服务端：

- 打开文件时自动识别编码，工具栏左上角的下拉框显示识别结果，可手动切换；
- 支持的编码：`UTF-8`、`UTF-8 (带 BOM)`、`UTF-16 LE`、`UTF-16 BE`、`GB18030 / GBK（简体中文）`、
  `Big5（繁体中文）`、`Shift_JIS（日文）`、`EUC-KR（韩文）`、`Windows-1252（西欧）`、`ISO-8859-1（Latin-1）`；
- 识别顺序是 **BOM → 无 BOM 的 UTF-16 → 严格 UTF-8 → 按常用字频率逐个候选编码打分**：
  所以 Big5 不会被误认成 GB18030、Shift_JIS 也不会被误认成 UTF-16；
- 识别只是**猜测**时（分差不够大），页面会提示「编码识别为 xxx，如果显示乱码请在工具栏手动切换编码」；
- **切换编码会重新读取文件**（改编码需要原始字节），有未保存改动时会先弹确认框；
- 保存时按当前编码写回，`UTF-8 (带 BOM)` / `UTF-16 LE` / `UTF-16 BE` **会自动写入 BOM**；
- **目标编码表示不了的字符会被拒绝保存**（提示「这些字符无法用 xxx 表示：… 请改用 UTF-8 保存」），
  而不是悄悄写成 `?` 把内容改坏——例如把含简体字的文本存成 Big5。

### 换行符

工具栏的换行符下拉框有 `CRLF` / `LF` / `CR` 三档：打开时按原文件的风格自动选中；
正文里统一按 `LF` 显示与编辑，**保存时才按这个选择还原**；保存后状态栏会回报实际写入的编码与换行风格。

### 编辑功能

| 功能 | 说明 |
|:--|:--|
| 行号 | 左侧行号栏，随正文滚动；**开启自动换行时自动隐藏**（换行后行号会与视觉行错位） |
| 自动换行 | 工具栏按钮切换；关闭时不折行、横向滚动 |
| 字号 | 工具栏 `-` / `+` 在 11–22 之间调整，当前值显示在中间 |
| 查找 | `Ctrl`/`⌘ + F`（或 `Ctrl+G`）打开查找条；`Enter` / `F3` 下一个，`Shift+F3` 上一个；显示 `当前/总数` |
| 替换 | `Ctrl`/`⌘ + H` 打开替换条，多出「替换」「全部替换」与替换内容输入框 |
| 区分大小写 / 正则 | 查找条上的两个开关按钮；正则无效时替换会提示「正则表达式无效」 |
| 跳转到行 | 查找条右侧的行号输入框，回车跳过去 |
| Tab 缩进 | 在编辑器里按 `Tab` 插入**两个空格**（不跳走焦点） |
| 状态栏 | 行 / 列、选中字符数、总行数、字符数、编码、换行符、文件大小；超过 **2 MB** 会提示「文件较大，编辑可能有卡顿」 |

支持的扩展名：`txt md mdx py cpp log html htm js ts css json xml yml yaml ini conf sh java c rs go rst adoc tex bat ps1 vbs lua rb php pl sql toml properties graphql rtf org cmake gradle gitignore env dockerfile makefile`。

### 上限与只读

- 单次**读取**上限 **8 MB**（`EDITOR_MAX_BYTES`），超过提示「文件过大（NMB），在线编辑上限 8MB」；
- 单次**保存**的内容上限是 **16 MB**（其余 JSON 接口仍是 1 MB），超过会提示「内容过大（NMB），在线编辑上限 16MB」；
- **二进制文件不能当文本打开**：含 NUL 字节或控制字符过多的文件会提示
  「这看起来是二进制文件，不能当文本编辑」（UTF-16 文件不受 NUL 检查影响）；
- 只读映射目录里的文件**不能**在线编辑：菜单项变灰，编辑器里也会显示「只读目录」徽章且无法保存。

## 搜索

在搜索框输入关键词后按 `Enter`：

- 网页界面的搜索**始终从网盘根目录开始递归**（不受你当前所在目录影响），匹配规则是**文件名包含关键词**（不区分大小写）；
- 结果列表显示文件名、类型、大小，以及它所在的路径（点击路径可以跳过去）；
- 搜索结果最多返回 200 条，单次搜索最长约 6 秒、最多访问 30000 个条目，超出就返回已找到的部分；
- 搜索框里输入的关键词限制在 100 个字符以内；
- 点结果上方的「清除」或清空关键词回车，即可回到正常浏览。

搜索接口属于重型操作，**受接口限流保护**。

## 访客可见性

对**文件夹**右键 →「对访客隐藏」，该项及其整个子树的名称会从访客的列表与搜索结果中消失，访客直接访问该路径会得到「目录不存在」，访客打包下载时也会被跳过。

- 只有文件夹可以设置（对文件设置会提示「只能对文件夹设置访客可见性」）；
- 根目录不能设置；
- 非访客成员仍然能看到，且列表里会有个“眼睛斜杠”小图标标识；
- 重命名 / 移动被隐藏的文件夹时，隐藏记录会**跟着一起更新**；删除该文件夹时对应记录一并清理；
- 已隐藏的列表可以在「设置 → 权限 → 对访客隐藏的文件夹」里查看，并点「恢复可见」取消。

## 快捷方式（`.zeropath`）

快捷方式本质上是一个内容为 JSON 的 `.zeropath` 文件，用来把常用入口固定到某个目录里，或者给某项起一个更友好的名字 / 换一个图标。

创建方式：

- 右键任意文件 / 文件夹 →「创建快捷方式」（自动填好目标）；
- 或在空白处右键 →「创建快捷方式」（手动填写目标）。

对话框中可填：

| 字段 | 说明 |
|:-------------- |:--------------------------------------- |
| 显示名称 | 在列表里显示的名字 |
| 目标路径 | 相对网盘的路径，或只读映射目录下的路径 |
| 目标类型 | 目录 / 文件 / 外部映射目录 / 外部映射文件 |
| 图标 | 从 18 个内置图标里挑一个（folder、file、image、film、music、globe、link…） |

保存后生成 `显示名.zeropath`，文件内容形如：

```json
{
  "name": "官网",
  "logo": "globe",
  "url": "团队资料/官网",
  "type": "path"
}
```

`type` 的取值与上面「目标类型」一一对应：`path` 目录、`file` 文件、`soft_path` 外部映射目录、`soft_file` 外部映射文件；`url` 就是「目标路径」，`name` 是「显示名称」，`logo` 是图标名。

解析时还额外兼容两种别名，以及一个兜底规则：`dir` 等同 `path`，`soft_dir` 等同 `soft_path`，**无法识别的取值一律按 `path`（目录）处理**。所以手写这个文件时写错了 `type`，它会静默当成目录快捷方式，而不会报错——排错时值得留意。

双击快捷方式：

- 目标是目录 → 跳进该目录；
- 目标是文件 → 有预览权限就打开预览，否则直接下载；
- 目标不存在或数据损坏 → 提示「快捷方式目标不存在或无权访问」/「快捷方式数据损坏」。

<Callout type="info" title="创建与修改都需要「在线编辑文件」权限">
创建与修改快捷方式都要经过「保存文件」接口，因此需要「在线编辑文件」权限。
</Callout>

侧边栏进入「工具」，目前有两个标签页。

界面上的名字是「多线程下载器」，实际行为是：**服务端拿着你给的直链去抓取文件，落到网盘指定目录**。

用法：

<Steps>

</Step>
<Step>

</Step>

限制与规则：

| 项 | 说明 |
|:------------------ |:--------------------------------------- |
| 单个文件大小上限 | 默认 4096 MB（「设置 → 权限 → 链接下载工具限制」`downloadUrlMaxMB`） |

## 团队待办

侧边栏「团队」（或直接访问 `/team`）是团队协作面板：**超管与组长下发任务，被指派的成员推进并勾选完成**。
访客看不到这个入口，未登录直接访问会提示「登录后可查看团队待办」。

页面是**整页单列滚动**（不再有"列表自己滚、外面也滚"的双层滚动区），从上到下依次是：
标题与「新建待办」、筛选工具条、待办列表、组长专属的「我管理的小组」。

### 筛选与搜索

筛选工具条把**状态分段、范围分段与搜索框收进同一块带边框的工具条**里（不再各占一行）：

- **状态**是一排分段按钮：`进行中`（默认）/ `已完成` / `全部`；
- **范围**也是一排分段按钮：`全部范围` / `小组` / `成员`；
- 右侧搜索框带放大镜图标，在**标题与备注**里做不区分大小写的子串匹配；
- **待办列表是页面的主体卡片**，放在最显眼的位置；列表上方的计数条显示 `共 N 条 · 未完成 M 条`；
  筛完没有结果时显示「暂无待办」空状态（能创建的人看到"点击右上角「新建待办」下发第一条任务"，
  其他人看到"当前筛选条件下没有待办"）；
- 每条待办的左侧复选框就是「完成 / 未完成」开关，改动会记下完成人；
  标题下方是备注（最多显示两行）、范围标签（`全体` / `小组·组名` / `成员·用户名`）、
  截止日期（已逾期红色、今天到期琥珀色）与创建者头像；右侧 `⋯` 菜单按权限显示
  「编辑」「标记完成 / 标记未完成」「删除」，行上**右键**还有一份同样的菜单再加
  「复制标题」「复制备注」。

### 一条待办包含什么

| 字段 | 说明 |
|:--|:--|
| 标题 | 必填，不超过 200 字 |
| 备注 | 可选，不超过 2000 字 |
| 优先级 | 分段按钮「高 / 中 / 低」，默认「中」；高优先级显示实心徽章 |
| 截止日期 | 日期选择器；已逾期标红并注明「（已逾期）」，今天到期标琥珀色并注明「（今天）」 |
| 下发范围 | 分段按钮：全体成员（仅超管可选）/ 指定小组 / 指定成员 |
| 允许被指派成员编辑内容 | 勾选后被指派者也能改标题、备注、优先级与截止日期 |

排序规则：未完成在前；填了截止日期的按日期升序（没填的排在最后）；日期相同时按优先级高 → 中 → 低。

### 谁能做什么

| 角色 | 能做什么 |
|:--|:--|
| **超级管理员** | 看到全部待办；可下发「全体成员」待办；可编辑 / 完成 / 删除任意待办 |
| **组长**（该小组已开启 `manageTodo`） | 向**本组**下发待办、给**本组成员**单独下发；管理本组与本组成员的待办 |
| **被指派的成员** | 看到发给自己的、本组的与全体的待办，可勾选完成；创建者勾了「允许被指派成员编辑内容」时还能改内容 |
| **访客** | 没有入口 |

<Callout type="info" title="「我管理的小组」在列表下方的管理对话框里">
组长登录后，待办列表**下方**会多出一张「我管理的小组」卡片（超管与普通成员看不到）。
它是**紧凑的一行一个小组**的列表：小组名、成员数徽章、可见范围徽章（`白名单 N` / `可见不限`，有黑名单时追加 `· 隐藏 N`），
还能看到前 6 位成员的头像与用户名（超出显示「等 N 人」）。

每行右侧的「管理」按钮打开**小组管理对话框**，里面分两个标签：

- **成员**：搜索成员，逐个加入 / 移出本组（移出会同时取消其组长身份）；没有「查看本组成员名单」能力时只显示
  「组长能力里未开启「查看本组成员名单」」；
- **可见范围**：`可见白名单` 与 `隐藏黑名单` 两个多行输入框（每行一个目录，相对网盘根目录），
  各自的右上角有「**从目录选择**」按钮，打开**目录选择器**——像文件浏览器一样逐层点进目录，
  选中后会把该目录追加到对应的输入框里；白名单留空表示不限制，黑名单优先级高于白名单；
  改完点「保存可见范围」。
</Callout>

数据存在服务端的 `data/todos.json`，所有人看到的是同一份真实状态。

<Callout type="warn" title="超管可以整体关掉这个功能">
「设置 → 数据与保留 → 团队待办 → 启用团队待办」（`todoEnabled`）关掉后，
`/team` 会显示明确的空状态「**团队待办已被关闭**」，并说明"管理员在「设置 → 权限」里关闭了团队待办功能；
重新开启后这里就能继续使用"——旧版本在这种情况下会直接报错白屏。
</Callout>

## 任务面板

右下角会出现两类浮动面板，两者同时存在时，操作面板会自动上移避免重叠。

| 面板 | 内容 | 可做的操作 |
|:--------------- |:--------------------------------------- |:------------------------ |
| **上传** | 每个上传任务的文件名、进度条、已传 / 总量 | 上传中可取消；完成后可逐条移除或一键清除 |
| **处理** | 压缩 / 解压 / 链接下载任务，标题形如「正在处理 N 项」 | 显示进度百分比，失败时显示原因，可逐条移除或一键清除 |

任务进度只对**创建者与超管**可见（可在「设置 → 安全」里放开，让成员之间互相可见）。

服务端任务状态保留 **10 分钟**，过期后再查询会得到“任务已过期”。

## 账户相关

### 头像

- **换头像**：点右上角头像 → 在「账户」卡片里把鼠标移到头像上，会出现相机图标，点它选一张本地图片。
  浏览器会**自动居中裁切并缩放到 128×128 的 WebP** 再上传（卡片上有「头像自动裁剪为 128×128」的说明）；
- 头像存在服务端的 `data/avatars/<owner>.webp`（成员是 `u-<成员 id>`，超管是 `_superadmin`），
  接口只回传 md5，前端用 IndexedDB 缓存，**没换过头像就不会重复下载**；
- 超管在「设置 → 成员」里也可以给某个成员**设置头像 / 恢复默认头像**（点列表里那一列的小头像同样能换）；
- 组长在本组开启 `editMemberAvatar` 后，也可以通过接口修改本组成员的头像
  （目前只有接口入口，界面上的成员管理仍只对超管开放，见 [API 参考](/docs/zeroshadow/api/reference) 的「头像」一节）；
- 上传失败会给出明确原因：`请选择图片文件`、`仅支持 WebP 格式头像`、
  `头像尺寸必须为 128×128（当前 宽×高）`、`头像体积超出限制（最大 200KB）`、
  `当前浏览器不支持 WebP，请更换现代浏览器`；
- 超管可在「设置 → 数据与保留 → 头像」里关掉「允许成员设置头像」（`avatarEnabled`，关掉后超管自己也改不了），
  或调整单张体积上限（`avatarMaxKB`，默认 200KB，范围 1–10240）。

**没有上传头像的人会得到一个自动生成的默认头像**（渐变圆底 + 两个字符的缩写）：

- 渐变由**色相 24 档 × 副色相 4 档 × 明度 3 档 = 288 种组合**里选一种（用稳定哈希按显示名取，
  同一个人在任何位置颜色都一样）；
- 缩写规则：**中日韩名字取后两个字**（同姓太多，姓氏几乎没有区分度）、
  拉丁文名字有多个词时取前两个词的首字母（`Wang Yuqian` → `WY`）、
  单个词时取首字母 + 末字母（`wangyq` → `WQ`）；
- 旧版默认头像是"8 种纯色 + 一个首字母"，十几人的团队里很容易撞脸（`wangyq` 与 `wanglei` 都是 `W`），
  现在 288 种外观叠加两个字符后基本不会认错人。

<Callout type="info" title="为什么只支持 WebP">
你可以选任意 `image/*` 图片（png / jpg / gif / webp 等），因为转换是在浏览器里完成的；
真正发到服务端并落盘的**只有 128×128 的 WebP**，所以服务端只认这一种格式。
</Callout>

## 换台设备还有效吗？

网页端只有几类“记住”的东西，都**存在浏览器本地**（`localStorage`）：

| 键名 | 内容 |
|:----------------------- |:--------------------------------------- |
| `zs-theme` | 主题（浅色 / 深色 / 跟随系统） |
| `zs-client-settings` | 视图模式、排序字段、排序方向、文件夹置顶、界面密度、字号、减少动画、背景噪点、桌面侧边栏是否默认折叠 |
| `zs-sidebar-collapsed` | **旧键**，桌面侧边栏是否折叠（`1` = 折叠成图标条，`0` = 展开）。只在首次读取时迁移进 `zs-client-settings.sidebarCollapsed`，之后不再写入 |
| `zs-group-context` | 当前选中的小组 id（`default` = 不使用小组上下文） |

换浏览器、换设备、清除浏览器数据后这些偏好会恢复默认；账号、文件、后台设置都在服务器上，不受影响。
