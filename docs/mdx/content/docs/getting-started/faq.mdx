## 账号与登录

<Accordions>
<Accordion title="忘记超级管理员密码怎么办">
**判断**：登录时一直提示"用户名或密码错误"，或者控制台里就没记下首次启动打印的随机密码。

**处理**：直接改 `.env`（位于项目根目录，打包运行时在 `ZeroShadow.exe` 同目录）：

```ini
SUPER_ADMIN_USER=admin
SUPER_ADMIN_PASSWORD=你自己的新密码
```

改完**重启服务**。注意两点：

1. 密码只在启动时读取，不重启不生效；
2. 重启后超管的**所有旧登录会话立刻失效**（令牌里带着密码指纹），其他成员不受影响。

**另一种更省事的做法**：把 `SUPER_ADMIN_PASSWORD=` 这一行删掉（或者把值写成 `change-me`），
重启后会**自动生成一个随机密码**，既打印在控制台、也写回 `.env`。

**成员的密码**不需要改 `.env`：超管登录后进「设置 → 成员」，点该成员的 `⋮` →「重置密码」（可点"随机生成"）。
</Accordion>

<Accordion title="「用户名或密码错误」（401）">
密码错误，或用户名大小写 / 空格不对（用户名前后空格会被自动去掉）。
</Accordion>

<Accordion title="「尝试次数过多，请约 N 分钟后再试」（429）">
触发了暴破防护。**IP** 维度：15 分钟内失败 30 次锁 15 分钟；**用户名**维度：15 分钟内失败 10 次锁 5 分钟起、连续触发翻倍、最长 30 分钟。等一会儿，或重启服务（计数在内存里）。
</Accordion>

<Accordion title="「该账户已被禁用」（403）">
超管在「设置 → 成员」里禁用了该账号。
</Accordion>

<Accordion title="超管改完 .env 密码后所有人都要重新登录">
这是预期行为：令牌里带着密码指纹。
</Accordion>

<Accordion title="成员改了密码后被踢出登录">
也是预期：重置密码会作废旧会话，用新密码重新登录。
</Accordion>

<Accordion title="登录成功但很多按钮是灰的">
你的角色或超管的权限设置限制了你。见 [权限与角色](/docs/zeroshadow/guide/permissions)。
</Accordion>

<Accordion title="直接改 data/users.json 后登录不了">
密码是 bcrypt 哈希，手改明文无法登录；请用后台"重置密码"。
</Accordion>
</Accordions>

## 启动相关

<Accordions>
<Accordion title="页面提示「前端尚未构建：请先运行 pnpm build，然后重启服务。」">
`web/dist` 不存在。执行：

```bash
pnpm build
```

然后重启服务。发布包里已经带了 `web/dist`，出现这个提示说明发布目录不完整。
</Accordion>

<Accordion title="pnpm setup 失败">
按顺序检查：

1. `node -v` 是否为 18 及以上；
2. `pnpm -v` 是否为 9 及以上（没有 pnpm：`npm i -g pnpm`）；
3. 网络是否能访问 npm 源（公司网络可能需要在 `.npmrc` 里配镜像）；
4. 报 `EPERM` / 文件被占用时，确认没有正在运行的服务或编辑器锁定 `node_modules`。
</Accordion>

<Accordion title="控制台什么输出都没有">
很可能设了静默模式。检查 `.env` 里是否有 `NOLOG=true`，或者启动命令里是否带了 `-nolog`。
静默模式下日志**照常写文件**，去「设置 → 日志与指标」看即可。
</Accordion>

<Accordion title="启动后 data/ 里多了东西">
这是正常的：服务会自动创建 `data/`、`data/files/`、`data/logs/`、`data/tmp/`，以及
`data/.jwt-secret`（会话密钥）。`data/tmp/` **每次启动都会清空**，不要往里放东西。
</Accordion>
</Accordions>

## 局域网里其他设备打不开

按这个顺序排除：

<Accordions>
<Accordion title="HOST 是不是 0.0.0.0">
**怎么确认**：看 `.env` 里的 `HOST`。

**处理**：写成 `127.0.0.1` 时只有本机能访问，改成 `0.0.0.0` 并重启。
</Accordion>

<Accordion title="别人用的是不是局域网地址">
**怎么确认**：启动日志里有「局域网访问」一行。

**处理**：把那行地址发出去；**不要给 `localhost`**（那是对方自己的机器）。
</Accordion>

<Accordion title="防火墙是否放行">
**怎么确认**：在对方机器上 `ping` 一下你的 IP 能通、但浏览器打不开。

**处理**：放行入站 TCP 端口（默认 12345）。Windows：`ZeroShadow.exe` 首次运行会弹"是否允许网络访问"，必须选**允许**；也可以手动到「Windows Defender 防火墙 → 高级设置 → 入站规则」新建一条 TCP 12345 的允许规则。
</Accordion>

<Accordion title="是否在同一网段">
**怎么确认**：`ipconfig` / `ifconfig` 对比前三位。

**处理**：不同网段（比如一方连了手机热点）需要走公网隧道，见 [公网访问与隧道](/docs/zeroshadow/admin/tunnel)。
</Accordion>

<Accordion title="WiFi 是否开了「AP 隔离 / 客户端隔离」">
**怎么确认**：同一路由下互相 ping 不通。

**处理**：关掉该功能，或改用有线 / 换网络。
</Accordion>

<Accordion title="是否多网卡取错了地址">
**怎么确认**：启动日志里可能列出多个局域网地址。

**处理**：用 `ipconfig` 确认哪个是本网段的，优先用有线的那个。
</Accordion>

<Accordion title="代理设置">
**怎么确认**：浏览器配了系统代理。

**处理**：把局域网地址加入代理例外（不走代理）。
</Accordion>
</Accordions>

## 端口相关

<Accordions>
<Accordion title="修改端口">
编辑 `.env` 的 `PORT`，重启即可（范围 1–65535）。
大于 1024 的端口通常不需要管理员权限。

<Callout type="warn">
如果你在**开发模式**下改了后端端口：Vite 的代理目标是由 `backendPort()` 从根目录 `.env` 的 `PORT`
读出来的，改完 `.env` 重启一下 `pnpm dev:web` 即可（只有把后端跑在别的目录、
或改了 `.env` 的位置时才需要手工同步 `web/vite.config.ts`）。
</Callout>
</Accordion>

<Accordion title="端口被占用（EADDRINUSE）">
**Windows**：

```powershell
netstat -ano | findstr :12345
tasklist /fi "pid eq <上面查到的PID>"
```

**Linux / macOS**：

```bash
lsof -i :12345
# 或
ss -lntp | grep 12345
```

要么结束占用进程，要么把 `PORT` 换成别的。
</Accordion>

<Accordion title="想让服务只对本机开放">
`.env` 里写 `HOST=127.0.0.1`，然后访问 `http://127.0.0.1:12345`。
</Accordion>
</Accordions>

## 上传失败或提示超出大小限制

<Accordions>
<Accordion title="「超出大小限制 (NMB)」">
该角色单文件上限。超管在「设置 → 权限 → 上传大小限制」调整（默认成员 512MB / 超管 2048MB）。
</Accordion>

<Accordion title="一次拖了很多文件，能传完吗">
能。网页会把选择自动切成**每批 100 个**依次上传，进度条与「已上传 N 个文件」都是合计结果。
只有自己写脚本裸调接口时才需要分批（响应里的 `truncated: true` 表示这一批超了，超出部分被丢弃）。
</Accordion>

<Accordion title="上传文件夹后目录结构乱了 / 全平铺了">
现在会**真实保留**相对路径（`子目录/文件.txt`）。若仍看到平铺，说明前端是旧版本的构建产物，
重新 `pnpm build` 或换新的发布包即可。
</Accordion>

<Accordion title="上传到某个目录按钮是灰的 / 提示「外部映射目录仅支持只读操作」">
那是只读映射目录（`FILES_SOFT_DIR`），本来就不能写。
</Accordion>

<Accordion title="文件名被改了">
非法字符（`\ / : * ? " < > \|` 等）被替换成 `_`；重名自动变成 `名字 (1).ext`。
</Accordion>

<Accordion title="上传中断、没有残留文件">
这是设计：文件先写进 `data/tmp/`，写完才移到目标位置，中途断开会清理临时文件。
</Accordion>

<Accordion title="通过公网隧道上传大文件总是失败">
先用局域网地址试一次，排除隧道服务本身的请求体限制；也可以改用分卷压缩后小批量上传。
</Accordion>

<Accordion title="上传后找不到文件">
看一下当前所在目录（面包屑）；上传一定是传到"当前目录"。
</Accordion>
</Accordions>

## 下载与打包

<Accordions>
<Accordion title="点下载没反应 / 提示没有权限">
「下载文件」或「下载文件夹」权限被关了（访客尤其容易被关）。
</Accordion>

<Accordion title="「操作过于频繁，请 N 秒后再试」">
打包属于重型接口，受限流保护（默认单 IP 每分钟 120 次）。等一下，或让超管在「设置 → 安全 → 接口限流」放宽。
</Accordion>

<Accordion title="打包被拒绝，提示超出限制">
打包上限：条目数 100、单文件 50MB、总量 128MB。可在「设置 → 权限 → ZIP 打包 / 解压限制」调整。
</Accordion>

<Accordion title="打包出来的压缩包里少了内容">
访客打包时会**递归跳过**"对其隐藏"的文件夹；成员当前小组可见范围之外的目录也会被递归跳过；
符号链接本身不会被跟随打包。
</Accordion>

<Accordion title="空文件夹在压缩包里只剩一个 .keep">
这是刻意保留的占位文件，避免解压后目录结构丢失。
</Accordion>

<Accordion title="压缩包里出现了 a_b_file.txt 这种名字">
来自不同目录的同名文件会用路径（`/` → `_`）区分，防止互相覆盖。
</Accordion>

<Accordion title="中文文件名下载后变乱码">
服务端同时给了标准与 UTF-8 两种文件名（`filename` + `filename*`），请使用现代浏览器；极老的下载工具可能只认前者。
</Accordion>

<Accordion title="「同名文件处理」里选了「重命名」却没生效">
老版本的缺陷（已修）：现在会把"原始来源 + 期望的新名字"一起提交给服务端，
按分段按钮上显示的名字写入；勾了「套用全部」时每一项仍会各自生成不冲突的名字。
</Accordion>

<Accordion title="点了「取消」文件还是被移动 / 复制了">
老版本的缺陷（已修）：现在点「取消」、按 `Esc`、点对话框外的遮罩都会**真正中止**整个操作，一个文件都不会动。
</Accordion>
</Accordions>

## 预览与编辑

<Accordions>
<Accordion title="双击文件直接下载了，没进预览">
该格式不可预览，或「允许预览」权限被关了。
</Accordion>

<Accordion title="视频 / 音频打不开">
浏览器不支持该编码（例如部分浏览器不支持 HEVC/H.265）。换个格式或换浏览器。
</Accordion>

<Accordion title="HTML 打开后看到的是源码">
缺「HTML 全屏预览」权限时，HTML 会退化为文本预览。
</Accordion>

<Accordion title="HTML 页面里的脚本行为异常">
出于安全，HTML 在**沙箱 iframe** 中运行（`sandbox="allow-scripts"`，不带 `allow-same-origin`），无法访问网盘的 Cookie 与接口。见 [安全设计](/docs/zeroshadow/security/design#5-html-与-svg-的沙箱处理)。
</Accordion>

<Accordion title="文本预览没有高亮">
文本预览是**原样显示**，不做 Markdown 渲染也不做语法高亮。
</Accordion>

<Accordion title="文本里的引号显示成了转义实体">
老版本的毛病，已修：文本按原样渲染，不会二次转义（屏幕上应该是引号本身，而不是 `&quot;` 这样的实体）。
若仍看到，说明前端还是旧的构建产物，重新构建 + 强制刷新即可。
</Accordion>

<Accordion title="打开某个文件显示「暂不支持预览此格式」">
该扩展名不在可预览清单里（docx / zip / exe 等**不会**硬当文本渲染）。
在文件列表里双击这类文件是**下载**，只有在直接访问 `/preview?path=…` 时才会看到这个提示。
</Accordion>

<Accordion title="双击 .html 直接进预览了，我想下载它">
有「HTML 全屏预览」权限时，双击 `.html` / `.htm` 就是进预览（这是刻意的，不再变成下载）；
要下载请用右键菜单里的「下载」。
</Accordion>

<Accordion title="在线编辑保存报 413">
**在线编辑保存的请求体上限是 16 MB**（其余 JSON 接口仍是 1 MB）。
超过时提示「内容过大（NMB），在线编辑上限 16MB」，更大的文本请分文件，或用上传接口写入。
</Accordion>

<Accordion title="在线编辑打不开、提示「文件过大」">
在线编辑**读取**上限是 **8 MB**（`EDITOR_MAX_BYTES`，旧版本没有这条限制，大文件会把浏览器卡死）。
更大的文本请下载后用本地编辑器打开。
</Accordion>

<Accordion title="在线编辑提示「这看起来是二进制文件」">
该文件含 NUL 字节或控制字符过多（图片、可执行文件改错了扩展名等），服务端返回 **415** 而不是把它当文本打开。
UTF-16 文件含 NUL 是正常的，不会被拦。
</Accordion>

<Accordion title="打开文件是乱码">
编码识别是**猜测**，猜错时页面会提示「编码识别为 xxx，如果显示乱码请在工具栏手动切换编码」。
用工具栏的编码下拉框手动选：GBK 的 txt 选 `GB18030 / GBK（简体中文）`、繁体选 `Big5`、
日文选 `Shift_JIS`、韩文选 `EUC-KR`。
</Accordion>

<Accordion title="预览里是乱码，在线编辑里正常">
**文本预览不识别编码**——预览页把文件按浏览器默认方式（UTF-8）直接显示；
只有在线编辑会识别编码。乱码的文件请用「在线编辑」打开，或在工具栏手动切换编码。
</Accordion>

<Accordion title="切换编码后未保存的修改没了">
换编码需要用**原始字节**重新解码，所以会重新读取文件；有未保存改动时会先弹确认框，
确认后才丢弃改动。
</Accordion>

<Accordion title="保存时报「这些字符无法用 xxx 表示」">
目标编码存不下这些字符（例如把简体字存成 `Big5`，或把汉字存成 `ISO-8859-1`）。
这是**故意的**：旧版本会静默写成 `?` 把内容改坏。按提示改用 `UTF-8` 保存即可。
</Accordion>

<Accordion title="保存后换行符变了">
换行符按工具栏的 `CRLF / LF / CR` 选择写回。打开时会自动选中原文件的风格，不要改它即可保持原样。
</Accordion>

<Accordion title="在线编辑菜单是灰的">
需要「在线编辑文件」权限；只读映射目录里的文件也不能编辑（编辑器里会显示「只读目录」徽章）。
</Accordion>

<Accordion title="保存后内容没变">
确认点的是「保存」或按了 `Ctrl/⌘ + S`；文件名后面的「未保存」徽章消失才算保存成功。
</Accordion>

<Accordion title=".md 里的 &lt;br&gt; 显示成了 &amp;lt;br&amp;gt;">
1.2.4 起支持 13 个**无属性**标签（`br` / `hr` / `sub` / `sup` / `kbd` / `u` / `s` / `mark` / `small` /
`span` / `div` / `p` / `center`）。若仍看到字面量，先确认标签在名单里，再确认前端是 1.2.4 的构建产物
（升级后要重新 `pnpm build` 或换发布包）。
</Accordion>

<Accordion title="Markdown 里的 &lt;div align=&quot;center&quot;&gt; 不居中">
标签属性**一律被丢弃**（`on*` / `style` / `href` 都是注入入口，白名单只解析无属性标签），
所以渲染出来的是不带 `align` 的 `div`，看不到居中效果。
</Accordion>

<Accordion title=".md 里的外链图片不显示">
1.2.4 起应用外壳 CSP 允许 `img-src http: https:`，公网 CDN 图片能正常加载。仍不显示时按序排查：
① 图片地址本身 404 / 需要登录 / 开了防盗链；
② 页面是 HTTPS 而图片是 `http://`（浏览器按混合内容拦掉）；
③ 前端是旧构建产物。
</Accordion>

<Accordion title=".md 正文选不中 / 复制不了">
1.2.4 已修（预览页外层容器的 `select-none` 曾波及正文）。仍是旧构建产物时请重新构建；
临时可以用右上角「源码」视图复制。
</Accordion>
</Accordions>

## 头像与小组

<Accordions>
<Accordion title="「头像尺寸必须为 128×128（当前 W×H）」">
服务端只接受 128×128 的 WebP。网页端会自动居中裁切缩放后上传；用脚本直传时要自己先转好。
</Accordion>

<Accordion title="「仅支持 WebP 格式头像」">
同上，只认 WebP——不是把扩展名改成 `.webp` 就行，需要真实转码。
</Accordion>

<Accordion title="「头像体积超出限制（最大 NKB）」">
超过「设置 → 数据与保留 → 头像 → 单张体积上限」（`avatarMaxKB`，默认 200KB，可调到 10240KB）。
</Accordion>

<Accordion title="「头像功能已关闭」">
超管关掉了 `avatarEnabled`（「设置 → 数据与保留 → 头像 → 允许成员设置头像」）。
</Accordion>

<Accordion title="换了头像但页面还是旧图">
前端按 `md5` 用 IndexedDB 缓存，没变过就不会重新下载。强制刷新（`Ctrl + F5`）或重新登录即可拉到新的。
</Accordion>

<Accordion title="菜单里找不到小组切换器">
访客看不到；如果你没有加入任何小组，下拉框里只有「默认」一项。
</Accordion>

<Accordion title="明明存在的目录却提示「目录不存在」">
它不在你**当前小组**（或默认上下文）的可见范围内——这是刻意的，不是故障。
切到对应小组，或让超管把该目录加进白名单。
</Accordion>

<Accordion title="打包下载的 zip 里少了整个文件夹">
该文件夹对你当前的小组上下文不可见（或对访客隐藏），打包与在线压缩都会**递归跳过**。
</Accordion>

<Accordion title="「没有权限执行此操作」但全局权限是开的">
当前小组把该权限收窄关掉了。切到「默认」上下文，或让超管在「设置 → 小组 → 权限」里放开。
</Accordion>

<Accordion title="组长看不到本组成员、也管不了可见范围">
超管要在该小组的「基本 → 组长权限」里勾选「查看本组成员名单」「管理本组成员与可见范围」等能力，
服务端是**逐请求校验**的，不只是界面限制。
</Accordion>
</Accordions>

## 团队待办

<Accordions>
<Accordion title="侧边栏里没有「团队」">
**访客**看不到这个入口；先登录。
</Accordion>

<Accordion title="「Todo 功能已关闭」">
超管在「设置 → 数据与保留 → 团队待办」关掉了 `todoEnabled`；打开 `/team` 会看到
「团队待办已被关闭」的空状态（旧版本在这种情况下会直接报错白屏）。
</Accordion>

<Accordion title="列表里看不到某条待办">
它不在你的范围内：`全体` / 你所在小组 / 指派给你本人，三者之外只有创建者、组长与超管能看到。
</Accordion>

<Accordion title="「新建待办」按钮不见了">
只有**超管与组长**能下发待办；普通成员只能完成被指派给自己的
（能否改内容要看该条是否勾了「允许被指派成员编辑内容」）。
</Accordion>

<Accordion title="「下发范围」里没有「全体成员」">
只有超管能创建全体 Todo。
</Accordion>

<Accordion title="「没有权限向该小组下发 Todo」">
你不是该小组的组长，或该小组没有被下放「创建 / 编辑本组待办」能力。
</Accordion>

<Accordion title="改了标题却提示「没有权限编辑该 Todo」">
内容编辑需要"创建者 / 组长 / 超管"，或这条待办开启了「允许被指派者编辑」。
</Accordion>

<Accordion title="待办数量到上限了">
单实例最多 **5000** 条，请先清理已完成的。
</Accordion>
</Accordions>

## 压缩与解压

<Accordions>
<Accordion title="「只能解压 zip 文件」">
目前只支持 `.zip`，rar / 7z 等需要先在本地转换。
</Accordion>

<Accordion title="「ZIP 文件超出解压大小限制」">
被解压的 zip 本身超过 `extractMaxZipMB`（默认 128MB），可在「设置 → 权限」调整。
</Accordion>

<Accordion title="「ZIP 解压后总大小超出限制」">
超过 `extractMaxTotalMB`（默认 512MB，在「设置 → 安全 → 解压保护」调整）。超限时会**中止并清理已写出的内容**。
</Accordion>

<Accordion title="「ZIP 内文件数超出限制」">
超过「最大文件数」（默认 100）。
</Accordion>

<Accordion title="解压出来的文件比原压缩包少">
压缩包里体积过大的单个条目、以及形如 `../` 的越界条目会被**跳过**。
</Accordion>

<Accordion title="「服务端未安装 unzipper 模块」">
后端依赖不完整，重新执行 `pnpm setup`（或 `pnpm -C server install`）并重启。
</Accordion>

<Accordion title="压缩 / 解压进度一直卡着">
进度每 400 毫秒刷新一次；服务端任务状态保留 10 分钟，超时会显示"任务已过期，请重试"。
</Accordion>

<Accordion title="看不到别人正在跑的任务">
默认「作业进度仅创建者可见」是开着的，超管可在「设置 → 安全」关闭它。
</Accordion>
</Accordions>

## 文件转换

<Accordions>
<Accordion title="右键菜单里没有「转换为」">
三种可能：访客（访客永远不能转换）；超管关掉了「设置 → 权限 → 成员权限 → 高级功能 → 文件转换」；
或者这个文件的扩展名当前没有可用的转换（例如 `.docx` 暂不支持）。
</Accordion>

<Accordion title="「转换为」是灰的">
这个文件在**只读映射目录**里 —— 产物没有地方写，只能先复制/下载到普通目录再转。
</Accordion>

<Accordion title="转换报错「服务器上没有可用的中文字体……」（api.fs.convert_no_cjk_font）">
含中文的转换**直接报错**，而不是给你一份满屏 `?` 的 PDF —— 这是有意的。
先去「设置 → 文件转换」看**诊断表**：它会逐条说明每个候选字体为什么被跳过，并允许你直接指定字体路径。
</Accordion>

<Accordion title="明明放了字体还是说缺字体">
按顺序查：

1. **放对地方了吗**：必须是 `data/fonts/`（程序数据目录），或后台「设置 → 文件转换」里填的路径；
2. **格式支持吗**：`.ttf` / TrueType 的 `.ttc` / CFF 的 `.otf`、`.ttc`（思源黑体、Noto Sans CJK 都属于 CFF）都支持；
   CFF2 变量字体与 name-keyed 的 `.otf` 不支持，会明确提示；
3. **缓存**：点后台的「重新探测」（或等 1 分钟），不需要重启；
4. **看诊断**：后台那一页会列出"这个文件被跳过的具体原因"。
</Accordion>

<Accordion title="PDF 里的图片只有一行 [图片: alt]">
图片**会被真的嵌进 PDF**（与预览一致）。只有这几种情况会退化成占位文字：
图片不在 `.md` 同目录或子目录里、是 `http(s)` 外链（服务端不为此发起外部请求）、格式不支持、超过 24MB。
</Accordion>

<Accordion title="PDF 排版和预览不完全一样">
2.1.0 起由 `scripts/markdown-parity-test.mjs` 逐行比对预览渲染结果与 PDF 内容，保证**文字逐字一致**
（字体本身不同；CFF 字体的字形细节可能略有差异）。
</Accordion>

<Accordion title="转换的产物文件名多出 (1)">
同名文件已存在：产物永不覆盖已有文件，自动改成 `名称 (1).ext`。
</Accordion>

<Accordion title="「文件过大（…），转换上限 …」">
Markdown 4MB / 图片 32MB；更大的内容请先在本地处理。
</Accordion>

<Accordion title="PDF 被截断了">
超过 400 页会截断，任务提示里会说明。
</Accordion>

<Accordion title="「服务端未安装 sharp，图片转换不可用」">
图片互转依赖 `sharp`。单文件 exe 发布版不含原生模块，属已知限制；`md` 的两种转换不受影响。
</Accordion>

<Accordion title="「转换任务过多，请稍后再试」">
同时最多 4 个转换、排队 32 个；稍等几秒重试即可。
</Accordion>

<Accordion title="JPG 转成 PNG 后文件反而更大">
正常：PNG 是无损格式，照片类内容压不过 JPEG。
</Accordion>
</Accordions>

## 链接下载器（多线程下载器）

<Accordions>
<Accordion title="菜单里看不到这个功能">
访客没有此功能；成员需要超管开启「高级功能 → 多线程下载器」。
</Accordion>

<Accordion title="「不允许下载内网地址（…）」">
默认禁止访问内网 / 回环 / 链路本地 / 云元数据地址（防 SSRF）。确有需要时由超管在「设置 → 安全」打开对应开关，或用 `DOWNLOAD_URL_ALLOW_HOSTS` 只放行指定主机。
</Accordion>

<Accordion title="「仅支持 http/https 链接」">
其他协议不支持。
</Accordion>

<Accordion title="「下载链接不能包含用户名或密码」">
`http://user:pass@host/` 这种形式会被拒绝。
</Accordion>

<Accordion title="「下载失败: HTTP 403」">
目标站点拒绝服务端的 User-Agent（`ZeroShadow/1.0`）或要求登录。这个工具只能抓公开直链。
</Accordion>

<Accordion title="「连接超时」">
60 秒超时；确认服务器能出网访问该地址。
</Accordion>

<Accordion title="「下载未完成（网络中断）」">
实际收到的字节数不到 `Content-Length` 的 95%，服务端会删除残缺文件并报错，重试即可。
</Accordion>

<Accordion title="文件太大被拒">
`downloadUrlMaxMB` 默认 4096MB，可在「设置 → 权限」调整。
</Accordion>
</Accordions>

## WebDAV 挂载

### Windows 资源管理器挂不上？按这个顺序查

| # | 检查项 | 怎么做 |
|:--|:--|:--|
| 1 | **入口用错了吗** | 资源管理器的「映射网络驱动器」**只支持 SMB**，填 `https://…` 必然失败。要用「此电脑」右键 → **添加一个网络位置**，或命令行 `net use Z: \\主机@SSL\dav` |
| 2 | **地址写法对不对** | HTTPS 默认端口 `\\主机@SSL\dav`；**非 443 端口** `\\主机@SSL@8443\dav`；纯 HTTP `\\主机@端口\dav`。后台 WebDAV 卡片里的「资源管理器地址」就是按你当前访问方式算好的 |
| 3 | **服务器开了吗** | 「设置 → 公网 → WebDAV」勾「启用 WebDAV」并保存（实时生效）；未开启时挂载点回 404 JSON |
| 4 | **证书受信任吗**（HTTPS） | 自签名证书会让 WebClient 直接放弃（「输入的文件夹似乎无效」）。把证书或其根 CA 装进「受信任的根证书颁发机构」；**浏览器里点"继续访问"不算** |
| 5 | **HTTP 下用了 Basic** | Windows 默认只允许 HTTPS 上用 Basic：`reg add HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters /v BasicAuthLevel /t REG_DWORD /d 2 /f`，再 `net stop webclient && net start webclient`（明文传密码，仅限可信内网） |
| 6 | **WebClient 服务没起来** | `net start webclient`（默认手动启动，被组策略禁用时会完全静默失败） |
| 7 | **账号用了超管** | WebDAV 不接受超级管理员账号（回 403，但资源管理器只会再弹一次密码框）。用团队成员账号 |
| 8 | **改过密码** | `net use * /delete /y` 清掉缓存凭据后重新挂载 |
| 9 | **大文件拷不进去** | Windows WebClient 默认单文件上限 **50 MB**：`reg add …\Parameters /v FileSizeLimitInBytes /t REG_DWORD /d 4294967295 /f`，再重启 webclient 服务 |
| 10 | **还是不行** | 「设置 → 日志与指标」筛 `webdav`：`webdav_auth_fail` = 凭据不对，`webdav_error` = 请求到了服务端但出错；**一条都没有** = 请求没到服务（地址 / 端口 / 证书 / 服务未启动） |

### 其它常见现象

<Accordions>
<Accordion title="客户端提示 404 / 打开地址看到一段 JSON">
WebDAV **默认关闭**。去「设置 → 公网 → WebDAV」打开并保存（实时生效，不用重启），或 `.env` 里设 `WEBDAV=1` 后重启。
</Accordion>

<Accordion title="改了挂载路径后旧地址连不上">
路径是**立即生效**的，客户端里的地址要同步改；后台卡片上的两个地址是当前正确的。
</Accordion>

<Accordion title="填了超管账号，提示 403">
WebDAV 不接受超级管理员账号（Basic 凭据每个请求都会重发）。建一个团队成员账号来挂载。
</Accordion>

<Accordion title="用浏览器打开 /dav/ 提示 401">
正常：DAV 只认 HTTP Basic，不认浏览器的 Cookie 会话。请用资源管理器 / Finder / RaiDrive / rclone 连接。
</Accordion>

<Accordion title="新建目录返回 409">
上级目录不存在。`MKCOL` 要求父目录先存在（不会替你递归建整条链）。
</Accordion>

<Accordion title="PROPFIND 返回 403（propfind-finite-depth）">
服务端拒绝"一次扫描整棵树"的请求（RFC 形式的标准拒绝），正常客户端会自动退回 `Depth: 1`。脚本里写死 `infinity` 的改成 `1`。
</Accordion>

<Accordion title="复制 / 移动返回 502">
`Destination` 头指向了别的主机。用**当前挂载地址**作为目标；反代后面带不同端口不会再被误判。
</Accordion>

<Accordion title="覆盖保存提示 412 / 文件已被他人修改">
2.1.0 之前 `PROPFIND` 给出的 ETag 与 `PUT` 比对的值算法不同，凡是从列表里拿到 ETag 再保存的操作都会被判冲突。现已统一，升级后重新挂载一次即可。
</Accordion>

<Accordion title="改了成员密码后挂载盘立刻掉线">
预期行为：凭据校验结果缓存 60 秒，但会校验 `tokenVersion`，改密码 / 禁用立即失效。用新密码重连。
</Accordion>

<Accordion title="Office 提示锁定却仍能被别人改">
`LOCK` 只是礼节性的；真正的并发保护靠版本比对（编辑器保存时 409）。见[安全设计](/docs/zeroshadow/security/design)。
</Accordion>
</Accordions>

## 日志与排查

<Accordions>
<Accordion title="看最近发生了什么">
「设置 → 日志与指标」，可按级别、天数与「仅审计事件」筛选，最新在最上面；
同一页还有 CPU / 内存曲线与请求指标（QPS、状态码分布、慢请求）。
</Accordion>

<Accordion title="看原始日志文件">
`data/logs/zs-YYYY-MM-DD.log`，每行一个 JSON。
</Accordion>

<Accordion title="想让控制台干净一点">
`.env` 里设 `NOLOG=true`（或 `-nolog` 启动参数），日志仍会写文件。
</Accordion>

<Accordion title="排查隧道问题">
「设置 → 公网」的输出区会显示实际执行的 `ssh` 命令与进程输出。
</Accordion>

<Accordion title="排查接口问题">
控制台每个请求都会打印 `[REQ] 方法 路径 host=… ip=… ua=…`（静默模式下不打印）。
</Accordion>

<Accordion title="判断限流是否在误伤">
看日志里的 IP 是否都是 `127.0.0.1`，是的话说明 `TRUST_PROXY` 没配对。
</Accordion>

<Accordion title="服务出过未捕获异常吗">
在日志里搜事件名 `unhandled_rejection` / `uncaught_exception`——进程级兜底捕获到的异常会记这两个事件
（服务**只记录、不退出**，所以看到它们不等于服务重启过）。
</Accordion>
</Accordions>

## 数据与备份

<Accordions>
<Accordion title="需要备份的三样东西">
1. `data/files/`（或 `FILES_DIR` 指向的目录）——所有文件；
2. `.env` 与 `data/config.json`——配置；
3. `data/users.json`——成员账号。

如果还希望迁移后小组、待办与头像一并保留，再加上 `data/groups.json`、`data/todos.json`、`data/avatars/`
（`data/backups/` 只是自动快照，可带可不带）。
</Accordion>

<Accordion title="改坏了配置能回滚吗">
能。服务端自己留了一份"后悔药"：**每次覆盖写入 `config.json` / `users.json` / `groups.json` / `todos.json`
之前自动快照**，并且每天做一次全量快照，存在 `data/backups/`，每个文件默认保留 20 份
（`backupKeep`，可在「设置 → 数据与保留」里调）。在「数据与保留 → 数据备份与回滚」里点「回滚」即可。
</Accordion>

<Accordion title="data/.jwt-secret 要不要一起备份">
`data/.jwt-secret` 一起备份可以让迁移后登录状态不中断；不备份也没关系，重新生成后大家重新登录一次。
</Accordion>

<Accordion title="恢复出厂设置">
停服务 → 删除 `data/config.json` → 启动。所有后台设置会回到默认值（文件和账号不受影响）。
</Accordion>

<Accordion title="彻底重来">
停服务 → 删除整个 `data/` 与 `.env` → 启动。会重新生成超管密码与所有运行时数据，
**`data/files/` 里的文件也会一起消失**，操作前请确认已备份。

<Callout type="error" title="会连数据一起删掉">
`data/files/` 是网盘文件的真实根目录，删掉 `data/` 就等于删掉所有文件。
</Callout>
</Accordion>
</Accordions>

## 还是没解决？

收集这几项信息，问题基本就能定位了：

1. 启动时的完整控制台输出（含版本与端口那一行）；
2. 出问题的操作路径：用的什么角色、在哪个页面、点了什么；
3. 「设置 → 日志与指标」里对应时间点的记录（可以用关键词筛一下）；
4. 服务端环境：操作系统、Node 版本、是否通过隧道 / 反代访问、`TRUST_PROXY` 的取值；
5. 浏览器控制台（F12）里的报错与失败请求的响应内容。

排查完之后，如果确认是配置问题，见 [配置参考](/docs/zeroshadow/admin/configuration)；如果怀疑是权限口径问题，见 [权限与角色](/docs/zeroshadow/guide/permissions)。
