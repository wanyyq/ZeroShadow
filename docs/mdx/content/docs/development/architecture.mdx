## 技术底座

| 部分 | 技术 | 关键约定 |
|:--|:--|:--|
| 后端 | Node.js（**ESM**，`server/package.json` 里 `"type": "module"`）+ Express 4 | 全部使用 `import` / `export`，无构建步骤即可运行 |
| 前端 | React 19 + TypeScript + Vite 8 + Tailwind CSS v4 | 路径别名 `@` → `web/src`；组件用 shadcn CLI 生成 |
| UI 组件底座 | `@base-ui/react`（**不是 Radix**） | `web/src/components/ui/*` 都建立在它之上 |
| 图标 | 本地 `lucide.min.js` + `<i data-lucide>` 占位，由 `createIcons()` 渲染 | 不用 CDN，内网离线可用 |
| 动画 | 本地 `gsap.min.js` + CSS 过渡 | 列表入场与页面入场动画（「减少动画」偏好会关掉它们） |
| 文本编码 | `iconv-lite` 0.7.3（MIT） | 在线编辑器的编码识别与写回；**服务端唯一为编解码引入的依赖**，其余模块都是手写的 |
| 打包 | Vite（前端）/ esbuild + pkg（后端） | esbuild 先把 ESM 打成 CJS，再由 pkg 生成可执行文件 |

根 `package.json` **没有依赖**，只是一个脚本入口；依赖分别装在 `server/` 与 `web/` 两个子项目里，
各自有独立锁文件（`lockfileVersion: '9.0'`）。

`server/package.json` 的 `dependencies` 就是后端全部第三方运行时依赖，共 8 个：
`archiver`、`bcryptjs`、`busboy`、`cookie-parser`、`express`、`iconv-lite`、`jsonwebtoken`、`unzipper`。
完整清单（含版本与许可证）在「软件开源信息」页（`/about`）与
[使用手册](/docs/zeroshadow/guide/manual) 的「软件开源信息页」一节。

<Callout type="warn" title="依赖底座容易被误判">
网上大量 shadcn 代码片段是按 **Radix** 的 API 写的，而本项目的 `ui/*` 组件底座是
`@base-ui/react`。直接把 Radix 写法的片段粘进来通常跑不起来，需要按 Base UI 的 API 改写。
</Callout>

## 后端请求处理链

`server/index.js` 的中间件顺序：

```text
关闭 x-powered-by
  → （可选）app.set("trust proxy", env.trustProxy)
  → GET /ping                     健康检查，纯文本 pong
  → 请求日志中间件                打印 [REQ] 方法 路径 host ip ua（静默模式下跳过）
  → 安全响应头中间件              nosniff / SAMEORIGIN / no-referrer / Permissions-Policy
  → cookieParser
  → socket.setNoDelay(true)       缓解隧道代理场景的缓冲问题
  → metricsMiddleware             请求指标采集（异常一律吞掉，不阻塞请求）
  → createWebdavRouter()          WebDAV（命中挂载点且未启用时自回 404）
  → attachAuth                    解析 Cookie 得到 req.auth = { role, username, userId }
  → attachContext                 解析小组上下文，算出 req.group / req.groupId / req.perms
  → /api 上的 csrfGuard           非 GET/HEAD/OPTIONS 校验自定义头与来源
  → /api/fs/save-file 专用 json    limit = SAVE_FILE_MAX_BYTES（16MB）
  → express.json({ limit: "1mb" }) 其余接口仍是 1MB
  → GET /api/meta
  → /api/auth  /api/fs  /api/admin  /api/avatars  /api/todos  /api/groups
  → /api 兜底 404 JSON
  → express.static(WEB_DIST) + 非 /api 的 SPA fallback（带应用外壳 CSP）
  → 统一错误处理（5xx 记日志，只回"服务器内部错误"）
```

<Callout type="warn" title="两条顺序不能动">
1. **body parser 必须在 `attachAuth` / `csrfGuard` 之后**：否则任何**未登录**者都能强迫服务把
   16MB 请求体解析成 JSON（`/api/fs/save-file` 是单独放宽的端点），几个并发请求就能把单核打满。
2. **`createWebdavRouter()` 必须在 body parser 之前**：WebDAV 的 `PUT` 是原始请求体，被
   `express.json()` 读完后 `req.pipe(ws)` 只会写出 0 字节并以 204 成功返回——"保存成功"但文件被清空。
   它也必须排在静态托管与 SPA fallback 之前，否则 `/dav/` 会被 fallback 吞掉、返回前端首页。
   挂载点可在后台改，因此**无条件挂载**，是否启用由中间件自己判断。
</Callout>

启动时会：自检并隔离损坏的数据文件（`integrity.js`，同时清空 `data/tmp/` 残留）
→ 重载配置 / 成员 / 小组 / 待办 → 建目录 → 重建头像索引（顺手删掉尺寸或格式不合规的文件）→ 做一次每日快照；
服务监听后启动指标采样（每分钟一次）与过期日志清理，并每 6 小时再清理一次日志 + 做每日快照
（同一个维护定时器里还跑一遍回收站的 `sweepTrash`）；
若隧道已启用则拉起隧道。
退出信号（`SIGINT` / `SIGTERM`）会先停隧道与指标再关服务，兜底 3 秒强制退出。

<Callout type="info" title="请求体上限：save-file 单独放宽到 16MB">
`/api/fs/save-file`（在线编辑保存）挂了一个单独的 `express.json({ limit: SAVE_FILE_MAX_BYTES })`，
`SAVE_FILE_MAX_BYTES = 16 * 1024 * 1024`；body-parser 解析成功后会标记 `req._body`，
后面的全局 `express.json({ limit: "1mb" })` 不会重复解析，**其余接口仍然是 1MB**。
超限时该接口自己先判字节数并返回 413（文案带实际大小与 16MB 上限）。
</Callout>

<Callout type="info" title="进程级兜底：记录但不退出">
`server/index.js` 末尾注册了 `unhandledRejection` 与 `uncaughtException`：
两者都只把原因（异常还带 `stack`）写进日志，**刻意不退出进程**——
本项目没有进程管理器（无 Docker / 无 pm2），退出即局域网内所有人同时断线。
理由很具体：一次失败的上传清理（例如磁盘写满后连 `rm` 也失败）不该升级成全局断线。
日志事件名是 `unhandled_rejection` 与 `uncaught_exception`，可在「设置 → 日志与指标」里查。
</Callout>

## 权限是怎么判的

两级中间件（`server/src/auth.js`）：

```js
requireRole("superadmin")   // 按角色
requirePerm("compressZip")  // 按当前请求的 req.perms 里的权限点
```

`effectivePerms(role, group)`（`server/src/config.js`）是**唯一的权限真相来源**：
把 `config.json` 里的 `memberPerms` / `guestPerms` 与角色叠加，算出最终布尔表
（例如成员的写类权限都要 `fileWrite` 为真）。前端拿到的 `perms` 就是它的输出。

登录之后每个请求还会经过 `attachContext`（`server/src/context.js`）：

```text
X-ZS-Group: <小组 id>  或  ?group=<小组 id>
  → resolveGroupContext(req)   校验小组存在、且调用者属于该小组；无效则回退"默认"
  → req.perms = effectivePerms(req.auth.role, req.group)
```

**小组权限只能收窄**：`effectivePerms` 会把 `memberPerms` 与小组 `perms` 逐项取与（`base[key] && !!groupPerms[key]`）。
超管直接返回固定全开的权限表，不参与小组收窄；访客没有小组上下文，只受 `guestHiddenPaths` 影响。
`requirePerm` 读的是 `req.perms`，所以小组切换对所有接口**立即生效**，不需要重新登录。
可见范围则由 `isVisibleForContext` 统一判定（黑名单优先、白名单为空即不限制）。
小组的可见性在**递归操作里也必须逐层应用**：打包 / 压缩走 `zipVisibility()`，
否则会出现"列表里看不到、zip 里却能拿到"。

失败时的状态码语义（前端据此区分"要登录"与"没权限"）：

| 中间件 | 访客 | 已登录但无权限 |
|:--|:--|:--|
| `requireRole` | `401` 请先登录 | `403` 没有权限执行此操作 |
| `requirePerm` | `401` 请先登录 | `403` 没有权限执行此操作 |

### 新增一个权限点的完整步骤

<Steps>
<Step>
### 加默认值

`server/src/config.js`：在 `DEFAULTS.memberPerms`（或 `guestPerms`）里加默认值。
</Step>
<Step>
### 让它生效

同文件 `effectivePerms()`：给对应角色返回这个键。
</Step>
<Step>
### 保护路由

目标路由加上 `requirePerm("你的键")`。
</Step>
<Step>
### 补前端类型

`web/src/lib/types.ts`：在 `Perms` 接口里加字段。
</Step>
<Step>
### 补未登录兜底

`web/src/state/auth.tsx`：在 `GUEST` 兜底常量里补一个默认值（未登录时前端要用）。
</Step>
<Step>
### 加后台开关

`web/src/pages/settings/index.tsx`：用 `permItem(...)` 在「权限」页加一个开关。
</Step>
<Step>
### 允许小组收窄（可选）

`web/src/pages/settings/groups-section.tsx`：把新键加进对应分组的 `PERM_GROUPS` 条目
（它能选中哪些键由 `MEMBER_PERM_KEYS` 决定，但分组与中文名要手工补上），
小组编辑器里才会出现这个开关；属于写操作的还要加进 `WRITE_PERM_KEYS`，
这样「文件操作总开关」关闭时它会跟着置灰。
</Step>

## 数据存放

| 数据 | 位置 | 生命周期 |
|:--|:--|:--|
| 服务配置 | `data/config.json` | 启动时读入内存，后台修改后原子写回 |
| 成员账号 | `data/users.json` | 同上；密码为 bcrypt 哈希 |
| 小组 | `data/groups.json` | 同上；后台「小组」页写回，成员被删除时自动移除 |
| 团队待办 | `data/todos.json` | 同上；删除小组时该组待办转为全体可见 |
| 头像 | `data/avatars/<owner>.webp` | 上传即原子替换；启动时扫描，尺寸 / 格式不合规的文件会被删除 |
| 回收站 | `data/trash/<时间戳>-<随机>/`（`meta.json` + `content`） | 删除时移入；启动时与每 6 小时的维护定时器按 `trashRetentionDays` 清理 |
| 数据快照 | `data/backups/<文件名>/<时间戳>-<随机>.json` | 覆盖写前 + 每天一次；每个文件保留 `backupKeep` 份 |
| 系统指标 | `data/metrics/zs-*.jsonl`（即 `data/metrics/zs-YYYY-MM-DD.jsonl`） | 每分钟一条；保留 `metricsRetentionDays` 天 |
| 请求指标 | **内存** 环形桶 + 最近 50 条慢请求 | 窗口由 `metricsMemMinutes` 决定（默认 15 分钟），重启清零 |
| 会话密钥 | `data/.jwt-secret` | 首次生成后复用；删除即让全部会话失效 |
| 长任务进度 | **内存** `Map` | 10 分钟 TTL，每分钟扫描清理 |
| 登录失败计数 | **内存** `Map` | 重启清零 |
| 限流计数 | **内存** `Map` | 重启清零 |
| 日志 | `data/logs/zs-*.log` | 按天一个 JSONL 文件；超过 `logRetentionDays` 自动清理 |

写入用 `store.js` 的 `withLock` + `writeJsonAtomic`（写临时文件再重命名），
避免并发覆盖和半个文件；**覆盖写之前会自动把旧内容快照进 `data/backups/`**（`backup.js`），
所以后台改错配置也能回滚。

<Callout type="warn" title="config.json 一旦存在，就会永久覆盖代码里的默认值">
`config.js` 启动时是 `deepMerge(structuredClone(DEFAULTS), readJsonSync(CONFIG_FILE, {}))`。
只要 `data/config.json` 存在，里面记录的值就优先，**日后升级代码也拿不到新的 `DEFAULTS`**。
所以要改默认体积上限之类的东西时，光改代码不够，还得顾及已存在的 `config.json`。
反过来，若某个实例从没在后台改过配置，就不会有 `config.json`，纯用代码默认值。
</Callout>

## 长任务模型

`compress` / `extract` / `download-url` 三个接口都是**先返回 `jobId` 再后台执行**：

```text
POST /api/fs/compress        → { jobId }
   ↓ 前端每 400ms 轮询
GET /api/fs/compress/status?job=<jobId>  → { state, percent, processed, total, processedBytes, error }
```

- 任务对象里有 `createdBy`，默认只有创建者与超管能查询（`jobStatusOwnerOnly`）；
- 状态机：`running` → `done` / `error`；任务被清理后查询返回 `state: "gone"`；
- 失败时（含解压中途超限）会清理临时产物——解压还会**整个删掉半成品目录**，
  压缩会**删掉已经写出的半个 `.zip`**，并如实把状态置为 `error`（而不是 `done`）。

## 在线编辑的编码处理（`server/src/encoding.js`）

在线编辑器的编解码**全部收在服务端**这一个模块里，前端只拿最终文本：

| 导出 | 作用 |
|:--|:--|
| `EDITOR_ENCODINGS` / `encodingList()` | 支持的编码表（id / label / bom），前端下拉框直接用 |
| `detectEncoding(buf)` | 识别编码，返回 `{ encoding, bom, confident }`；`confident: false` 表示是靠打分猜的，前端会提示用户手动切换 |
| `decodeBuffer(buf, encoding)` | 解码并剥掉 BOM |
| `detectEol(text)` / `applyEol(text, eol)` | 换行风格探测与还原（读取时统一成 `\n`，保存时按选择写回 `crlf` / `lf` / `cr`） |
| `encodeText(text, encoding)` | 编码并**回读比对**，返回 `{ buffer, unmappable }`；目标编码表示不了的字符由调用方报 400 |
| `looksBinary(buf)` | 二进制判定（NUL 字节，或控制字符比例 > 10%） |
| `EDITOR_MAX_BYTES` | 单次读取上限 8 MB |

识别的判定顺序（每一步都有理由，改之前请先读懂）：

1. **BOM**：`utf8bom` / `utf16le` / `utf16be`，最确定，直接采信；
2. **无 BOM 的 UTF-16**：按 16 位单元落在「可打印 ASCII / CJK / 常用标点」里的比例打分，
   两种字节序差距 > 0.1 才认（只看 NUL 字节是不够的——纯中文的 UTF-16 一个 NUL 都没有）；
3. **严格 UTF-8**：`TextDecoder("utf-8", { fatal: true })` 不抛异常就认定 UTF-8（含 NUL 时跳过这一步）；
4. **逐个候选编码打分**：`gb18030` / `big5` / `shift_jis` / `euc-kr` / `windows-1252` / `iso-8859-1`，
   用「命中常用字的数量 ×3 − 替换字符 ×100 − 控制字符 ×20」排序取最高分。
   只数替换字符是不够的：GB18030 几乎能解码任意字节序列，拿它去解 Big5 文件往往一个替换字符都没有，但内容是错的；
5. **候选都不像正常文本时**才回头采信第 2 步的 UTF-16 结果（顺序很关键：
   Shift_JIS 的假名字节按 UTF-16BE 读会落在汉字区，让候选编码先表态才不会把日文误判成 UTF-16）。

写回时的两条硬约束：**BOM 要按编码补上**（UTF-16 没有 BOM 就无法区分字节序），
**表示不了的字符宁可拒绝也不静默写成 `?`**（`encodeText` 回读比对，最多列出 12 个字符交给前端提示）。

## 想加一个接口

```js
// server/src/routes/fs.js
router.post("/my-op", requirePerm("editFiles"), rateLimit, async (req, res, next) => {
  try {
    const { abs, rel } = resolveSafe(req.body?.path)   // 一定走 safety.js
    blockSoft(rel)                                     // 只读映射目录要拦住
    // ...业务
    info("my_op", { msg: rel, ...actor(req) })         // 记日志
    res.json({ ok: true })
  } catch (err) { next(err) }
})
```

要点：**路径一律用 `resolveSafe` / `resolveAny` 解析**（自带穿越防护），
写操作要先 `blockSoft`，需要限流就挂 `rateLimit`，错误统一交给 `next(err)`（`httpError(status, msg)` 造错误）。
涉及路径的端点还应当调用 `assertContextVisible(req, rel)`，让小组 / 默认可见范围对读写都生效
（`attachContext` 已经全局挂好，`req.perms` / `req.group` 随取随用）。
新路由文件要在 `server/index.js` 里 `app.use("/api/xxx", xxxRoutes)` 挂上。
前端在 `web/src/lib/api.ts` 里加一个薄封装即可。

## 内容版本与并发编辑（`server/src/version.js`）

版本串是 `<mtimeMs>-<size>-<内容哈希>`，同时用在三处：

| 用处 | 位置 |
|:--|:--|
| 在线编辑器的乐观并发控制 | `GET /api/fs/file` 返回 `baseVersion`；`POST /api/fs/save-file` 校验它 |
| HTTP `ETag` | `GET /api/fs/download`（普通下载接口），让客户端能用 `If-Match` / `If-None-Match` |

<Callout type="warn" title="WebDAV 的 ETag 是另一个算法">
DAV 的 ETag 是 `"s-<mtimeMs>-<size>"`（`webdav.js` 的 `davEtag()`），因为 `PROPFIND` 一次要列几千条、
不可能逐条算内容哈希。**PROPFIND 的 `getetag`、`GET`/`HEAD` 的 `ETag`、`PUT` 的 `If-Match`
必须是同一个函数产生的** —— 早期版本给了三套不同的值，于是"从列表里拿 ETag 再保存"永远返回 412。
</Callout>

**为什么不能只用 `mtime`**：Windows 的 mtime 粒度可达秒级（FAT 更粗），
同一秒内的两次保存用 `mtime` 区分不开，会把真实冲突漏判。所以必须带上内容哈希。
哈希用 sha1 是因为这里只做"内容变没变"的指纹，不是密码学用途，短且快。

改动这一块时注意：`versionOf()` 必须保持一致 —— 编辑器认的版本和 WebDAV 客户端认的
`ETag` 如果算法不同，就会出现"浏览器里保存提示冲突、但用 DAV 客户端却能写进去"这种怪事。

## 回收站（`server/src/trash.js`）

- 布局：`data/trash/<时间戳>-<随机>/meta.json` + `content`；
- **必须放在 `data/` 下**：放进 `FILES_DIR` 会让它出现在网盘根目录，被列目录、被搜索、
  被打包，甚至能按路径被访客下载；
- 移入用 `rename`（同盘原子）；跨设备 `EXDEV` 时退化为"先复制成功、再删原件"；
- 元数据用 `store.js` 的原子写；
- **目录建不出来不能抛异常**：`trash.js` 顶部的 `ensureDir()` 会捕获失败并置标志，
  写操作退回"直接删除"。早期版本在模块加载时直接 `mkdirSync`，`data/` 只读会让
  **整个服务起不来**（连登录界面都打不开）；
- 清理时机：服务启动时 + 每 6 小时的维护定时器（`sweepTrash`），天数取
  `config.trashRetentionDays`。

## 文件详细信息（`server/src/fileinfo.js`）

「详细信息」对话框里除基础字段以外的内容全部来自 `GET /api/fs/details`，实现集中在这一个模块：

| 能力 | 做法 |
|:--|:--|
| 签名识别 | 头 64KB 内按固定偏移比对的签名表，加几个需要上下文的特例：`ftyp` 品牌（MP4 / MOV / HEIC / AVIF / CR3）、RIFF 子类型（WAV / AVI / WebP）、用 ZIP 内部条目名区分 docx / xlsx / pptx / apk / jar / epub、偏移 257 的 `ustar`、MPEG-TS 的同步字节 |
| 图片尺寸 | PNG 的 `IHDR`、JPEG 逐段扫 `SOF`、GIF / BMP / WebP（`VP8 ` / `VP8L` / `VP8X`）、PSD、ICO |
| EXIF | 自带的 TIFF / IFD 解析器：IFD0、ExifIFD（`0x8769`）、GPS IFD（`0x8825`），按类型读取后格式化成中文（`1/125 秒`、`f/2.8`、GPS 十进制度） |
| 文档属性 | PDF 的 Info 字典（**头尾各 64KB 都搜**，兼容 Info 在文件尾的写法）、OOXML 的 `docProps/core.xml` 与 `app.xml`（就地定位并解压一个 ZIP 条目，用内置 `zlib.inflateRawSync`） |
| 媒体信息 | MP4 / MOV / M4A 沿顶层 box 走到 `moov` 再读 `mvhd`（**不能只搜开头**：未做 faststart 的文件 `moov` 在末尾且可能大于 64KB）、WAV 的 chunk、FLAC 的 `STREAMINFO`、ID3v2 帧 |
| 文本信息 | 复用 `encoding.js` 的探测；**只有签名判定为文本时**才统计编码与行数，否则 MP3 的 ID3 区会被误认成 UTF-16 文本 |
| 哈希 | `fs.createReadStream` + 三个 `crypto` Hash 流式计算；其中 sha1 的 base64url 与 `version.js` 的内容哈希同源，所以 `contentVersion` 和 `baseVersion` 是同一个串 |

三条纪律：

- **不整文件读进内存**：解析只读头尾各 64KB，哈希流式计算且限 64MB，文本统计限 8MB；
- **分段容错**：每一段都包在自己的 `try/catch` 里，解析失败只让那一段为 `null`，
  绝不能因为一个坏 EXIF 就返回 5xx；
- **不新增配置项**：上限都是模块内常量（`HEAD_BYTES` / `HASH_MAX_BYTES` / `TEXT_SCAN_BYTES`），
  不为一次详情点击引入需要文档化的新开关。

## 文件转换（`server/src/convert/`）

v2.1.0 引入。路由只负责鉴权、路径校验、读写与进度，具体能转什么全由这里的注册表决定：

| 文件 | 职责 |
|:--|:--|
| `index.js` | 内置转换器的**注册点**（`registerConverter(...)`），也是对外出口 |
| `registry.js` | 转换器注册表：校验定义、按扩展名查表、生成下发给前端的清单 |
| `queue.js` | 并发闸门：同时最多 4 个转换在执行、32 个排队，队列满回 503（`api.fs.convert_busy`） |
| `markdown.js` | 手写 Markdown 解析器（块级 + 行内）与纯文本渲染 |
| `converters/md-to-txt.js` | Markdown → 纯文本 |
| `converters/md-to-pdf.js` | Markdown → PDF（A4） |
| `converters/image.js` | PNG → JPG、JPG → PNG（走 `sharp`，可降级） |
| `pdf/font.js` | 找一个能排中文的系统字体，提供度量视图 |
| `pdf/truetype.js` | 只读 TrueType 解析 + 子集化（保留原始字形号，供 Identity-H 内嵌） |
| `pdf/layout.js` | 块列表 → 页面操作（折行、分页、表格、页脚、链接矩形） |
| `pdf/document.js` | 最小 PDF 1.7 写出器（对象 / xref / trailer / 内容流 / 字体对象） |

三个设计取舍：

- **零新增依赖**：PDF 写出与 TrueType 子集化都是自己写的。后端依赖清单刻意精简
  （见 [技术底座](#技术底座) 那张表），为一个导出功能引入 PDF / 字体库不划算；
- **注册表驱动**：加一种格式不需要改路由、也不需要改前端——右键菜单的「转换为」子项按
  `GET /api/fs/convert/targets` 返回的清单动态渲染。图片转换复用项目已有的 `sharp`；
  单文件 exe 里没有 `sharp` 时返回 **501**（`api.fs.convert_no_sharp`），与缩略图是同一套降级思路。
- **为什么需要 `queue.js`**：图片转换走原生解码、PDF 排版是纯 CPU 循环，两者都会把单个核心吃满。
  网盘是"一个人的机器给全组人用"，没有配额也没有进程管理器，所以转换必须自己限并发
  （与缩略图队列同一思路，参数按"用户主动发起"放宽到 4 / 32）。新加的转换器**自动**被这个闸门保护。

<Callout type="info" title="接口、错误码与上限">
三个接口（`targets` / `convert` / `status`）的参数、返回结构与全部 `errorKey` 见
[API 参考](/docs/zeroshadow/api/reference)。它们都挂在 `convertFiles` 权限点下，
`POST /api/fs/convert` 另外要求对源文件有读权限（`preview` 或 `downloadFile`）。
它和压缩 / 解压共用同一套作业模型（`createJob` / `patchJob` / `finishJob` / `failJob`），
只是任务状态里多两个字段：`notes`（补充提示，例如字体缺字已用 `?` 代替）与 `output`（产物相对路径）。
</Callout>

## 如何新增一种转换

四步，全在服务端：

1. **写模块**：在 `server/src/convert/converters/` 下新建一个 `.js`，导出一个（或几个）转换器对象；
2. **注册**：在 `server/src/convert/index.js` 里 `import` 进来并 `registerConverter(你的转换器)` 一次
   ——数组顺序即右键菜单里的显示顺序，定义写错会**在启动时就抛错**，而不是等用户点了菜单才 500；
3. **补译文**：给它的 `labelKey` 在 `web/src/locales/<语言>/convert.json` 里补上译文
   （不补也能用，会显示 `label` 里的中文兜底）；
4. **补断言**：在 `scripts/convert-test.mjs` 里加一条（`node scripts/convert-test.mjs` **不需要起服务**，
   产物写到系统临时目录）。

转换器对象的字段（`registry.js` 的 `registerConverter` 会逐个校验）：

| 字段 | 必填 | 说明 |
|:--|:--|:--|
| `id` | 是 | 唯一标识，会出现在接口里（`POST /api/fs/convert` 的 `target` 传它） |
| `from` | 是 | 源扩展名数组，小写、不带点 |
| `to` | 是 | 目标扩展名，小写、不带点——决定产物文件名 |
| `label` | 否 | 中文兜底文案；缺省时由 `from` / `to` 拼出来 |
| `labelKey` | 否 | i18n 键，如 `ui.convert.md_pdf` |
| `input` | 否 | `"text"` = 先按识别出的编码解码，再把 `text` 交给 `run`；`"buffer"`（默认）= 传原始字节 |
| `maxBytes` | 是 | 源文件上限（字节），超过直接 413、不进转换 |
| `run` | 是 | `async (ctx) => ({ data: Buffer, notes?: string[] })` |

`run` 拿到的 `ctx` 是 `{ text?, buffer?, name, ext, encoding?, eol?, onProgress(percent), job }`，
返回的 `notes` 会原样进任务状态的 `notes` 数组。

示例（内置的 `converters/md-to-txt.js` 节选，`run` 的换行处理从略）：

```js
export const mdToTxt = {
  id: "md-to-txt",
  from: ["md", "markdown", "mdown", "mkd"],
  to: "txt",
  label: "Markdown → 纯文本",
  labelKey: "ui.convert.md_txt",
  input: "text",
  maxBytes: TEXT_MAX_BYTES,   // 4 MB
  run({ text, eol }) { /* 解析 → 去标记 → 按源文件的换行风格输出 */ },
}
```

新转换器会自动纳入并发闸门（`convert/queue.js`）：同时最多 4 个执行、32 个排队，排队与 503
都由闸门处理，转换器自己**不需要**处理排队；要调这两个数就改 `queue.js` 顶部的常量。

## WebDAV（实验性，`server/src/webdav.js`）

**默认关闭，只能在 `.env` 里用 `WEBDAV=1` 打开**（挂载点由 `WEBDAV_PATH` 决定，默认 `/dav`）。
入口在 `server/index.js`，用 `createWebdavRouter()` 生成中间件：

```js
const webdav = createWebdavRouter()   // 未启用时返回 null
if (webdav) app.use(env.webdavPath, webdav)
```

挂载时机的两个要点，改动时别踩：

1. **必须在 `express.static` 与 SPA fallback 之前挂**。否则 `/dav/` 会被 fallback 吞掉、
   返回前端首页 —— 用户把地址填进客户端后拿到的是网页，非常难排查；
2. **未启用时要显式 404 掉挂载路径**（`index.js` 里那段 `if (!env.webdavEnabled)`）。
   只靠"不挂载"是不够的：`app.get("*")` 会接住一切 GET，于是 `/dav` 仍然返回首页。
   这也是为什么早期症状是"`GET /dav` 返回网页、`PROPFIND /dav` 却 404"这种自相矛盾的现象。

三条**不能改**的安全约束（改了就是漏洞）：

| 约束 | 原因 |
|:--|:--|
| 只认 Basic 认证，**不认 Cookie 会话** | 认 Cookie 就等于给了任意网页一个绕过 CSRF 的后门：它可以用用户浏览器里已有的登录态发 `PROPFIND` / `PUT`，而 DAV 请求不会带 `X-Requested-With`、也走不到 `csrfGuard` |
| **不接受超管账号** | Basic 凭据每个请求都会重复发送，超管密码不该被这样反复暴露。只走 `verifyLogin()`（成员账号、bcrypt） |
| 权限与路径复用 Web 端那套 | `effectivePerms(role, group)` + `normRel` / `resolveAny`；隐藏路径返回 **404**（不是 403，避免探测"这里有什么"） |

方法与权限的对应：`OPTIONS`（免认证，公告能力）、`PROPFIND`→browse、`GET/HEAD`→downloadFile、
`PUT`→fileWrite+upload、`MKCOL`→mkdir、`DELETE`→delete（走回收站）、
`COPY/MOVE`→copy/move（`Destination` 头要按同样规则剥离前缀并重新做穿越校验）、
`LOCK/UNLOCK`→内存锁表（**只是让客户端认为锁生效**，真正的并发保护靠 `version.js`）。

改完请跑一遍 [测试脚本](/docs/zeroshadow/development/testing) 里的 WebDAV 断言
（含"仅带 Cookie 必须 401"这条）。

### 破坏性操作必须二次确认

用 `components/confirm-dialog.tsx` 的 `useConfirm()`（`ConfirmProvider` 在 `App.tsx` 里挂载），

const confirm = useConfirm()
if (!(await confirm({ title: "删除成员？", description: "不可撤销。" }))) return

<Callout type="warn" title="通知必须 portal 到 document.body">

### 图标与动画

- `lib/lucide.ts` 提供 `initLucide()`：在 `DOMContentLoaded`、`load` 与
  **MutationObserver 监听到新节点**时调用 `window.lucide.createIcons()`，
  这样动态渲染出来的图标也能正确显示；
- `animateListIn()` / `animatePageIn()` 用 GSAP 做入场动画；GSAP 不存在时**静默跳过**，不影响功能。
  两者都会先看「设置 → 外观 → 减少动画」（判断 `html[data-reduce-motion="1"]`）**以及系统的 `prefers-reduced-motion`**，命中任一就不再播放。

<Callout type="warn" title="动画必须守住的规矩">
违反过，代价是整页掉帧：

1. **只动 `transform` 与 `opacity`**，不要动 `width/height/top/left`（会逐帧触发布局）；
2. **绝对不要给 `<html>` 或整页容器做动画**。曾经对 `document.documentElement` 淡入、又给整页容器做 `y` 位移，
   等于每帧重绘/合成整屏，好机器都卡，机房机器更不用说。整页级别的入场动画已全部移除；
3. **同一批元素只保留一个 tween**：`animateListIn` 会先 `kill()` 上一个再新建，否则列表刷新频繁时会叠成好几个同时跑；
4. **限制数量**：只对前 36 个元素做错落（`MAX_STAGGER_ITEMS`），长列表直接不播；
5. **不要每次刷新都重放**：文件页只在「换目录 / 换搜索」时播一次，团队页只在筛选条件变化时播一次
   ——上传、删除、勾选完成之后的 `refresh()` 不再重放。

规则来自 GSAP 官方的 gsap-core / gsap-performance 指引，细节见 `lib/lucide.ts` 顶部注释。
</Callout>

<Callout type="warn" title="存在两套图标体系">
应用代码走 `Icon` 组件 + 全局 `lucide.min.js` + `createIcons()` 扫描 DOM；
但 `components/ui/*` 里有 7 个文件直接从 `lucide-react` 导入图标
（`breadcrumb`、`checkbox`、`dialog`、`context-menu`、`dropdown-menu`、`select`、`spinner`）。
结果是打包体积里存在两份 lucide、两套渲染时机。不致命，但属于该收敛的技术债。
</Callout>

### 兼容模式（`robustness`）

给"跑不动 React / Tailwind 的老机器"用的一份**独立静态页面**，
源码在 `web/public/robustness/`，构建后由 `express.static(WEB_DIST)` 直接托管，
访问路径 **`/robustness/index.html`**：

```text
web/public/robustness/
├── index.html       页面骨架（<head> 里同步加载 theme-boot.js）
├── index.css        样式（沿用正常页面的 oklch 配色，写法退回 IE11 能吃的那套）
├── index.js         全部逻辑（ES5 + XMLHttpRequest + 回调）
└── theme-boot.js    首帧应用深色，避免白闪
```

**它不是前端工程的一部分**：不经过 Vite 打包、不引用任何 npm 依赖，
`public/` 会被原样复制到 `web/dist/robustness/`。

改这个目录下的文件时必须遵守这几条，否则老浏览器会整页白屏：

| 约束 | 原因 |
|:--|:--|
| 只用 **ES5**：不用 `let`/`const`/箭头函数/模板字符串/解构/`class`/`for...of` | 目标浏览器含 IE11 |
| 不用 **Promise / fetch** | IE11 都没有；统一 XHR + `function (err, data)` 回调 |
| 不用现代 DOM API：`classList` / `dataset` / `closest` / `Object.assign` / `includes` / `startsWith` | IE11 缺失 |
| **不写内联 `<script>`** | 后端给 `web/dist` 下的 `.html` 挂了 `script-src 'self'` 的 CSP（见 `server/index.js` 的 `SHELL_CSP`），内联脚本会被拦掉 |
| 不写内联事件属性（`onclick="..."`） | 同上，CSP 不允许；统一用 `node.onclick = fn` 赋值 |
| 所有拼进 `innerHTML` 的字符串先过 `esc()` | 文件名与路径都是用户可控输入 |
| 每个请求都带 `X-Requested-With: XMLHttpRequest` | 这是 `csrfGuard` 的第一道校验 |
| 修改后跑 `node --check web/public/robustness/index.js` | 快速排掉语法错误 |

**为什么不需要放松任何安全设置**：同源 XHR 设置自定义头不触发 CORS 预检，
而 IE11 的**同源**请求不带 `Origin` 头，所以 `csrfGuard` 的第二道校验（比对
`Origin` 与 `Host`）自然放行。因此这个页面零安全例外——不要为了它去改
`csrfOriginCheck` 或加什么白名单。

**与服务端的两处约定**（改接口时要注意，否则兼容页会静默出错）：

1. `MAX_FILES_PER_REQUEST = 100`：服务端丢弃超出的文件且只回 `truncated: true`，
   兼容页自己按 100 分批（`web/src/state/uploads.tsx` 里的同名常量也是这个值，
   三处必须一致）。
2. 文件夹上传靠 **filename 里带相对路径**还原目录结构。浏览器只把相对路径给到
   `webkitRelativePath`，而服务端 busboy 读的是 `filename`，所以兼容页会先
   `new File([file], relativePath, ...)` 把名字改写成相对路径再上传。

**预览策略**：不自己解析任何文件格式，能交给浏览器原生组件的就交给它
（`<img>` / `<video>` / `<audio>` / `<iframe>` 加载 PDF），并在元素上挂 `onerror`
兜底成「浏览器不支持此格式」；文本类走 `GET /api/fs/file`（服务端识别编码）后
以文本节点只读显示。**不要**在这里引入任何 JS 解析库。

### Markdown 预览渲染（`lib/markdown.ts` + `lib/markdown-html.ts`）

> 注意：这一节说的是**主前端**的 `.md` 预览。兼容模式对 `.md` 仍然是等宽字体只读展示，
> 它不参与本节这套渲染（见上一节「预览策略」）。

`.md` 预览的渲染器是**自己写的**，没有引入第三方 Markdown 库（`marked` / `markdown-it`
会让前端产物多出 30~110KB）。它只有一条安全前提：

<Callout type="warn" title="先整体转义，再解析 —— 顺序不能反">
`inline()` 一进来就把 `&` `<` `>` `"` 转成实体，此后所有正则只处理已经转义过的文本，
而生成出来的标签全是我们自己拼的。因此输出串里不可能出现来自文件的标签，
可以安全地交给 `dangerouslySetInnerHTML` —— 不存在 XSS 通道。
</Callout>

唯一的例外是一张**固定的无属性标签白名单**（`lib/markdown-html.ts` 的 `SAFE_HTML_TAGS`，13 个）：
它把已转义文本里的 `&lt;br&gt;` 还原成字面标签，**属性全部丢弃**，所以上面那条前提仍然成立。

- 白名单还原排在**行内代码抠走之后**、图片 / 链接解析之前（代码里的 `<br>` 是示例，不该渲染）；
- 属性必须写成 `name=value`（`ATTRS_RE` 保证），`<span and more text>` 这种残句不会被当成标签；
- 行内代码、链接地址、图片地址先用 `NUL + 序号 + NUL` 的占位符"抠出来"，最后再还原
  （占位符可能嵌套，所以还原要跑最多 4 轮）；
- 危险协议（`javascript:` / `vbscript:` / `data:`）命中即降级为纯文本；
- 样式集中在 `index.css` 的 `.md-body` 段：渲染器只产出语义标签、**不给任何 class**，
  这样既省字节，也避开"运行时生成的 HTML 里写的工具类 Tailwind 扫不到、根本不会进产物"
  这个坑；
- 预览页正文与源码视图都带 `select-text`：外层 `ContextMenuTrigger` 自带 `select-none`，
  不覆盖会导致整页文字选不中（"Markdown 不能复制"的根因）；
- 外链图片依赖应用外壳 CSP 的 `img-src http: https:`（见 [安全设计](/docs/zeroshadow/security/design)）。

### 多语言（i18n）

**一句话**：源码里不再写中文，写 `t("命名键")`；译文放在 `web/src/locales/<语言>/<区域>.json`。

| 位置 | 作用 |
|:--|:--|
| `web/src/lib/i18n.tsx` | 运行时：`t()` / `translate()` / `useT()`、语言状态与切换、插值、回落链 |
| `web/src/locales/zh/<区域>.json` | **中文（源语言）**，必须覆盖每一个用到的键 |
| `web/src/locales/en/<区域>.json` | 英文 |
| `web/src/locales/index.ts` | 用 `import.meta.glob` 在**构建期**把各区域文件合并成 `BUILTIN`（运行期零请求） |
| `web/src/components/language-select.tsx` | 语言选择器 + 「导出翻译模板」（值就是中文原文） |
| `server/src/i18n.js` | 扫描 / 校验 `data/lang/*.json`，按 mtime 失效缓存 |
| `server/src/routes/i18n.js` | `GET /api/i18n`（清单 + 站点默认）、`GET /api/i18n/:code`（译文） |
| `web/public/robustness/index.js` 顶部 | 兼容模式页自带的 ES5 版 `T()` 与字典加载（它不参与构建，自己按 `/resources/locales/*.json` 取静态字典） |
| `vite.config.ts` 的 `localeAssets()` | 构建时把合并后的字典额外输出成 `dist/resources/locales/<语言>.json`，专供兼容模式页 |
| `i18n-check.mjs` | 键完整性校验 + 剩余硬编码中文统计 |

键的形状：`<命名空间>.<区域>.<名字>`，**至少三段**（第三段用于排除 `meta.json` 这类文件名误报），
命名空间取 `ui`（界面）/ `api`（服务端提示）/ `meta`（文件元数据字段名）/ `compat`（兼容模式）。

写代码时的三条纪律：

1. 组件里 `const t = useT()`（语言一变就重渲染）；非组件模块用 `translate()`；
2. **不要在模块顶层把 `translate()` 的结果存成常量** —— 那会把首次加载时的语言锁死
   （`lib/format.ts` 的 `EXT_KIND` 存的是**键**，在 `fileKind()` 里才翻译，就是这个原因）；
3. 插值统一用 `{name}` 占位符：`t("ui.browser.deleted_count", { n })`。

<Callout type="warn" title="中文是唯一的兜底">
任何键在当前语言里缺失都会依次回落到 `zh`、最后回落到键名本身（界面上会显示成
`ui.xxx.yyy`）。所以 `zh` 必须完整 —— `i18n-check.mjs` 里"缺 zh"是**错误**、"缺 en"是警告。
</Callout>

#### 服务端的文案怎么本地化

服务端**不持有字典**，只在错误里多带两个字段（见 `server/src/http.js` 的 `httpError`）：

```js
throw httpError(400, `文件过大（${size}），在线编辑上限 ${limit}`, {
  errorKey: "api.fs.file_too_large_for_editor",
  errorParams: { size, limit },
})
```

- `error` 仍是拼好的**中文原文**（`curl` 与第三方脚本的既有行为一字不变）；
- 前端在 `lib/api.ts` 里优先用 `errorKey` + `errorParams` 渲染，缺键就回落到 `error`；
- 新增服务端错误时：**中文照写，另外给一个键**；
- **日志不要本地化**：`info()` / `warn()` 的 event 与 msg 是运维数据，保持中文；
- 文件元数据的字段名走同一套：`server/src/fileinfo.js` 每条返回
  `{ key: "meta.exif.make", label: "相机厂商", value }`，前端 `t(key)` 查不到就用 `label` 兜底。

#### 校验

```bash
node i18n-check.mjs            # 退出码 = 错误数
node i18n-check.mjs --list-cn  # 列出还没接入 i18n 的中文
node i18n-check.mjs --strict   # 把"剩余硬编码中文"也算作失败
```

它检查：用到的键在 zh / en 里是否都存在、en 里有而 zh 里没有的键、en 值里是否残留中文、
两个语言都没用到的死键、同一键在两份区域文件里冲突、`data/lang/` 里的非法键，
以及还剩多少处硬编码中文。扫描范围包括 `web/src`、`web/public/robustness` 与
`server/src` + `server/index.js`（服务端的 `errorKey` / `meta.*` 字面量同样算"用到的键"）。

<Callout type="info" title="「剩余硬编码中文」怎么读">
服务端文件里的中文**大多是设计使然**，不是漏改：`error` 字段必须保留中文原文
（保证 curl 与第三方脚本的既有行为）、元数据的 `label` / `value` 是缺译文时的兜底、
`info()` / `warn()` 日志与启动横幅不做本地化。所以这个数字应该**看趋势**：
前端（`web/src`、`web/public/robustness`）应当为 0，服务端则逐个确认
"新加的中文有没有同时给 `errorKey`"。
</Callout>

#### 要内置一门新语言

在 `web/src/locales/` 下新建语言目录（如 `ja/`）放入各区域文件，并在 `locales/index.ts` 的
`BUILTIN_META` 里登记代码与自称；`BUILTIN` 会自动把它合并进来。只想**临时加一门**
（不改代码）：往服务端 `data/lang/<代码>.json` 丢文件即可，格式与限制见
[配置参考](/docs/zeroshadow/admin/configuration)。

## 约定与注意事项

| 约定 | 说明 |
|:--|:--|
| 后端全部用 `node:` 前缀导入内置模块 | 例如 `import fs from "node:fs"` |
| 前端只用 `@/` 别名导入 | 对应 `web/src` |
| UI 文案 | 全部中文，不引外部文案系统 |
| 图标与字体 | 一律走 `public/resources/`，**禁止 CDN**（内网离线可用性的前提） |
| 阴影 | 用 `edge-highlight` / `surface-inset` 这类内阴影 + 顶部高光工具类，避免生硬投影 |
| 颜色 | 通过 `index.css` 的 `@theme` 令牌引用，不硬编码色值 |
| 权限判定 | **只在服务端做**；前端的隐藏/置灰只是体验优化 |
| 路径处理 | 客户端传来的路径必须过 `safety.js`，不要自己拼字符串 |
| 日志 | 业务动作记 `info("事件名", { msg, ...actor(req) })`，密码与令牌**绝不入库** |
| 错误 | 业务错误用 `httpError(status, msg)` 抛，交给统一错误处理 |

### 已知的小不一致

以下都不影响功能，改文档或改代码时注意别被绕进去：

- `components/layout/app-shell.tsx` 里导出的 `useShellSearch` 与 `ShellContext`
  目前没有页面在用（文件浏览器的搜索框在自己的工具栏里）；
- `components/browser/dialogs.tsx` 里的 `PreviewDialog` 与 `EditorDialog` 已被独立的
  `/preview`、`/editor` 页面取代，但两套实现仍然并存；
- `components/ui/` 下的 `breadcrumb` 完全没有引用（面包屑在 `browser-page.tsx` 与
  `dest-picker.tsx` 各手写了一遍）；`input-group` 与 `field` 现在是团队页 /
  小组编辑器在用的，不再属于死代码；
- 依赖里装了但全代码库零引用：`next-themes`、`@fontsource-variable/inter`；
  静态资源里 `web/public/resources/tailwindcss.min.js` 也没有引用。

<Callout type="warn" title="typecheck 抓不到死代码">
`tsconfig` 开了 `noUnusedLocals`，但它**不报未使用的 export**。
所以上面这些死代码 `pnpm typecheck` 全绿也发现不了，只能靠人工或额外工具。

（另外注意：`pnpm typecheck` 以前其实**什么都没检查**——根 `tsconfig.json` 是 solution 式配置、
`files` 为空数组，`tsc` 不会顺着 `references` 去查任何文件。现在它直接跑
`tsc -p tsconfig.app.json --noEmit && tsc -p tsconfig.node.json --noEmit`，是真检查了。）
</Callout>
