# 公网访问与隧道

ZeroShadow 跑在局域网里时，同事直接访问 `http://<局域网IP>:12345` 就能用。
但需要让**不在同一网络**的人访问时，就得把这个端口暴露出去。

内置的做法是 **SSH 反向隧道**：服务端主动连出去，由隧道服务分配一个公网地址并把请求转发回来。
**不需要路由器端口映射，不需要公网 IP，不需要域名证书**。

---

## 1. 前置条件

| 条件 | 说明 |
|:------------------ |:--------------------------------------- |
| 服务端能执行 `ssh` 命令 | 程序启动隧道时会先执行 `ssh -V` 探测，探测结果会被缓存 |
| 出网通畅 | 能连到隧道服务商的 22 / 443 端口 |

没装 SSH 客户端时，「设置 → 公网」的输出区会显示：

```
错误: 未检测到 SSH 客户端，请先安装 OpenSSH Client
Windows: 设置 → 应用 → 可选功能 → 添加功能 → OpenSSH 客户端
```

并且**不会自动重试**——装好之后点一下「应用并重连」，或者把总开关关掉再打开。

---

## 2. 四种隧道模式

在「设置 → 公网 → SSH 反向隧道 → 隧道服务」里选。下面列出的是程序**实际执行的命令**
（`<PORT>` 就是 `.env` 的 `PORT`，默认 12345）。

### pinggy.io（推荐）

```
ssh -T -p 443 -R 0:127.0.0.1:<PORT> a.pinggy.io
```

- 用 443 端口，**对只放行 HTTPS 出网的网络更友好**；
- `-R 0:...` 表示让远端自动分配端口；
- 界面上枚举里标注了"（推荐）"，也是默认模式。

### localhost.run

```
ssh -T -R 80:127.0.0.1:<PORT> nokey@localhost.run
```

- 免注册，用固定的 `nokey` 账号。

### serveo.net

```
ssh -T -R 80:127.0.0.1:<PORT> serveo.net
```

### 自定义 SSH

```
ssh -N -R 80:127.0.0.1:<PORT> [ -p <端口> ] <user@host>
```

- 「SSH 目标」填 `user@host` 或 `user@host:端口`；
- 需要服务端**已经配置好免密登录**（密钥或被 ssh-agent 托管），因为程序无法交互式输入密码；
- 目标格式会有校验：不能以 `-` 开头，只能是 `[user@]host[:port]` 形式，否则提交时返回"SSH 目标格式无效"。

### 所有模式共用的 `ssh` 参数

| 参数 | 作用 |
|:------------------------------------------- |:--------------------------------------- |
| `-o StrictHostKeyChecking=accept-new` | 首次连接自动接受主机密钥（不阻塞在交互询问上） |
| `-o ServerAliveInterval=60` | 每 60 秒发一次心跳 |
| `-o ServerAliveCountMax=3` | 连续 3 次心跳无响应则判定断开 |
| `-o ConnectTimeout=15` | 连接超时 15 秒 |
| `-o UserKnownHostsFile=<运行根目录>/data/.ssh-known-hosts-tunnel` | 专用 `known_hosts`，**不污染你系统的 `~/.ssh/known_hosts`** |

## 3. 使用方式

1. 用超管登录 →「设置」→「公网」；
2. 打开「启用公网访问」，界面会立刻拉起隧道进程；
3. 几秒后「运行状态」区会显示：

   - 徽章变成 **运行中**；
   - **公网地址** 出现在只读输入框里（点一下可全选复制），形如 `https://<隧道服务分配的子域>`；
   - 下方输出区显示实际执行的 `ssh` 命令与隧道进程的输出。

4. 把公网地址发出去即可。

其它细节：

- **切换「隧道服务」**：如果隧道正在运行，会立刻按新模式断开重连；
- **「应用并重连」**：按当前配置重新建立连接；
- **关闭「启用公网访问」**：立刻停掉隧道，地址失效；
- 状态每 5 秒刷新一次；输出区保留最近 40 行，输出缓冲区本身最多保留 120 行；
- 如果启动后 15 秒还没抓到地址，输出区会提示「（尚未捕获到公网地址，隧道可能仍正常工作）」——
  此时地址可能仍在隧道进程的输出里，往上翻一翻即可。

### 掉线自动重连

隧道进程退出时，如果开关仍然是打开的，服务会按**指数退避**重连：

```
5 秒 → 10 秒 → 20 秒 → 40 秒 → 60 秒 → 60 秒 → …
```

重连次数会显示在状态区（显示成"已自动重连 N 次"）。
**免费隧道一般不保证固定地址，重连后地址很可能发生变化**，所以不要把地址写死在别人的收藏夹里。

### 手动跑隧道（备选）

隧道本质上就是一条 `ssh -R`，你完全可以在自己的机器上手动跑，不动用界面功能：

```bash
ssh -R 80:localhost:12345 serveo.net
```

（把 `12345` 换成你的实际端口。）输出里会给出公网地址。

## 4. TRUST_PROXY 该怎么填

隧道和反向代理都会让服务"看起来"是被本机访问的——所有请求的来源 IP 都变成 `127.0.0.1`。
这会造成两个后果：

1. 日志里的 IP 全是 `127.0.0.1`，排查时没有参考价值；
2. **按 IP 的失败限速与接口限流会误伤所有人**——因为所有人共用同一个 IP 计数。

解决办法是让服务去读 `X-Forwarded-For`，也就是设置 `.env`：

```env
TRUST_PROXY=loopback
```

| 你的部署方式 | 建议取值 |
|:----------------------------------------------- |:--------------------------------------- |
| **只**通过 SSH 隧道 / 本机反向代理访问 | `TRUST_PROXY=loopback` |
| 只通过某一台可信反代访问 | 填那台反代的地址或网段，例如 `10.0.0.0/8` |
| 经过多层代理 | 填跳数，例如 `2` |
| 服务**同时能被直连**（别人可以直接访问 `http://你的IP:12345`） | **保持关闭（默认）** |

**为什么"同时能被直连"时必须关闭？**
因为 `X-Forwarded-For` 是客户端可以自己伪造的请求头。如果服务既信任代理头、又能被直接访问，
攻击者只要自己编一个 `X-Forwarded-For: 1.2.3.4` 发过来，就能让每一次请求都算作"不同的 IP"，
从而**绕过登录失败锁定与接口限流**。

改完之后：

- 必须**重启服务**；
- 启动日志会打印当前生效模式：`客户端 IP: 直连（不信任代理头）` 或 `客户端 IP: 信任代理头 loopback`；
- 也可以随时在「设置 → 安全 → 客户端 IP 解析」里查看这个徽章。

> 相关回归测试：`security-test.ps1` 的第 9 组会验证"`TRUST_PROXY` 关闭时 `X-Forwarded-For` 是否被忽略"，
> 加 `-TrustProxyMode` 参数则反过来验证开启后是否生效。见 [开发者指南](开发者指南.md)。

## 5. 暴露到公网前请务必确认

公网地址**任何人都能访问**，默认配置下访客可以浏览和下载。上线前建议过一遍这张清单：

- [ ] **访客权限**是否是你想要的？「设置 → 权限 → 访客权限」可以把浏览 / 下载 / 打包 / 预览全部关掉，
      这样只有拿到账号的人才能用；
- [ ] 需要保留访客浏览、但有些内容不对外时，用**对访客隐藏**逐个文件夹设置（右键 →「对访客隐藏」）；
- [ ] **超管密码**是不是够强？`.env` 里的密码可以用很久，别用弱口令；
- [ ] 需要时给成员**单独发账号**，别让大家共用超管账号（成员会话失效更好管理）；
- [ ] **`TRUST_PROXY`** 是否按上一节设对了？设错会导致限流形同虚设；
- [ ] **`FILES_SOFT_DIR`** 是否映射了敏感目录？如果把项目根目录映射进网盘，即使有 `softDirAllowCopyOut`
      兜底，也建议直接改成映射真正需要共享的目录；
- [ ] **HTTP 还是 HTTPS**：隧道服务给出的通常是 `https://` 地址。服务端在判断请求为 HTTPS
      （`req.secure`，或存在 `X-Forwarded-Proto: https`）时会自动给会话 Cookie 加上 `Secure`；
      如果自己用反向代理暴露，请配置好 TLS 并透传该请求头，否则会话 Cookie 会以明文经过网络；
- [ ] 别忘了访客模式是**不需要登录**的，公网地址一旦泄露，任何人都能按你的访客权限使用。

## 6. 排查清单

| 现象 | 可能原因与处理 |
|:----------------------------------- |:--------------------------------------- |
| 输出区提示找不到 SSH 客户端 | 装 OpenSSH Client；Windows：设置 → 应用 → 可选功能 → 添加功能 → OpenSSH 客户端。装好后点「应用并重连」 |
| 一直"未运行"、没有输出 | 出网被拦（防火墙 / 公司网络限制 22 与 443 端口）；换 `pinggy` 模式（走 443）试试 |
| 显示"运行中"但没有公网地址 | 地址可能还在输出里，往上翻；或等一会儿（界面 15 秒会提示）；也可以用「应用并重连」重来一次 |
| 打开公网地址是 502 / 打不开 | 隧道进程通常已经掉了，看输出区最后几行；程序会自动重连，重连后地址会变 |
| 地址昨天还好，今天变了 | 免费隧道服务的特点，重连即换地址 |
| 日志里 IP 全是 `127.0.0.1` | 设置 `TRUST_PROXY=loopback` 并重启；详见上一节 |
| 有人狂刷打包 / 解压接口 | 确认「设置 → 安全 → 接口限流」是开启的，且 `TRUST_PROXY` 配置正确，否则限流会被绕过 |
| 自定义 SSH 一直失败 | 确认服务端对目标主机**免密登录**可用（`ssh user@host` 不提示密码），并注意目标格式是 `user@host[:端口]` |
