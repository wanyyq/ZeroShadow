# 权限与角色

ZeroShadow 只有三种角色，但成员与访客的权限可以逐项开关。这一篇给出**完整的权限矩阵**、
**每一项权限在界面上的表现**，以及容易被忽略的**依赖关系**。

> 角色权限开关都在「设置 → 权限」里，改动即刻生效（不需要重启），持久化在 `data/config.json`。

---

## 1. 三种角色

| 角色 | 内部标识 | 如何获得 | 能不能登录 |
|:------------------ |:----------- |:--------------------------------------- |:----------------- |
| **超级管理员** | `superadmin` | `.env` 中的 `SUPER_ADMIN_USER` / `SUPER_ADMIN_PASSWORD`，全局唯一 | 可以，密码只能改 `.env` |
| **团队成员**（也叫低级管理员） | `member` | 由超管在「设置 → 成员」创建 | 可以 |
| **访客** | `guest` | 无需任何操作，未登录即访客 | 不需要登录 |

补充规则：

- 超管账号**不能删除、不能改用户名**，也不出现在成员列表里；成员用户名不能与超管重名。
- 超管密码只在启动时读取，**改了 `.env` 必须重启服务**才生效。
- 超管登录令牌里带有一个由密码派生的指纹，所以**改了密码后，所有旧的超管会话立刻失效**。
- 成员密码用 bcrypt 存储（成本因子 10）。成员被「禁用」或「重置密码」时，其旧会话也会立刻失效。
- 成员数量上限 **500**；一次批量创建上限 **200** 个。
- 用户名规则：`2–32` 位，只允许字母、数字、下划线、点、连字符（`^[A-Za-z0-9_.-]{2,32}$`）。
- 密码规则：`6–128` 位。

## 2. 权限矩阵

下表是**默认值**。超级管理员一列固定不可改；成员、访客两列都可以在后台调整。

图例：✅ 固定开启　❌ 固定关闭　🔧 可配置（括号内为默认值）

| 权限点（后台名称） | 配置字段 | 超级管理员 | 团队成员 | 访客 |
|:-------------------------------- |:------------------------- |:---:|:--------------:|:--------------:|
| 文件操作（总开关） | `memberPerms.fileWrite` | ✅ | 🔧（开） | ❌ |
| 上传文件 | `memberPerms.upload` / `guestPerms` 无 | ✅ | 🔧（开） | ❌ |
| 上传文件夹 | `memberPerms.uploadFolders` | ✅ | 🔧（开） | ❌ |
| 新建文件夹 | `memberPerms.mkdir` | ✅ | 🔧（开） | ❌ |
| 复制 | `memberPerms.copy` | ✅ | 🔧（开） | ❌ |
| 移动 | `memberPerms.move` | ✅ | 🔧（开） | ❌ |
| 重命名 | `memberPerms.rename` | ✅ | 🔧（开） | ❌ |
| 删除 | `memberPerms.delete` | ✅ | 🔧（开） | ❌ |
| 浏览目录 | `memberPerms.browse` / `guestPerms.browse` | ✅ | 🔧（开） | 🔧（开） |
| 下载文件 | `memberPerms.downloadFile` / `guestPerms.downloadFile` | ✅ | 🔧（开） | 🔧（开） |
| 下载文件夹（打包） | `memberPerms.downloadFolder` / `guestPerms.downloadFolder` | ✅ | 🔧（开） | 🔧（开） |
| 允许预览 | `memberPerms.preview` / `guestPerms.preview` | ✅ | 🔧（开） | 🔧（开） |
| 查看详细信息 | 成员固定开启 | ✅ | ✅ | ❌ |
| 压缩为 Zip | `memberPerms.compressZip` / `guestPerms.compressZip` | ✅ | 🔧（开） | 🔧（关） |
| 解压 Zip | `memberPerms.extractZip` / `guestPerms.extractZip` | ✅ | 🔧（开） | 🔧（关） |
| HTML 全屏预览 | `memberPerms.htmlPreview` / `guestPerms.htmlPreview` | ✅ | 🔧（开） | 🔧（关） |
| 在线编辑文件 | `memberPerms.editFiles` / `guestPerms.editFiles` | ✅ | 🔧（开） | 🔧（关） |
| 多线程下载器 | `memberPerms.downloadUrl` | ✅ | 🔧（开） | ❌ |
| 管理访客可见性 | `memberPerms.manageGuestVisibility` | ✅ | 🔧（开） | ❌ |
| 修改密码 | `memberPerms.changePassword` | ✅（走 `.env`） | 🔧（开） | ❌ |

上传大小上限（不是布尔开关，是数值）：

| 角色 | 配置字段 | 默认值 |
|:------------------ |:---------------------- |:-------- |
| 超级管理员 | `superUploadLimitMB` | 2048 MB |
| 团队成员 | `memberUploadLimitMB` | 512 MB |
| 访客 | — | 不能上传 |

> 上表是**全局默认值**。团队成员的最终权限还要再和"当前所在小组的权限收窄"取一次「与」，
> 详见下一节。访客与超级管理员不受小组影响。

## 3. 小组：权限收窄与可见范围

**小组不改变角色。** 超级管理员仍然是超管，成员仍然是成员，访客仍然是访客；小组只是给成员加了一个
"上下文"：成员可以同时属于多个小组，在**顶栏的小组切换器**里选择当前生效的那个（选择「默认」表示不套用
任何小组）。切换之后，三件事随之变化：

| 影响面 | 说明 |
|:------------------ |:--------------------------------------- |
| **有效权限** | 小组的 19 个权限开关与全局 `memberPerms` **取与**，只能收窄、不能放宽 |
| **可见范围** | 小组的白名单 / 黑名单决定该成员能看到哪些目录；不在范围内的目录对他表现为**不存在** |
| **团队待办** | 组长可对本组下发待办；成员能看到发给本组或本人的待办 |

### 收窄的计算方式

服务端在**每个请求**上解析当前小组并要求成员确实属于该组（`X-ZS-Group` 请求头，缺失或非法时回退「默认」），
然后计算本轮的有效权限（`server/src/config.js` 的 `effectivePerms(role, group)`）：

```
最终权限(某个权限点) = 全局 memberPerms(该权限点)  AND  小组 perms(该权限点)
```

所以：

- 全局关掉的权限，小组里**打不开**；
- 全局开着、小组里关掉的权限，**对该组成员不生效**——界面上也会同步置灰 / 隐藏对应按钮；
- 「文件操作总开关」（`fileWrite`）依然是最外层闸门：全局或小组任一侧把它关掉，
  上传 / 上传文件夹 / 新建文件夹 / 复制 / 移动 / 重命名 / 删除就都是关的。

具体开关与分组见 [管理员指南 · 小组](管理员指南.md#小组)。

### 可见范围（白名单 / 黑名单）

- 两个列表都存**相对网盘根目录的路径**，判定规则是"等于该路径，或位于该路径之内"
  （Windows / macOS 上不区分大小写）；
- **黑名单优先**：同时命中白名单与黑名单时一律不可见；
- **白名单为空表示不限制**；非空时只有白名单内的目录及其子目录可见；
- 不可见的目录对成员表现为**不存在**：列表里没有、搜索结果里没有、直接访问返回 **404**，
  打包下载与在线压缩也会**递归跳过**，不会从压缩包里泄露出去；
- **不属于任何小组的成员**、以及顶栏选择「默认」时，套用的是超管在
  「设置 → 数据与保留 → 默认上下文可见范围」里设定的 `defaultVisibility`（同样规则、同样默认不限制）。

### 组长的四项能力

超管在小组对话框的「基本」页勾选下放给组长的能力（默认值见括号）：

| 能力 | 字段 | 默认 | 组长可以做什么 |
|:-------------------------------- |:------------------ |:-------- |:--------------------------------------- |
| 查看本组成员名单 | `viewMembers` | 开 | 只读查看本组成员 |
| 创建 / 编辑本组待办 | `manageTodo` | 开 | 向本组或本组成员下发待办，编辑 / 删除自己管辖范围内的待办 |
| 修改本组成员头像 | `editMemberAvatar` | 关 | 为本组成员设置 / 删除头像 |
| 管理本组成员与可见范围 | `manageMembers` | 关 | 增删本组成员、调整本组的白名单 / 黑名单 |

- 未勾选的能力，组长在该小组内**无法使用**（服务端逐请求校验，不只是界面限制）；
- 组长只能调整**自己所在小组**的成员与可见范围，改不了组名、颜色、权限收窄与组长能力——
  那些始终归超管；
- 被移出小组会自动卸任组长。

### 谁不受小组影响

| 角色 | 表现 |
|:-------------- |:--------------------------------------- |
| **超级管理员** | 可以切换任意小组，但可见范围与权限收窄对他**不生效**（始终是全部权限 + 全部可见） |
| **访客** | 完全不参与小组机制，只受 `guestHiddenPaths`（「对访客隐藏」）约束 |
| **不属于任何小组的成员** | 只能使用「默认」上下文，套用全局 `memberPerms` 与 `defaultVisibility` |

> 数量限制：最多 **200** 个小组，每个小组最多 **500** 名成员、**100** 名组长；
> 组名重名（不区分大小写）会被拒绝。小组相关的配置都存在 `data/groups.json`。

## 4. 权限之间的依赖关系（重点）

### 「文件操作」是总开关

成员的所有**写操作**都被 `fileWrite` 收口。也就是说，`fileWrite` 关掉之后，即使
「上传文件」「删除」「重命名」…… 这些开关还亮着，实际权限也是**关**的：

```
fileWrite = 关
  ⇒ 上传文件 / 上传文件夹 / 新建文件夹 / 复制 / 移动 / 重命名 / 删除  全部无效
```

后台界面上这些子项会一起变灰，就是这个原因。
不受它影响的只有：浏览、下载、预览、压缩、解压、链接下载、在线编辑、HTML 预览、管理访客可见性。

> 如果成员当前处于某个小组，还要**同时**满足该小组的 `fileWrite`——小组只能在此基础上继续关闭，
> 详见上一节。

### 「上传文件」与「上传文件夹」是分开的

只开「上传文件」时，工具栏的「上传文件夹」按钮不可用；拖拽整个文件夹上传也会被拒绝，
因为整目录上传走的是 `uploadFolders` 这条权限。

> **需要知道的一点**：`uploadFolders` 目前是**前端生效**的开关——界面会把「上传文件夹」按钮置灰，
> 但服务端的上传接口只校验 `upload`。如果你要防的是"有人绕过界面直接调接口传整个目录"，
> 请直接关闭「上传文件」；如果只是想让界面清爽一些，用 `uploadFolders` 就够了。

### 「允许预览」与「下载文件」的区别

- 两者都开：正常预览 + 正常下载；
- 只开「允许预览」、关掉「下载文件」：文件**只能以内联方式打开**（浏览器里显示，而不是另存为）。
  服务端会把 `Content-Disposition` 强制成 `inline`；对于不支持内联打开的类型，成员会得到
  403「没有权限下载文件」，访客则是 401「请先登录」。
- 关掉「允许预览」、开着「下载文件」：双击文件会直接下载，右键菜单里没有「预览」。

### 「在线编辑文件」同时也决定了快捷方式

创建 / 修改 `.zeropath` 快捷方式本质上是写文件，所以需要「在线编辑文件」权限。

### 「管理访客可见性」只控制"设置隐藏"这个动作

它是给**成员**准备的权限：成员可以把某个文件夹标记为"对访客隐藏"。
访客自己当然不能设置，他们只承受结果。

### 访客永远做不到的事

无论后台怎么配，访客都**不可能**获得：上传、新建文件夹、复制、移动、重命名、删除、
查看详细信息、使用链接下载器、管理访客可见性、修改密码。

### 不随角色变化的全局设置

下面这些是**全局**的，对所有角色（包括访客）生效：

- 接口限流（`rateLimitEnabled` / `rateLimitPerMin`）
- 各类体积上限（ZIP、解压、链接下载）
- 只读映射目录是否允许复制出去（`softDirAllowCopyOut`）
- 作业进度是否仅创建者可见（`jobStatusOwnerOnly`）
- 链接下载是否允许访问内网（`downloadUrlAllowPrivate`）
- 写操作是否校验来源（`csrfOriginCheck`）

## 5. 访客隐藏文件夹

超管或（拥有对应权限的）成员可以在文件列表里右键文件夹 →「对访客隐藏」。

**判断规则**：隐藏记录里存的是**相对网盘的路径**，判定时使用的是"等于该路径，或位于该路径之内"。
因此在 Windows 与 macOS 上比较是**不区分大小写**的（Linux 上区分）。

被隐藏后会发生什么：

| 场景 | 表现 |
|:--------------------- |:--------------------------------------- |
| 访客列目录 | 该文件夹**完全不出现在列表里** |
| 访客搜索 | 该文件夹及其子目录下的命中结果被过滤掉 |
| 访客直接访问该路径 | 返回 **404「目录不存在」**（而不是 403，避免泄露"这里确实有东西"） |
| 访客下载其中的文件 | 返回 **404「文件不存在」** |
| 访客打包下载包含它的目录 | 打包时**跳过**该文件夹及其内容 |
| 成员 / 超管 | 一切正常，列表里会多一个"眼睛斜杠"图标 |
| 重命名 / 移动被隐藏的文件夹 | 隐藏记录**自动跟着更新** |
| 删除被隐藏的文件夹 | 对应记录**自动清理** |

管理入口：右键菜单切换单项目，或「设置 → 权限 → 对访客隐藏的文件夹」查看全部并点「恢复可见」。

> 注意：只有**文件夹**能设置隐藏。如果你想隐藏单个文件，把它放进一个文件夹再隐藏该文件夹。

## 6. 常见配置组合

### A. 完全公开的资料盘

```
访客：浏览 ✅  下载文件 ✅  下载文件夹 ✅  预览 ✅
成员：文件操作 ✅，但只留「上传文件」（关掉上传文件夹 / 新建文件夹 / 复制 / 移动 / 重命名 / 删除）
```

适合给客户 / 外部人员看的素材分发场景：任何人打开链接就能取文件，但改不了任何东西。

### B. 内部协作盘（推荐给工作室）

```
访客：浏览 ❌  下载 ❌（等于对外关闭）
成员：文件操作 ✅ 全部子项 ✅
```

对外只保留"要账号才能看"，内部成员当作普通网盘使用。

### C. 只读资料库

```
成员：文件操作 ❌  压缩为 Zip ✅  解压 ❌  在线编辑 ❌  多线程下载器 ✅
访客：浏览 ✅  下载文件 ✅  下载文件夹 ✅
```

成员可以打包带走资料、可以用链接下载器往盘里抓文件，但不能改动现有文件——
注意：链接下载器写文件走的是它自己的权限，不受 `fileWrite` 限制。

### D. 极简展示盘

```
访客：浏览 ✅  下载文件 ❌  下载文件夹 ❌  预览 ✅
成员：允许预览 ✅
```

只能在线看、不能下载原文件——但请知悉：**能预览的内容在技术上仍然可以被访问者保存下来**，
这只是提高门槛，不是内容保护方案。

## 7. 改权限的步骤

1. 用超管登录，进「设置 → 权限」；
2. 修改对应开关（开关是即时保存的，不需要点确认）；
3. 改数值类（上传大小、ZIP 上限、链接下载上限）后要点旁边的「保存」按钮；
4. 改完刷新一下页面即可看到按钮状态变化。

> 权限变更**不需要重启服务**。修改 `.env` 里的超管账号密码、端口、`TRUST_PROXY` 等才需要重启。
