# 快速开始

这一篇只讲一件事：**把 ZeroShadow 跑起来，并让别人能访问到它**。整个过程不需要数据库、不需要 Docker，也不需要改任何代码。

---

## 1. 环境要求

| 组件 | 要求 | 说明 |
|:-------- |:-------- |:--------------------------------------- |
| **Node.js** | 18 及以上 | 仅源码运行需要。`Auto-building.bat` 会检查主版本号，低于 18 时告警；`pkg` 打包目标为 `node18-win-x64` |
| **pnpm** | 9 及以上 | 仓库锁文件为 `lockfileVersion: '9.0'`（见 `web/pnpm-lock.yaml`、`server/pnpm-lock.yaml`） |
| **SSH 客户端** | 可选 | 只有要用「公网访问」功能时才需要（服务端要能执行 `ssh` 命令） |

检查一下版本：

```bash
node -v
pnpm -v
```

---

## 2. 从源码启动（三步）

```bash
# 1. 安装依赖：会分别安装 server 与 web 两个子项目（root package.json 的 setup 脚本）
pnpm setup

# 2. 构建前端：等价于 cd web && tsc -b && vite build，产物在 web/dist
pnpm build

# 3. 启动服务：等价于 node server/index.js
pnpm start
```

启动成功后，控制台会输出类似内容：

```
  ZeroShadow 网盘已启动
  本机访问:   http://localhost:12345
  局域网访问: http://192.168.1.23:12345
  文件目录:   D:\ZeroShadow\data\files
  客户端 IP:  直连（不信任代理头）
```

- 「本机访问」是你自己这台机器用的地址；
- 「局域网访问」可能有多个（机器有多张网卡时逐个列出），**把这个地址发给同事即可**；
- 「文件目录」就是网盘的文件根目录，往里放文件等价于在网页里上传；
- 「客户端 IP」显示的是 `TRUST_PROXY` 的当前生效模式，默认是"直连（不信任代理头）"。

> 如果看到 `前端尚未构建：请先运行 pnpm build，然后重启服务。`，说明 `web/dist` 不存在，执行一次 `pnpm build` 再重启即可。

### 首次启动会自动生成 `.env`

只要项目根目录（打包后是 `ZeroShadow.exe` 同目录）没有 `.env`，服务会**自动创建一个**，内容包括：

- `PORT=12345`、`HOST=0.0.0.0`、`SUPER_ADMIN_USER=admin`、`SESSION_HOURS=72`；
- 一个**随机生成的超级管理员密码**（`crypto.randomBytes(12)` 的 base64url 编码，16 个字符），并在控制台上以醒目块打印：

```
  [重要] 已自动生成超级管理员密码并写入 .env：
         用户名: admin
         密码:   xxxxxxxxxxxxxxxxxxxxxxxx
```

**请立刻把密码记下来。** 如果 `.env` 里 `SUPER_ADMIN_PASSWORD` 缺失，或者值还是模板里的 `change-me`，
服务也会重新生成一个随机密码并回写进 `.env`，同样会打印出来。

> `.env` 属于敏感文件，已被 `.gitignore` 忽略。在 Linux / macOS 上写入权限会收紧为仅属主可读写。

### 会自动创建的运行时目录

首次启动时，下面这些目录不存在的话会被自动创建（都在"运行根目录"下，即 `.env` 旁边）：

| 目录 / 文件 | 用途 |
|:--------------------- |:------------------------ |
| `data/` | 运行时数据根目录 |
| `data/files/` | 网盘文件的真实根目录（可用 `FILES_DIR` 改到别处） |
| `data/logs/` | 按天写入的日志文件 `zs-YYYY-MM-DD.log` |
| `data/metrics/` | 按天写入的指标采样 `zs-YYYY-MM-DD.jsonl`（每分钟一条） |
| `data/tmp/` | 上传与下载的临时中转目录，**每次启动都会清空** |
| `data/.jwt-secret` | 会话签名密钥，自动生成 96 个十六进制字符（`crypto.randomBytes(48)`） |
| `data/config.json` | 后台设置（首次保存设置时才写入） |
| `data/users.json` | 团队成员账号（密码为 bcrypt 哈希） |
| `data/groups.json` / `data/todos.json` | 小组 / 团队待办（首次创建时才写入） |
| `data/avatars/` | 头像（128×128 WebP），设置过头像才有文件 |
| `data/backups/` | 数据快照：覆盖写前自动备份 + 每日一次，可在「设置 → 数据与保留」里回滚 |

## 3. 第一次登录

1. 浏览器打开 `http://localhost:12345`；
2. 右上角点「登录」（或直接访问 `/login`）；
3. 输入 `.env` 里的 `SUPER_ADMIN_USER` / `SUPER_ADMIN_PASSWORD`；
4. 登录后侧边栏会出现「设置」与「团队」：前者配置成员、小组、权限、公网等，后者是团队待办。

不登录也可以直接点「以访客身份浏览」——**访客模式默认可以浏览和下载**，具体能做什么由超管在
「设置 → 权限 → 访客权限」中决定。

### 想让别人访问

| 场景 | 做法 |
|:-------------- |:--------------------------------------- |
| **同一局域网** | 别人直接访问 `http://<你的局域网IP>:12345`，无需登录（访客）或使用你创建的成员账号 |
| **跨网络 / 外网** | 用内置的 SSH 反向隧道，详见 [公网访问与隧道](公网访问与隧道.md) |
| **只给自己用** | 把 `HOST` 改成 `127.0.0.1`，然后访问 `http://127.0.0.1:12345` |

## 4. 开发模式

需要前后端分开跑的时候：

```bash
pnpm dev:server   # 终端 1：后端，node --watch 热重载，端口由 .env 的 PORT 决定
pnpm dev:web      # 终端 2：前端 Vite 开发服务器，端口 5173
```

**开发时请访问 http://localhost:5173**，不要访问 12345：Vite 会把浏览器发来的 `/api` 请求
转发到后端（见 `web/vite.config.ts` 的 `server.proxy`）。
**代理目标端口是自动读根目录 `.env` 的 `PORT` 得到的**（`backendPort()`），所以不需要手工同步；
改了 `.env` 的 `PORT` 后重新启动 `pnpm dev:web` 即可。

生产模式下不需要 Vite，后端直接托管构建产物。

## 5. 正式部署到服务器（pm2 + Caddy HTTPS）

前面三步跑起来的是**开发/试用**形态：终端一关服务就停，而且是明文 HTTP。
如果要长期挂在一台服务器上给团队用，推荐这套组合：

```
浏览器 ──HTTPS──> Caddy（80/443，自动证书） ──HTTP──> 127.0.0.1:12345 ZeroShadow（pm2 守护）
```

- **pm2** 负责进程守护：崩溃自动拉起、开机自启、日志收集、平滑重启；
- **Caddy** 负责 HTTPS 与反向代理：自动申请/续期 Let's Encrypt 证书，不需要自己折腾 certbot；
- ZeroShadow 只监听回环地址，**不要**把 12345 直接暴露到公网。

### 5.1 准备目录与运行用户

不要用 root 跑服务。以一个专用用户为例（Debian/Ubuntu）：

```bash
sudo useradd -r -m -d /opt/zeroshadow -s /usr/sbin/nologin zeroshadow
sudo mkdir -p /opt/zeroshadow
sudo chown -R zeroshadow:zeroshadow /opt/zeroshadow
```

把项目放到 `/opt/zeroshadow`（`git clone` 或解压发布包），然后**用该用户**安装依赖并构建：

```bash
sudo -u zeroshadow -H bash -lc 'cd /opt/zeroshadow && pnpm setup && pnpm build'
```

> **工作目录很重要**：pm2 必须以仓库根为 `cwd` 启动（`server/index.js` 用
> `process.cwd()` 推导 `.env` 与 `data/`）。在 `server/` 里启动会凭空生成
> `server/.env` 与 `server/data/`，看起来像"数据丢了"。

### 5.2 调整 `.env`

```ini
# 只监听本机，公网入口交给 Caddy
HOST=127.0.0.1
PORT=12345

# Caddy 在同一台机器上：只信任来自回环地址的代理头
# 这样日志/限速拿到的是真实客户端 IP，而不是 127.0.0.1
TRUST_PROXY=loopback
```

> 只有在「Caddy 与 ZeroShadow 同机」时才用 `loopback`。如果 Caddy 在 Docker / 另一台机器上，
> 改成它的网段（如 `TRUST_PROXY=172.18.0.0/16`），**不要**图省事写 `TRUST_PROXY=1` 或 `true`：
> 那会信任任何来源的 `X-Forwarded-For`，攻击者可以伪造 IP 绕过登录与分享密码的限速。

### 5.3 用 pm2 守护

在仓库根新建 `ecosystem.config.cjs`：

```js
module.exports = {
  apps: [
    {
      name: "zeroshadow",
      script: "server/index.js",
      cwd: "/opt/zeroshadow",       // 必须是仓库根（.env 与 data/ 都相对它）
      exec_mode: "fork",
      instances: 1,                  // 必须是 1：任务进度、限速、DAV 锁都在内存里
      autorestart: true,
      max_memory_restart: "512M",
      env: { NODE_ENV: "production" },
      out_file: "./data/logs/pm2-out.log",
      error_file: "./data/logs/pm2-error.log",
      time: true,
    },
  ],
}
```

安装并启动：

```bash
sudo npm i -g pm2
sudo -u zeroshadow -H bash -lc 'cd /opt/zeroshadow && pm2 start ecosystem.config.cjs'
sudo -u zeroshadow -H bash -lc 'pm2 save'

# 开机自启：按 pm2 输出的提示执行那条 sudo 命令
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u zeroshadow --hp /opt/zeroshadow
```

常用命令（都用运行用户执行，或 `sudo -u zeroshadow pm2 ...`）：

```bash
pm2 status                 # 进程状态与重启次数
pm2 logs zeroshadow        # 实时日志（业务日志另在 data/logs/zs-*.log）
pm2 restart zeroshadow     # 改完 .env / 更新代码后重启
pm2 reload zeroshadow      # 平滑重启（fork 模式下等价于 restart）
pm2 monit                  # CPU / 内存
```

健康检查：

```bash
curl -s http://127.0.0.1:12345/ping    # 应返回 pong
```

> **不要用 cluster 模式**（`instances > 1` / `exec_mode: "cluster"`）：上传/压缩任务进度、
> 登录失败计数、接口限速、WebDAV 锁都保存在**单进程内存**里，多进程会各算各的，
> 表现为"进度查不到 / 限速失效 / 锁不住"。

### 5.4 用 Caddy 配 HTTPS

安装 Caddy（Debian/Ubuntu，官方源）：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install caddy
```

编辑 `/etc/caddy/Caddyfile`：

```caddyfile
pan.example.com {
    encode zstd gzip

    # ZeroShadow 只监听回环地址
    reverse_proxy 127.0.0.1:12345 {
        header_up X-Real-IP {remote_host}
        # Caddy 会自动补 X-Forwarded-For / X-Forwarded-Proto；
        # 不要在这里手工覆盖成固定值，否则 TRUST_PROXY 拿到的又是假 IP
    }

    header {
        # 确认全站强制 HTTPS 后再开 HSTS；开了就不要轻易退回 HTTP
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        -Server
    }

    # 上传大文件由 ZeroShadow 自己按角色限制（默认超管 2048MB / 成员 512MB），
    # Caddy 默认不限制请求体；如需在边缘再兜一层，可取消下面注释：
    # request_body {
    #     max_size 4GB
    # }
}
```

检查并加载：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo systemctl status caddy
```

前置条件：

1. 域名的 **A/AAAA 记录**已指向这台服务器；
2. 公网放行 **80/443**（Caddy 用 80 做 ACME 校验、用 443 提供服务）；
3. `pan.example.com` 能从公网解析到本机，Caddy 才会自动签发证书。

### 5.5 上线前检查

- [ ] `HOST=127.0.0.1`，防火墙/安全组**没有**放行 12345；
- [ ] `TRUST_PROXY=loopback`（或 Caddy 实际所在网段），日志里能看到真实客户端 IP；
- [ ] 浏览器地址栏是 `https://`，登录后刷新不会掉线（Cookie 的 `Secure` 依赖
      `X-Forwarded-Proto`，Caddy 已自动带上）；
- [ ] 分享链接是 `https://pan.example.com/s/...`；
- [ ] pm2 `startup` + `save` 都执行过，重启服务器后 `pm2 status` 能看到进程；
- [ ] `data/` 已纳入备份（配置/成员/小组/待办/分享都在这里，见
      [配置参考 · 备份与迁移](配置参考.md#六备份与迁移)）；
- [ ] 运行用户对 `data/` 有读写权限，且**不是 root**。

### 5.6 更新与回滚

```bash
sudo -u zeroshadow -H bash -lc 'cd /opt/zeroshadow && git pull'
sudo -u zeroshadow -H bash -lc 'cd /opt/zeroshadow && pnpm setup && pnpm build'
sudo -u zeroshadow -H bash -lc 'cd /opt/zeroshadow && pm2 restart zeroshadow'
```

`data/` 不在 git 里，`git pull` 不会动它；升级前建议在「设置 → 数据与保留」点一次手动备份，
或直接 `tar` 一份 `data/`。

> **Windows 服务器**：pm2 可以用 `pm2-installer` 注册成 Windows 服务，Caddy 用
> `caddy run --config Caddyfile`（或 `caddy service install`）常驻。其余步骤一致：
> `HOST=127.0.0.1`、`TRUST_PROXY=loopback`、只让 Caddy 暴露 443。

### 5.7 常见问题

| 现象 | 原因 / 处理 |
|:--- |:--- |
| 浏览器 **502 Bad Gateway** | ZeroShadow 没在跑（`pm2 status` / `pm2 logs`），或 `HOST`/`PORT` 与 Caddy 里写的不一致 |
| 登录成功但一刷新就退出 | 反向代理没带 `X-Forwarded-Proto`，或 `TRUST_PROXY` 没开 → Cookie 的 `Secure` 判定不一致 |
| 日志里全是 `127.0.0.1` | `TRUST_PROXY` 没设置或设错；同机 Caddy 用 `loopback` |
| 上传大文件被 Caddy 拒绝 | 在 Caddyfile 里放开 `request_body max_size`（默认不限制，多半是被别的反代/网关挡了） |
| 分享链接打不开、提示 CSRF 校验失败 | 反代改写了 `Host`/`Origin`；Caddy 默认透传，别手工覆盖 `Host` 头 |
| WebDAV 客户端 405/404 | 需要在 `.env` 里 `WEBDAV=1` 并重启；Caddy 正常转发 `PROPFIND` 等方法 |

## 6. 使用发布包（ZeroShadow.exe）

在 Windows 上双击 `Auto-building.bat` 会生成：

```
ZeroShadow-Release/
├── ZeroShadow.exe        # 后端可执行文件（前端已内置资源引用）
├── web/dist/             # 前端构建产物
├── data/                 # 空的数据目录
└── .env.example          # 配置模板
ZeroShadow-Release.zip    # 上述目录的压缩包（已过密钥门禁）
```

使用方式：

1. 把 `ZeroShadow-Release` 整个目录拷到目标机器（路径随意）；
2. 双击 `ZeroShadow.exe`；
3. 首次运行会在 **exe 同目录**生成 `.env` 与 `data/`，控制台打印访问地址与随机超管密码；
4. 需要固定配置时，把 `.env.example` 复制成 `.env` 再编辑。

> 打包后的程序把"运行根目录"认定为 **exe 所在目录**（源码运行则是当前工作目录），
> 所以 `data/`、`.env`、`web/dist` 都相对 exe 定位。
>
> 关闭程序：在控制台按 `Ctrl + C`。服务会先停掉隧道再退出，3 秒内没退干净就强制结束。

## 7. 接下来做什么

1. 进「设置 → 权限」按需调整成员能做什么，特别是**上传大小限制**（默认成员 512MB、超管 2048MB）；
2. 进「设置 → 成员」批量添加团队成员账号；
3. 需要把服务器上的素材目录挂进网盘时，配置 [只读映射目录](配置参考.md#15-外部只读映射目录-files_soft_dir)；
4. 需要对访客隐藏某些文件夹时，在文件列表里右键文件夹 →「对访客隐藏」；
5. 团队要分头使用、各自只看到自己的目录时，进「设置 → 小组」建组并在「可见范围」里划分；
   日常分派任务用侧边栏的「团队」（[团队待办](使用手册.md#14-团队待办)）；
6. 需要外网访问时，看 [公网访问与隧道](公网访问与隧道.md)。
